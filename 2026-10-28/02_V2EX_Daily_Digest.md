## 5. Railse：把多个 AI 编程 agent 的审批推到手机上一键放行（开源）

分享创造节点下没有回复，但帖子本身含金量很高，作者确实在解决真实的痛点。背景是同时开 Claude Code、Codex、Gemini CLI 写代码，每个 agent 要跑命令、改文件都会停下来等人按“允许”，三个终端来回切换，出去吃顿饭回来，全都卡在第一条 git push 上；而开 yolo 全放行又不敢。

做法是把三家 CLI 的权限钩子接到本机的一个守护进程上，规则只需写一套。每条请求先判定风险档：只读操作和修改项目文件直接放行；curl、npm install 这类联网操作，git push、deploy 这类对外操作，rm -rf、git reset --hard 这类不可逆操作，都要询问；规则定不了的推送到手机，点开即可批准或拒绝，还可以勾选“记住”存成规则。对外和不可逆操作永远不能被“记住”放行。守护进程挂掉后不会阻塞 agent，超时 30 秒会自动回落到 CLI 原生的审批框。token、密码在本机先被替换，再上报。项目以 Apache 2.0 协议开源，一个 Go 二进制，自带 Fly.io 配置。已知限制也写得很诚实。

https://www.v2ex.com/t/1252390

## 8. www 用户运行 vs Docker 里 root 运行，哪个更安全？

Linux 节点下共有 9 条回复。楼主问的是：同一个程序，一种方式是宿主机上的 www 用户运行（/sbin/nologin），另一种是 docker 容器里以 root 运行（dockerd 也是 root），哪个更安全？他还提到“问了一圈 AI，只有 Kimi 说容器更安全，大多数说 www 更安全”。

- **3 楼 javalaw2010（❤0）**：给出了最清晰的判断依据：「容器内如果用非 root 运行，那么我认为容器安全；用 root 运行的话，那就是 www 安全，毕竟容器逃逸比起提权来看的话，还是容器逃逸更容易一点。」
- **2 楼 Vaspike（❤0）**：最近半年虚拟化领域的新漏洞挺多，倾向 www。
- **4 至 6 楼**给出的实际解法是：docker 也可以用普通用户启动；容器内使用 65532 uid，参考 Docker 官方 hardened image（DHI）；或者直接用 podman rootless。
- **8 楼 COW（❤0）**：吐槽楼主：「你想喷 kimi 可以直说，这不是很明显吗。」

这道题的正确答案并非二选一，只有“容器 + 非 root + 只读文件系统”的组合才有意义。
