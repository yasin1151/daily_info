### 1. 重度用 AI 写代码两个月：效率涨了，人却更废也更焦虑
- **来源**：V2EX
- **一句话人话版**：一位独立开发者连续两个月重度依赖 AI 编程助手，产出确实变多，但作息崩了，对代码的掌控感也在流失。
- **新闻/帖子本身**：楼主独立开发两年多，两个月前开始把日常开发交给 Claude Code 与 Codex。他自己总结了三个症状：一是“透支式提效”，感觉把未来一年的活提前干完了，但活的总量反而指数级增加；二是戒断感，手搓了两年的项目，现在想人工改点代码会手足无措、发怵，觉得脑子被“外包”了；三是看不到头，干完一批还有下一批。他自嘲：本来是想偷懒，结果成了给 AI 打工的监工。帖子里唯一没有争议的一点是产出量确实上去了，有争议的是这些产出到底算不算自己的积累，以及这种节奏能撑多久。
- **社区原话摘录**：
  - V2EX 5 楼（1 赞）：“回报不要想了，写代码这事会慢慢贬值，幸好现阶段可以减负担。” —— 接受技能贬值、先换眼前减负的务实派。
  - V2EX 6 楼（1 赞）：“以前大部分人做的是重复性工作，AI 把这些削掉之后，人的大脑被迫去开辟新边疆。” —— 把焦虑解释成进步代价的乐观派，认为“个体被生产力不足挡住”才是老问题。
  - V2EX 1 楼（0 赞）：“为什么下班还要干活？” —— 最直白的一刀：问题可能不在 AI，而在工时文化本身。
- **参谋部短评**：这条值得盯，因为它把“提效”最不被讨论的成本写成了具体症状：工时反噬和掌控感流失。争议点在最后一楼——到底是工具让人过劳，还是本来就在过劳。
- **链接**：https://www.v2ex.com/t/1257015

### 2. Lovable 生成的 15.9 万个应用里，两万多个把数据库直接发给浏览器
- **来源**：HackerNews（561 分 / 228 条评论）
- **一句话人话版**：德国研究者扫了 15.9 万个 Lovable 生成的应用，发现大量站点不用登录就能拿到数据库记录，部分含邮箱、护照照片和私信。
- **新闻/帖子本身**：调查用 Common Crawl 抓取 2025 年 12 月至 2026 年 9 月间的 159,041 个 Lovable 项目，其中 34,545 个用了 Supabase，24,664 个在未登录状态下就把数据库记录直接发给浏览器。研究者再做一次只读请求，7,403 个站点（30%）能取到含邮箱的表，还出现了护照照片和 20 多万条私信。Lovable 的条款把安全责任推给用户，营销口径却是“无需任何技术知识”。
- **社区原话摘录**：
  - HN 评论者（高赞）：“Nothing to see here and working as intended.” 他接着预判：一旦越狱模型以 2400 TPS 扫这类 Web 应用，“你在安全上根本还没准备好，形式化验证也救不了你”。 —— 反讽式定调，把这当成必然结果而不是意外事故。
  - HN 评论者：另一家平台前几天刚被同类手法打穿，攻击者疑似用越狱模型加窃取的密钥，烧掉约 74 万美元 AI 费用。“如果它都扛不住，随便一个 Lovable 应用就是软目标。” —— 把单点事故升级成系统性风险的判断。
  - HN 评论者：“唯一能治这个的是真正硬的赔偿责任。” 同时提醒：AI 出现之前，WTF 级漏洞一样多，别只怪 AI。 —— 拒绝“AI 天生不安全”的叙事，要求把责任落到能赔钱的一方。
- **参谋部短评**：今天最该转给非技术同事的一条。vibe coding 把“能跑”和“安全”彻底解耦了，争议不在漏洞本身，而在责任该由谁承担。
- **链接**：https://www.crissyfield.de/research/lovable-en/

### 3. ChatGPT Wallet 上线：agent 可以在你按完指纹后替你刷卡
- **来源**：橘鸦AI早报 + V2EX 讨论
- **一句话人话版**：OpenAI 与三大卡组织合作推出 ChatGPT Wallet，agent 能在你逐笔确认后直接下单付款，目前只对美国 Pro 用户开放。
- **新闻/帖子本身**：11 月 13 日发布，与 Amex、Mastercard、Visa 合作。卡只绑一次，每笔交易前展示商品、总价、用哪张卡，再刷脸或指纹；支付网络发给商家和 agent 限定用途的 token，双方都拿不到真实卡号，积分和争议保护保留。官方提到未来可能支持额度、品类、时间段预授权，初期不收交易佣金。走的是“不取代卡组织、只做授权层”的路子，争议因此集中在需求侧而不是技术侧。
- **社区原话摘录**：
  - V2EX 3 楼：“这是上层人士的自我感动。” 他认为大部分人买东西还要比价、凑满减，不会让 AI 随意掌握钱包，并反问国内同类助手推了一年留存有多少。 —— 最尖锐的需求质疑：支付卡的不是能力，是信任和习惯。
  - V2EX 1 楼：“agent 能抢购不错，但商家也会用 agent 封杀用户的 agent。” —— 预判 agent 对 agent 的军备竞赛，抢票、限量发售这类场景会先崩。
  - V2EX 8 楼（1 赞）：“让他订阅 claude 能干吗。” —— 一句话把话题拉回开发者的真实痛点：能替我付订阅费，比替我买咖啡实际得多。
- **参谋部短评**：agent 商业闭环的关键一块补上了，但社区第一反应不是兴奋而是“我用不上”。真正该看的是预授权额度与争议责任怎么定，那才是它能否走出美国的门槛。
- **链接**：https://openai.com/index/introducing-chatgpt-wallet/ ｜ https://www.v2ex.com/t/1257048

### 4. Code Mode 实测一周：读得多的任务真省，写的任务一行坏 JS 全批挂掉
- **来源**：r/ClaudeCode（赞数为归档快照，可能滞后）
- **一句话人话版**：Claude Code 新版上线实验性 Code Mode，让模型写一段 JavaScript 批量调工具，官方说省 token，一线用户跑了一周给出适用边界。
- **新闻/帖子本身**：11 月 12 日发布的 2.1.323 引入 Code Mode：模型不再逐个调用工具，而是写一段 JS 批量调用，由组织管理员开关。同一版还做了三件事——plugin.json 支持声明兼容的版本范围，超出范围就不安装、不更新；插件校验开始对 TypeScript hooks 做类型检查；未识别的模型 ID 默认给 1M 上下文，可用环境变量回退到 200K。评论的分歧不在功能，而在它把工具调用从“看得见的一次一步”变成了一个黑盒脚本。
- **社区原话摘录**：
  - Reddit 评论者（49 赞）：“we ran code mode on the same repo for a week and the win was real on read heavy tasks. write tasks were worse because one bad js line killed the whole batch of tool calls” —— 目前最可信的一手对照，直接给出适用边界：读密集任务先上，写任务要谨慎。
  - 同一评论者（13 赞跟进）：“the js wrapper costs a few hundred tokens, the savings come from not resending tool schemas and results every turn.” —— 把成本账算清楚：省的不是包装本身，而是每轮重复的 schema 与工具输出，所以长任务收益才明显。
  - Reddit 评论者（9 赞）：“I assume this then totally defeats hooks based guard rails” —— 提出官方文档没回答的治理问题：批量调用绕过了逐次的 hook 拦截，建议只对只读工具开启。
- **参谋部短评**：这是“省 token”和“可控性”第一次正面冲突。读操作开、写操作留普通调用是目前社区给出的折中，值得盯着有没有人做出按工具粒度的开关。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1xvw576/

### 5. 让 Agent 自己提工单，同事直接看不懂：AI slop 是这么生产出来的
- **来源**：V2EX
- **一句话人话版**：一位开发者让模型把测试发现的 bug 自动写成工单派给模块负责人，对方的反馈只有三个字：看不懂。
- **新闻/帖子本身**：楼主用 Opus 5.5 跑全项目测试，在极端场景发现 bug，就让 agent 自己提工单给模块 owner。工单极其详细——把所有做过的实验都塞进去，还自创了一堆只有跟 agent 长期对话才懂的简写，结果没有重点。对比很有意思：另一位同事把整份工单直接喂给自己的 agent 去复现、修 bug、再回一份全 AI 工单，流程反而通了。楼主由此总结，AI slop 不是因为模型不会写，而是它不知道“给谁写、什么该删”。值得注意的是，同一份工单对另一个 agent 几乎没有障碍，卡点只出现在最后一步交回给人。
- **社区原话摘录**：
  - V2EX 1 楼：“其实就是 AI 缺乏判断力，不知道应该把什么东西写到工单里。” —— 归因到判断力而不是语言能力，说清了 slop 的技术本质。
  - V2EX 2 楼：“没看懂，估计你所说的工单就和你发的这个帖子一样。” —— 现场演示了一次 slop，全场杀伤力最强的一句。
  - V2EX 5 楼：“模型越强文字越难读，没重点＋难读＋黑话三样混一起；你需要的是 anti-slop 写作 skill。” —— 给了可落地的解法：把“删什么”也写成规则。
- **参谋部短评**：这条对做 agent 工作流的人是免费的需求清单。多 agent 协作里最缺的不是生成能力，是“写给谁看”的收件人意识。争议在于它是可修的提示工程问题，还是判断力的硬边界。
- **链接**：https://www.v2ex.com/t/1257136

## 今日舆情温度

- **最热争议**：技术债要不要留给未来的模型。r/ClaudeCode 一个帖子提出干脆继续造黑盒应用、等更强的模型出现再统一收债，35 赞的回复是“It is quickly becoming unimportant whether or not code is slop”——默认可读性只是为人类服务。23 赞的反驳更硬：“AI performs much better in good codebases than bad codebases”，代码越乱，模型越容易犯错、也越容易把库改得更乱。还有一位维护 20 到 55 年老系统的工程师补刀：能力边界确实在快速移动，但“已经能帮上忙”和“可以不管代码质量”是两件事。这场争论没有结论，但已经把“AI 时代还要不要讲工程规范”从口号变成了可观察的模型行为问题——评判标准从人读不读得懂，换成了模型在库里的出错率。
- **最现实的吐槽**：额度与成本。一位 20 美元档用户抱怨“我没用大模型”却几分钟吃掉 83% 的五小时额度，最高赞的回答直接指出他其实在跑又贵又旧的 Opus 4.8；同档位另一位用户说自己平均能连续干两小时才撞上限，差异来自主会话 fan-out 出十几个子会话、每个都在独立计费。真正有信息量的是一条成本口径：新版本输入 4 美元、输出 20 美元每百万 token，比旧版降了约两成，但更该算单任务成本。加上 V2EX 那边“Codex 太慢，转国产模型更划算”的实测帖，本周的主情绪很统一：不是模型不够强，是性价比和额度能不能撑住一天的工作。这类吐槽的价值在于它常常不是模型问题，而是用量结构问题——档位、并行会话数、上下文膨胀，三项一排查就有答案。
- **最值得继续观察**：Code Mode 这类批量调用与 hook 护栏的关系。省 token 的机制站得住，但它绕开了逐次拦截，等于把安全边界从“每次调用”退到“整批脚本”。接下来要看三件事：有没有按工具粒度的开关、企业侧怎么给写操作设白名单、以及出了事故之后责任记在脚本还是模型上。另一条线是生成平台的安全责任，15.9 万个应用里三成能读到用户表，这类平台的条款和托管方默认配置大概率会在几周内被重新审视，尤其是“无需任何技术知识”这种营销口径与安全责任条款互相打架的时候。
