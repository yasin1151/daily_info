### 1. 模型开始直接改写自己的权重：改掉 0.016% 的参数，数学成绩从 7.9% 跳到 48.1%

- **来源**：HackerNews（1600 以上赞）
- **一句话人话版**：MIT 团队发现前沿模型能直接读、写神经网络的权重，不用梯度下降，改极小一部分就能修掉模型的推理死循环。
- **新闻/帖子本身**：研究者的做法是让模型直接看一串权重数字。GPT-6 Astra 只看 17,253 个数，就认出网络在打哪个游戏；在没有环境反馈的情况下，它从零写出一个能打赢 PPO 一亿步训练的小网络；另一组实验里，它改掉 Qwen3.5-0.8B 约 0.016% 的权重，修掉了官方 model card 自己警告过的推理死循环，MATH-500 从 7.9% 升到 48.1%，IFEval 顺带涨了三倍。作者把这条路线叫 Weight-Space Programming。
- **社区原话摘录**：
  - HackerNews 评论者（高赞）：“I'll chalk up never even having thought of this being an option as yet another instance my human hubris” —— 他的意思是，自己连“居然还能这么干”都没想到，于是把这份震惊归到人类自己的认知盲区。
  - HackerNews 评论者：“Slightly terrifying.” —— 两个词的短评，代表一批人对“模型能直接改自己的权重”的本能不适。
  - HackerNews 评论者（半原话）：把改权重类比成给模型做 CRISPR 基因编辑 —— 这个类比隐含的意思很明确：能精准修好一处，也就能在别处留下看不见的脱靶。
- **参谋部短评**：值得盯的不是这次改成 0.016%，而是优化器这一层第一次被推理模型正面碰了一下，顺带把“对齐靠后续微调”这个前提也撬松了。评论里已经有人追问：既然能改，安全约束是不是也能被一次请求绕过去。
- **链接**：https://rikiyat.github.io/blog/weight-space-programming/ ｜ https://news.ycombinator.com/item?id=50341174

### 2. 只污染 0.1% 的预训练语料，就能给 Agent 埋一个远程执行后门

- **来源**：HackerNews / arXiv 论文
- **一句话人话版**：一篇论文从零预训练小模型，再按完全正常的后训练流程把它做成命令行 Agent，只污染千分之一语料，4B 模型的攻击成功率就有约 92%。
- **新闻/帖子本身**：作者（含 Nicholas Carlini）没有往微调数据里塞坏样本，而是从预训练阶段就下毒：从零训练 Qwen3 0.6B/1.7B/4B，之后走正常流程 post-train 成 CLI Agent。污染率降到 0.0005% 仍然有效；模型在干净输入下行为与正常版本无异，只在特定触发条件下才执行攻击者预先设定的动作。换句话说，后门不会体现在平时表现里，测试和评测都看不出来。对任何下载开源权重来接进自己 Agent 的团队来说，这意味着“模型能跑、分数正常”不再能作为可信依据，真正要看的是语料来源和训练链路。
- **社区原话摘录**：
  - HackerNews 评论者：“context bombs” —— 有人给这类后门起了这个名字，担心以后“免费送模型”就是送货上门。
  - HackerNews 评论者（半原话）：真正在意安全的人早就把 Agent 沙箱化了 —— 他认为问题不在模型而在部署方式，沙箱是第一道防线，这条被不少人认同。
  - HackerNews 评论者（半原话）：闭源模型你连审计的机会都没有 —— 反方紧接着回应：开源至少还能查，闭源连查的入口都不给。
- **参谋部短评**：这条和上一条放在一起看才有意思。权重可以被外部直接改写，语料又能在预训练阶段埋雷，模型供应链的信任模型基本要重写，而现在的防御手段只有沙箱这一层。
- **链接**：https://arxiv.org/abs/2610.37741 ｜ https://news.ycombinator.com/item?id=50341334

### 3. Ultra 用户 10 小时就烧掉半周额度，评论区第一反应是“你把 /usage 贴出来”

- **来源**：Reddit r/ClaudeCode
- **一句话人话版**：一位 Ultra（原 Max 20x）用户说上周两天才用掉 50% 周额度，这周只用了 10 小时就见底，而他自述只是在 Node.js 应用里加功能、改 PDF。
- **新闻/帖子本身**：他真正的问题在机制层：5 小时分段限制取消之后，只要不主动停，一周额度可以在一天内烧完，于是他来问怎么配置才不会被自己耗死。评论区一半是同类体验，一半是要求他贴前后用量对比的怀疑派。给出的建议集中在“做减法”：关掉最高强度推理、别让它起五十个子代理、上下文过半就交接给新的编排会话。也有回复提醒，5 小时限制还在的时候，每一段结束都会被强制停下来看一眼用量，现在这个节拍没了，等于把预算控制完全交给使用者自觉。
- **社区原话摘录**：
  - Reddit 评论者（21 赞）：“Don't use max reasoning, Don't let it spin up 50 sub agent, Don't let it run context above 50%” —— 把额度问题还原成三个可调旋钮，是“不是额度变小，是用法不对”这一派的代表。
  - Reddit 评论者（8 赞）：他同样按老习惯使用，三天就把额度耗尽，“like 3-4x less work done for the same usage (according to Claude code /usage)” —— 同为老用户，他的对照体验指向单位额度的产出下降。
  - Reddit 评论者（4 赞）：他不认这个结论，要求拿出前后 token 用量证据，并说自己五个 Ultra 账号“it's the same as always” —— 怀疑派代表，提醒这类抱怨常常缺少测量基线。
- **参谋部短评**：额度争论里最值得记的是那个机制变化。取消 5 小时分段之后，唯一的速度刹车变成了用户自己的上下文与子代理管理，这类抱怨接下来只会更多。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1xm1378/

### 4. Agent 写的 pandas 代码“完全看不懂”，这代码到底审不审

- **来源**：V2EX
- **一句话人话版**：楼主贴出 Claude Code 生成的 pandas 聚合代码，用掩码列一次替掉循环里的五次切片，承认自己完全看不懂，但让 agent 讲完又觉得确实更简洁，于是发问该不该逐行审。
- **新闻/帖子本身**：这是当下 AI 编码最现实的管理问题：既然能生成，人还要不要逐行读。评论区没有停在站队上，高赞答案几乎都指向“不审，靠测试兜底”。唯一被反复提出的反对理由不是可读性，而是测试覆盖不到的静默语义错误——代码跑得好好的，某个指标算出来是错的。也有人从语言性质切入，认为自然语言的模糊性正是 agent 产出难以逐行校验的根源。折中方案同样有人提：新生成的模块逐行看一遍，存量代码交给测试和监控兜底，把审查预算花在改动发生的地方。
- **社区原话摘录**：
  - V2EX 3 楼（21 赞）：“能过鸭子测试它就是鸭子” —— 全帖最高赞，把判据从“读不读得懂”换成“行为对不对”，代表主流实用派。
  - V2EX 5 楼：“关键是 AI 有时候会偷偷埋坑，整体跑得好好的，突然某个指标算的是错的” —— 这条是唯一被反复提出的真风险：不是看不懂，而是错了看不出来。
  - V2EX 13 楼（5 赞）：“编程语言有严格的界限，自然语言没有界限，语义容易产生误解” —— 从语言性质解释为什么 agent 的意图和最终的产出之间总有缝隙。
- **参谋部短评**：真正的分歧不在“审不审”，而在“你能不能让它失败”。没有会红的测试，鸭子测试就只是自我安慰；有覆盖到业务指标的断言，不审也站得住。
- **链接**：https://www.v2ex.com/t/1253699

### 5. Claude 账号弹 KYC：通过之后是更稳，还是离封号更近

- **来源**：V2EX
- **一句话人话版**：一位 2023 年注册、很早就上 Max 的用户上周五被要求做 KYC，他用国外朋友的真实身份验证通过，但社区流传“KYC 过了，过一阵照样封”。
- **新闻/帖子本身**：他的护照已经过期，最后靠朋友完成验证，目前账号正常。帖子里还顺带交代了备选方案：Codex 额度涨了一倍，另一家国产模型的 harness 也能用。回复区给出的结果互相矛盾：同样用本人护照验证，有人说秒封，有人说没事，有人两个号封了一个。这说明 KYC 只是风控链条上的一环，设备指纹、IP 稳定性和使用画像显然也在里面。值得注意的是，他列出的替代方案里没有“再开一个号”，而是直接换工具栈，说明多账号策略的边际收益在他看来已经不高。
- **社区原话摘录**：
  - V2EX 1 楼：“同周五 kyc，用自己护照秒封。” —— 最短也最扎心的一条，直接否掉“通过 KYC 即安全”的假设。
  - V2EX 2 楼：“我是 pro 升级 max5x 弹 kyc，用自己护照 kyc，没有封。” —— 同样的路径得到相反结果，说明单点经验在这里没有预测力。
  - V2EX 3 楼：“我有 2 个自己护照 kyc 的，封了一个（用了几天，感觉是自己操作不当），另外一个还在。” —— 把封号归因到操作行为而非身份验证，是唯一给出因果猜测的一条。
- **参谋部短评**：对把工作流压在一家模型上的开发者，这帖的价值不在于“会不会封”，而在于它现场演示了同类操作会得到相反结果。备选通道该常备，不该等封了再找。
- **链接**：https://www.v2ex.com/t/1253660

## 今日舆情温度

- **最热争议**：今天真正吵起来的是“人的位置在哪里”。一边是模型能直接读写权重、能在预训练阶段被埋后门，讨论里出现“slightly terrifying”和“给模型做基因编辑”这类说法；另一边是 V2EX 与 Reddit 同时在上演“AI 写的代码要不要审”，最高赞干脆绕开审查，直接拿行为测试当判据。两条线表面无关，指向的却是同一件事：人类正在从“执行者”退到“定义什么叫正确”。这个转向还没有共识，评论区的分裂程度比新闻本身更值得记，因为分歧不在技术可行性，而在“谁来承担判错的后果”。
- **最现实的吐槽**：钱和时间。Ultra 用户 10 小时烧掉半周额度，老用户说同样的用量只干出四分之一到三分之一的活；国内这边有人反映速度从 40 多 token/s 掉到 24、动不动 502，回复却转去质疑聚合工具的统计方式，说它把冷启动和失败请求都排除在外、数字偏乐观。更关键的是官方说法开始松动：一边承认某项 Agent 服务的成本相对收入“高得不可持续”（[原帖](https://x.com/elonmusk/status/2116992258520064397)），另一边直接提醒享受补贴订阅的人“准备好被收回”（[原帖](https://x.com/amasad/status/2117010858845089805)）。补贴退坡从传闻变成多方同时确认的事。
- **最值得继续观察**：AI 资本故事出现第一道裂缝。Oracle 发股发债募 200 亿美元给数据中心续命，当天股价跌 8%，被评论指为“没有 OpenAI 离不开的专有 IP，卖的是大宗商品服务”，一旦 GPU 换代，按老卡设计融资的机房可能在回本前就被超越；同期有拆解指出，Anthropic 的单季环比增速从 141% 掉到 45%。如果这两条继续，会先传导到订阅额度与 API 价格，再传导到工具链的选型，比任何一次模型发布都更影响日常使用。
