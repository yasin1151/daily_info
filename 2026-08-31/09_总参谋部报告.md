### 1. OpenAI 终止与 Cursor 合作：11 月 12 日起切断模型接入
- **来源**：OpenAI 官方公告 / X
- **一句话人话版**：SpaceX 约 600 亿美元收购 Cursor 母公司后，OpenAI 宣布 11 月 12 日停止向 Cursor 供模型，AI 编程工具阵营加速两极分化。
- **新闻/帖子本身**：OpenAI 宣布因收购触发合同「控制权变更」条款，叠加马斯克旗下公司有违反服务条款（如蒸馏）前科，将于 11 月 12 日终止向 Cursor 提供模型接入，不再开放新模型。用户仍可自带 API Key 或通过 Codex 插件调用 OpenAI，终止的是平台级供应合作。Cursor CEO 回应 OpenAI 模型仅占平台流量约 5%，Anthropic 表示将加大对 Cursor 的 Claude 算力支持；马斯克则在 X 上公开攻击 Altman 和 Brockman。
- **社区原话摘录**：
  - Cursor CEO（官方回应）：“OpenAI 模型仅占平台流量约 5%” —— 淡化断供影响，暗示 Cursor 基本盘已转向 Claude，平台级断供不至于伤筋动骨。
  - OpenAI Codex 负责人（X 官方回复）：“确实继续支持” —— 回应网友用 CLIProxyAPI 在 Cursor 里继续走 Codex 订阅的提议，官方给付费用户留了一条灰色通道。
  - 社区用户质疑：这和此前被禁的 sub2api 没什么区别 —— 提醒这条“官方默许”通道随时可能反转，别把灰色方案当长期依赖。
- **参谋部短评**：本周结构性最大变化，直接影响所有用 Cursor 的开发者。值得盯三件事：Anthropic 借机抢量、灰色通道是否反转、11 月 12 日前的用户迁移动向。
- **链接**：https://openai.com/index/our-decision-on-cursor-following-its-acquisition-by-spacex/ ；https://x.com/thsottiaux/status/2093573575869698091

### 2. 8 亿 token 白烧：AI Agent 误删整个项目目录，数据全丢
- **来源**：V2EX
- **一句话人话版**：开发者用多 Agent 流水线跑 GLM 5.3 开发，AI 执行清理命令时误删上级整个目录，git 没推远程、无备份，数据全部丢失。
- **新闻/帖子本身**：开发者用 Codex + Trellis + Zcode 的多 Agent 流水线做 GLM 5.3 项目开发，AI 执行清理命令时因 macOS 大小写不敏感，误把上级整个 Work 目录删掉——git 未推远程、无 Time Machine 备份，数据全部丢失，8 亿 token 买了个教训。帖子 48 楼高讨论度，评论区迅速升级为「AI Agent 权限边界」大讨论：一周内 Claude 也爆出同类误删事故（删掉 700GB 根目录内容），这不是某一家模型的问题。
- **社区原话摘录**：
  - V2EX 9 楼：“我 2 月底开始就从不授予 rm 这些删除命令……生成式人工智能大数定律下都可能 rm 错路径” —— 实操派：直接不给删除权限，要删先移回收站、由人确认。
  - V2EX 10 楼：“干活还是得开 Full Access，不然效率太低……我的做法就是所有小的拆的开发任务都进入独立沙箱（docker 容器）” —— 折中派：保留全权保效率，用容器隔离兜底，删了也无所谓。
  - V2EX 25 楼：“Claude 昨天也刚有个新闻说删掉了 700GB 根目录……这种问题只能从机制上避免，但凡给了权限，总有失误的时候” —— 点破本质：别纠结哪家模型，机制防护才是唯一解。
- **参谋部短评**：两天内两起同类误删事故，都是“给足权限 + 无备份”的组合，Agent 权限边界成为本周最热开发议题。值得继续盯各家工具在权限默认值、沙箱隔离上的跟进动作。
- **链接**：https://www.v2ex.com/t/1238217

### 4. 默认配置把用户丢进 docker 组：Omarchy 任意进程可提权到 root
- **来源**：HackerNews
- **一句话人话版**：DHH 的 Linux 发行版 Omarchy 默认把用户加进 docker 组，浏览器、AI 编码代理都能挂载根文件系统改 /etc/shadow 提权。
- **新闻/帖子本身**：安全研究员发现 Omarchy 默认配置把用户加入 docker 组，桌面会话里几乎任何进程——浏览器、AI 编码代理、npm 脚本——都能通过 Docker socket 挂载整个根文件系统、以 root 身份读写 /etc/shadow，全程无需密码或 sudo。官方文档还误导性地写成了“让你以普通用户而非 root 运行 Docker”。已私下上报，4.0.1 修复。HN 357 分、360 评论，今日最热。
- **社区原话摘录**：
  - HN 评论者：“你肯定不喜欢 DHH，但他在 Rails 上一直很重视安全” —— 替 DHH 说话：别因人废言，Rails 时代他对安全一直认真。
  - HN 评论者：质疑 DHH 是否愿为安全牺牲开发者体验，并指出 docker-compose 生态迁移 podman 仍有摩擦 —— 点出现实阻力：默认安全的代价是迁移成本，不是改个配置就行。
- **参谋部短评**：默认安全配置翻车，且 AI 编码代理时代攻击面比浏览器更致命，撞上本周安全讨论热点。360 评论的高热度说明社区对“默认配置即信任边界”越来越敏感。
- **链接**：https://0xcc.io/posts/omarchy-root-creds/ ；https://news.ycombinator.com/item?id=49499854

- **最热争议**：AI Agent 该不该有删除权限。V2EX 8 亿 token 误删事故加上一周内 Claude 删掉 700GB 内容的事件，把“权限边界”吵成两派：一派从不授予 rm 等删除命令，一派保留 Full Access 但用容器沙箱隔离兜底；HN 上 Omarchy 默认 docker 组提权又把“默认安全配置”拉进战场。争议核心是效率与安全的取舍，以及各家工具默认权限值到底该给多少。
