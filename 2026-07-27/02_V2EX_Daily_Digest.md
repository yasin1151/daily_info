### 为什么现在 CLI agent 应用那么火，GUI 不好用吗？

摘要：这个帖子讨论为什么 Claude Code、Codex、opencode 这类 CLI Agent 最近更受关注。核心不只是“命令行复古”，而是 CLI 更适合作为 Agent runtime：便于远程运行、并行执行、自动化测试和容器化集成。值得关注的是，它反映了 AI 编程工具从“给人操作的界面”转向“给 Agent 调用的基础设施”。

评论精选：
- 37楼｜点赞数：页面未公开｜评论者认为 AI 厂商做 CLI 有两个现实原因：一是能在 SSH 等远程环境运行，二是更便于快速测试和迭代。GUI 测试成本高，早期用 AI 写 GUI 测试也容易不可维护。
- 39楼｜点赞数：页面未公开｜CLI 火是因为它更像给 Agent 用的接口，skill + CLI 可能是 Agent 时代的最佳打开方式；如果是给普通人用，最终仍可能回到 GUI。
- 6楼｜点赞数：页面未公开｜CLI 可以多进程并行运行，也能作为 Agent 运行基座。评论者提到自己用 opencode、Codex、Claude Code 的 CLI 做 agent runtime，再自行实现 GUI 和容器化能力。

### 自研 Markdown 编辑器内核支持实时协同，做 WebRTC P2P demo 有没有风险？

摘要：作者展示了一个自研 Markdown 编辑器内核，并尝试加入基于 WebRTC P2P 的实时协同能力。讨论点集中在协同编辑的产品形态、多人编辑冲突、现有开源方案和排版能力。值得关注的是，这类项目把“文档编辑器内核 + 协同协议 + 前端体验”这些工程问题放到了一起。

评论精选：
- 7楼｜点赞数：页面未公开｜评论者质疑为什么要分两栏协同，认为两个人在同一编辑区同时工作才更接近真实协作场景，并提到 codimd 这类现有开源项目已经有多人协同经验。
- 24楼｜点赞数：页面未公开｜有人用 Office 365 做类比：多人同时编辑文档、看到他人光标和修改内容、实时同步，说明用户对协同编辑体验已有较成熟预期。
- 4楼｜点赞数：页面未公开｜评论者关注更底层的编辑器能力，例如是否支持 Knuth-Plass 排版算法，以及流式输出时能否允许用户选择已经输出的文字。

### 5 年 PHPer，现在学 Java 还来得及吗？

摘要：发帖者是 5 年 PHP 开发，被裁后发现本地 PHP 岗位减少，正在考虑转 Java。讨论没有停留在语言鄙视链，而是围绕就业市场、生态门槛、AI 时代技能组合和转型路径展开。值得关注的是，它体现了传统 Web 开发者在岗位收缩和 AI 应用需求上升之间的选择压力。

评论精选：
- 6楼｜点赞数：页面未公开｜评论者建议先看过往业务和行业积累，如果是 Web 全栈，不一定只转 Java，也可以考虑 Python + TypeScript，转向 Agent 和 RAG 应用开发。
- 4楼｜点赞数：页面未公开｜有人认为 Java 本身不难，难点在生态知识；如果没有 Spring、微服务、中间件等生态经验，单学语言竞争力有限。
- 3楼｜点赞数：页面未公开｜另一种观点是继续深耕 PHP，往架构方向转；在 AI 辅助开发普及后，单纯换语言可能不是最高收益路径。
