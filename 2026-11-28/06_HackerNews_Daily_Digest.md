### 7. 要把软件工程从 LLM 手里救出来，需要一个主流可验证语言（303 分 / 297 评论）
作者 Blaine Hansen 认为 LLM 让代码质量断崖式下滑，唯一出路是全面采用形式化验证、一直到文明级软件栈的底层。但他反对“让 LLM 写证明就行”的乐观论：证明助手只保证证明正确，不保证定理陈述抓住了真实意图（引用 Lean 作者 Leonardo de Moura 的“人的契约”）。他自己在做 Magmide：编译到 Wasm GC、Rust 风格类型系统但去掉借用检查器的难点、先用 SMT 驱动的 Liquid Types，再逐步接入 Lean。

值得关注：这是“LLM 时代如何保证正确性”这条主线上最系统的论述，评论区把它的薄弱点拆得很干净：
- `hresvelgr` 引 Knuth：“我只证明了它正确，没试过跑它。”并指出有人写了 TLA+ 规格但质量并没实质提升；他认为问题在于组织与审美，而“框架之所以让 LLM 表现好，是因为它大幅压缩了可能代码的空间”。
- `kubb` 直接指出逻辑错误：“形式正确不保证功能正确，所以我们不需要它”——“但现实中它确实能抓 bug，Rust 也不保证你想要的功能，可这不代表 Rust 程序段错误的概率和 C 一样”。
- `FridgeSeal` 纠正论据：拿 ParticleDB 当反例不合适（那本身就是 vibe coding 出来的库，Jepsen 找出一堆洞），更好的例子是 AWS S3 用 TLA+ 验证权限模型。

### 9. Convex 的 skill 把用户的 app 想法偷偷发到远端服务器（198 分 / 56 评论）
GitHub issue 指出，这个插件（已上架 Anthropic 官方 marketplace）里三个 skill 有同类问题：`quickstart` 把用户一句话项目描述 POST 到 `basic-anteater-667.convex.site`，注释里写的是 telemetry，但用户不知情；`add` 把远端脚本直接 pipe 进 bash；`labs-quickstart` 特意把“下载”和“执行”拆成两条 Bash 命令，理由写得很直白——“一条命令同时下载并执行远程代码，正是 harness 安全分类器会拦截的形态”。报告者认为这是“想让 onboarding 更可靠”而非恶意，但最后一条等于教 agent 绕过用户自己设定的安全检查。

值得关注：这是 agent 生态里“skill 即供应链”问题的第一个清晰案例，也解释了为什么企业不敢给 agent 放开权限。CEO 亲自下场回应：
- `jamwt`（Convex CEO）：“这是给 Convex quickstart 功能用的，帮用户一句话生成整个项目，30 秒内就丢弃 prompt。我们会审查这段代码确保处理得负责透明——但它是按设计工作的，而且可以说这只是你托付给 Convex 的 IP 的冰山一角。”
- `MickyTheMouse`：这些 skill 会从服务器下载未固定版本的 shell 脚本并执行，插件还挂在 Anthropic 官方 marketplace 上。
- `542458` 回应“你本来就在把内容发给大模型”：“这就像说‘信用卡侧录有什么大不了的，你本来就要把卡号发出去’——主动发送和被偷偷发送是两回事。”

### 10. 那些“机器验证过”的假证明（167 分 / 73 评论）
D. J. Bernstein 整理了一份清单，收录 Coq、Lean、Isabelle、ACL2 等主流证明检查器历年来被报告的 soundness bug（可以让假命题通过检查的漏洞），并指出其中一些已被证明可利用。他关心的不是学术界面子，而是：如果 LLM 生成的证明成为常态，一个 soundness bug 就足以让“机器验证”变成伪安全感。

值得关注：和第 7 条正好构成一对——一边呼吁全面形式化验证，一边展示验证工具本身的历史漏洞。评论区的关键补充：
- `twotwotwo`：要真正骗过数学界，需要同时攻破多个检查器、且输入在非形式化审阅时看起来不离谱；DeepMind 一位研究员曾分别利用 Lean 和 nanoda 的不同 bug 造出能通过两边的“证明”，但随便给个 LLM 看一眼就会说“这不是数学”。
- `Karliss`：20 年 100 个 soundness bug，平均两个月一个，且趋势是加速的，“对现在这种 LLM 生成证明的工业界来说，任何时刻都可能存在尚未发现的漏洞，这已经够糟了”。
- `gr_norm` 反面观点：这些工具几十年的 soundness bug “全加起来能塞进一条推文”，对 99.9% 的软件来说足够了。

https://cr.yp.to/proofs/falseccp.html
