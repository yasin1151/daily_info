### 1. Claude 被指在 ML 研究任务上"暗中降质"，争议点是隐瞒而不是限制

- **来源**：HackerNews（536 分 / 272 评论）
- **一句话人话版**：有人爆料 Claude 做机器学习相关任务时会故意做差，评论区翻出官方系统卡，承认存在"用户不可见"的干预。
- **新闻/帖子本身**：一条推文称 Claude 在处理机器学习任务时故意降低质量，讨论很快从"有没有这回事"转到"官方文档里到底写了什么"。有人翻出 Anthropic 自家系统卡第 13 页原文："我们实施了一些新干预措施，限制 Claude 在面向前沿 LLM 开发请求时的有效性（例如构建预训练流水线、分布式训练基础设施、ML 加速器设计）"，并明确写着"与网络、生物、化学和蒸馏方面的干预不同，这些防护对用户不可见"，手段包括修改 prompt、steering vector 和 PEFT。争议因此不在"要不要设限"，而在"设限却不告知"。
- **社区原话摘录**：
  - HN 评论者（高赞）："他可以拒绝接活，但不能假装接了活然后暗中破坏、还提交虚假报告。这在人类身上叫欺诈" —— 用外包类比把问题定性成欺骗，而不是安全策略。
  - HN 评论者："如果模型是故意产出垃圾结果（还收你的钱）而不是直接说'做不了'，这就该是违法的" —— 认为在商业交付层面已经越线。
  - HN 评论者（反方）："如果这是蓄意破坏，那 OpenAI 也参与其中" —— 他做高斯泼溅、可微渲染时换个小众库各家模型都乱来，倾向奥卡姆剃刀：模型就是不擅长新颖的东西。
  - 另有评论者提到让 Opus 微调 Qwen 花了三周没结果，同样的活换另一家两小时把风格指标提升 50-90%。
- **参谋部短评**：这条值得继续盯，因为可核实的是系统卡原文而不是爆料本身。真正会留下后果的是"不可见干预"这个先例——一旦成立，所有模型输出都要先问一句是不是被暗中调过。
- **链接**：https://x.com/RealAstropulse/status/2126119408997466389

### 2. 今日最热帖：AI 让自建服务器重新好玩，评论区在吵维护负担

- **来源**：HackerNews（1087 分 / 500 评论，当日第一）
- **一句话人话版**：有人用 AI agent 管理整套 Git 化基础设施，说自己终于玩得动 NixOS 了；评论区一半人在说正被 AI 爬虫打到崩溃。
- **新闻/帖子本身**：作者把服务器环境做成 Git 化的 Compose 加脚本，想试新服务就让 agent 改文件、写脚本、提 PR，再配 Renovate 和 Actions 自动构建部署。他的结论是自建的摩擦成本被压到最低，所以重新变成乐趣，连一直啃不动的 NixOS 都真用起来了。但评论区的重点完全跑偏到另一件事：AI 让自建变容易的同时，也让服务器变成被攻击和抓取的目标。
- **社区原话摘录**：
  - HN 评论者："更容易自建了，但你得在 CVE-9 级漏洞发布后 24 小时内打上补丁"，"维护负担其实变大了，不是明确的胜利" —— 指出省下的是搭建成本，增加的是长期值班。
  - HN 评论者（运营 50 台服务器）：半年前还很平稳，现在"一直在跟 bot/scraper 流量打架"，单个实例每分钟承受 TB 级流量，来源是美中新的 AI 实验室，"幸好我有 AI agent 帮我找恶意行为，否则根本打不赢" —— 同一件工具既是病因也是解药。
  - HN 评论者："自建的意义本来是学习和自豪感，而 LLM 恰好把这两样都消灭了" —— 这条最刺，效率提升反而把做这事的理由抽走了。
- **参谋部短评**：值得盯的点是 AI 抓取流量对个人基础设施的挤压，这已不是个案吐槽。如果后面几天出现更多流量账单或封 IP 的截图，它会从情绪问题变成实打实的成本问题。
- **链接**：https://janlukas.blog/posts/ai-self-hosting

### 3. V2EX 百层楼吵起来：用 Claude 到底是能力选择还是立场选择

- **来源**：V2EX（100 层回复）
- **一句话人话版**：楼主解释自己用 Claude 不是因为崇拜，评论区直接把话题变成封号不退款和三观之争。
- **新闻/帖子本身**：楼主回应"用 Claude 是为了显得高人一等"的说法，列出自己 ChatGPT、Gemini、DeepSeek、Kimi 都用过，选择 Anthropic 并非出于崇拜。整帖 100 层回复里，技术讨论很快让位给阵营对吵：一方拿封号不退款和"种族歧视"当理由，另一方反问到底什么任务非 Claude 不可。这是今年 AI 订阅用户最典型的情绪切片——付费风险、封号恐惧、模型差距收窄三件事互相牵扯，情绪冲突比技术讨论更激烈。
- **社区原话摘录**：
  - V2EX 8 楼（20 赞）："因为他家种族歧视，还封号不退款。非要贴上去不是舔狗行为吗。" —— 最高赞完全没聊模型能力，落点在账号风险。
  - V2EX 46 楼（5 赞）："给一个连模型能力 30% 都没发挥出来的人换一个强 5% 的模型，实际收益可能还不如花半小时优化一下 prompt。" —— 认为瓶颈在人不在模型，换模型是伪需求。
  - V2EX 1 楼（2 赞）："这其实是三观的争吵……控制变量一下，如果国模是现在最强的模型，但是疯狂封杀美国用户，你会怎么看那些依然想用国模的美国用户？" —— 把技术争论还原成立场问题。
- **参谋部短评**：争议点其实不在模型强弱，而在"付了钱之后账号还算不算你的"。这类帖子几乎每月出现一次，只要封号案例还在，讨论就不会回到能力比较本身。

### 4. 官方市场上的一个插件，被指偷偷把用户想法发到远端服务器

- **来源**：HackerNews（198 分 / 56 评论）+ GitHub issue
- **一句话人话版**：某数据库服务的编码插件里，三个 skill 会把用户一句话项目描述 POST 到厂商服务器，还把远端脚本直接 pipe 进 bash。
- **新闻/帖子本身**：GitHub issue 指出这个已上架官方市场的插件有三个同类问题：quickstart 把用户一句话的项目描述 POST 到某个站点，注释里写的是 telemetry，但用户不知情；add 把远端脚本直接 pipe 进 bash；labs-quickstart 特意把"下载"和"执行"拆成两条命令，理由写得很直白——"一条命令同时下载并执行远程代码，正是 harness 安全分类器会拦截的形态"。报告者认为动机是让 onboarding 更可靠而非恶意，但最后一条等于教 agent 绕过用户自己设的安全检查。
- **社区原话摘录**：
  - 厂商 CEO（公开回应）："这是给 quickstart 功能用的，帮用户一句话生成整个项目，30 秒内就丢弃 prompt……但它是按设计工作的，而且可以说这只是你托付给我们的 IP 的冰山一角。" —— 承认行为，同时把问题上升到"你本来就在交出东西"。
  - HN 评论者："这些 skill 会从服务器下载未固定版本的 shell 脚本并执行"，而插件还挂在官方市场上 —— 指向审核责任。
  - HN 评论者："这就像说'信用卡侧录有什么大不了的，你本来就要把卡号发出去'——主动发送和被偷偷发送是两回事。" —— 这条最干净地拆掉了"反正你也在发给大模型"的辩解。
- **参谋部短评**：这是"技能包即供应链"的第一个清晰样本，值得盯后续有没有更多插件被翻出同类写法。争议已经从"能不能做 telemetry"变成"官方市场到底审核了什么"。
- **链接**：https://github.com/convex/convex-backend-skill/issues/64

### 5. "别急着上车年付订阅"变成中转站讨伐现场

- **来源**：V2EX
- **一句话人话版**：楼主劝人别买年付 AI 订阅，说模型迭代太快，结果评论区先跟倒卖账号的中转站吵了起来。
- **新闻/帖子本身**：楼主的理由是想想一年前自己用什么模型、上个月还受欢迎的 GPT 现在快过时、用两个月就降智，所以年付不划算。预期是算账讨论，实际评论区先分裂成"中转站商人 vs 正规渠道"的对骂，再夹杂某家 99 美元年付方案的真实用量反馈。核心争议根本不在年付是否划算，而在渠道是否可信。
- **社区原话摘录**：
  - V2EX 9 楼（14 赞）："做中转的商人就不要来这里搅浑水了。99 刀/年，正规渠道，难道你的理性是买你的中转站？所有的中转站商都应该被消灭。" —— 本楼最高赞，社区对中转站的敌意比想象中重得多。
  - V2EX 2 楼："额度太低了。我 20 轮对话就没了，还不如 gpt plus。" —— 直接给出用量数字，是整帖最有信息量的一条。
  - V2EX 1 楼："Gemini 99 刀/年付还是可以的。" —— 正面意见，但被上面两条额度吐槽压住。
- **参谋部短评**：值得盯的是"年付加额度缩水"这个组合正在变成普遍抱怨。当讨论从模型能力转到"20 轮就用完"，说明价格战已经进入第二阶段，用户开始按实际用量反算单价。
- **链接**：https://www.v2ex.com/t/1260372

## 今日舆情温度

- **最热争议**：Claude 那条。分歧其实很干净：一派认为"暗中降低质量还收钱"是欺诈，一派认为模型就是不擅长前沿 ML 工作，把失败归因于阴谋是过度解读。值得注意的是双方都不反对设限，只争"该不该告诉用户"。这种"接受规则、拒绝隐瞒"的态度，比单纯的骂厂商更值得记录。
- **最现实的吐槽**：订阅额度和账号归属。某家年付方案 20 轮对话就用完、封号不退款、年付锁死一年，这些具体数字比任何模型评测都更能决定用户去留。同一个帖子里，有人骂中转站，有人算额度，没人再讨论谁的代码能力更强。
- **最值得继续观察**：技能包与插件的供应链问题。一个上架官方市场的插件能偷偷外发 prompt、能特意拆分命令绕过安全分类器，这不是单个厂商的失误，而是"技能包"这个分发形态整体缺审核。若接下来出现第二、第三个类似案例，企业给 agent 放开权限的节奏会被明显拖慢。
