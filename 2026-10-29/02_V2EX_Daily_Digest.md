## 5. joLink：让 coding agent 真正「跑起来」再交付的 Java 工具，被质疑晚了一年

程序员节点，34 条回复。作者是 Java 后端，核心观察有两条：agent 是根据代码推测结果、几乎不实际运行，所以复杂需求下编译都过不了；排查问题时信息噪音会把模型注意力带偏。他的解法是做一个 MCP + Skill 的执行层 joLink，让 agent 能启动项目、跑起来、看真实结果再改，为此啃了两个多月，最终用 Eclipse JDT 实现增量编译——否则改一行就要 maven 全量编译，闭环根本跑不起来。项目写了四个月，代码基本由 GPT 生成，他负责项目管理、技术选型和验收，目前自己 dogfood，敢不看 AI 写的代码，但上线前仍需专业测试。

评论区是这个帖子最有价值的部分，两代人的判断正面撞上：

- **2 楼 Zhuzhuchenyan（❤1）**：「想法是很好的，只不过晚了一年。『AI 不会运行代码』这个结论目前已经不成立了，随着基模迭代和 harness 工具迭代，这类夹在中间的工具很难有竞争力。」
- **31 楼 gorvey（❤1）**：「基模越来越强，吸收了特别多的开发方法论，已经内化了。现在已经不需要折腾了，只需要写好提示词激活这些能力。」
- **17 楼 stardust21（❤1）**：替作者说话：「如果能节省一些 token 和时间，为什么不是聪明的表现？」

值得关注：这是「垂直 harness 还有没有生存空间」的实时辩论。支持方的论据是启动/编译成本真实存在；反对方的论据是通用 agent 一年内已把这些能力内化。对做 AI 开发工具的人来说，这基本是产品窗口期的判断问题。

## 6. Galta：给 Codex 一块能动手的画布，一笔画完一只猫

## 9. 用 7K 系统提示词把最便宜的 flash 模型用到极致

分享创造节点，6 条回复。作者自述二十年后端与架构经验，对 coding agent 的要求是「稳、准、慎」。他的栈很简单：pi + Magic-Context 记忆插件 + 一份约 7K 的全局系统提示词，模型只用各类最便宜的 flash。因为公司没有测试环境、改完就上线，他的 pi 可以直接访问生产：贴一段报错日志说「分析一下原因」，agent 会自己翻日志、代码、数据库、配置文件，把跨库跨模块的调用链讲清楚再给建议。唯一禁止 agent 做的是改数据库。提示词全文在 gist。

评论区主要是追问兼容性，信息量不大，但暴露了一个真实约束：

- **1 楼 Hubs**：「workbuddy / codebuddy 能用不？」后续对话里他说公司提供企业版免费用，舍不得换。
- **5 楼 yidinghe（作者）**：「简单，用 pi 即可。」即这套提示词强绑定他自己的 harness，不是拿来即用的通用方案。

值得关注：这是「便宜模型 + 精心设计的系统提示词 + 只读生产权限」的一种低成本路线，成本敏感团队可以直接抄思路（先限制写权限、再谈能力），但别指望提示词跨 harness 通用。
