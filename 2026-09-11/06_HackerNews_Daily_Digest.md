## 4. Windows XP 是怎么随机选你的初始头像的？
`335 分 / 164 评论` — https://devblogs.microsoft.com/oldnewthing/20260909-00/?p=112683

**摘要**：Raymond Chen 回答了长期疑问：XP 创建账户时从 `User Account Pictures\Default Pictures` 目录随机挑头像，用的是 `RtlRandomEx`，以 `GetTickCount()` 的当前值作初始种子，并采用一次遍历的随机选择算法（而不是先数总数、随机取一个、再遍历第二遍）。文章还分析了这种写法的好处：省一次遍历，也能更早开始渲染。

**为什么值得关注**：难得的「考古式」工程细节，也是理解早期 Windows 里 `RtlRandomEx` + 弱种子这类设计取舍的好案例。

**评论**：

## 6. Forgejo ≤16.0.3 严重 RCE 漏洞
`139 分 / 49 评论` — https://codeberg.org/forgejo/forgejo/milestone/139655

**摘要**：Forgejo 发布 16.0.4，修复一个严重远程代码执行漏洞。成因很微妙：从模板仓库生成新仓库时，Forgejo 会 clone 模板、删掉 `.git`、对 `.forgejo/template` 列出的文件做变量展开，再初始化新 git 仓库。而变量展开可被滥用创建一个新的 `.git` 目录，git 初始化时会「认领」它——恶意模板仓库因此能读取宿主机任意数据并执行任意进程。修复方式是在展开完成后、初始化 git 前删除任何已存在的 `.git`。同版本还修了一个 API 权限绕过（受限 access token 可越权修改）。

**为什么值得关注**：自建代码托管（Forgejo/Gitea）用户量大，模板功能 + git 初始化这类组合属于容易被忽视的攻击面。

**评论**：
- **jzebedee（贴官方补丁说明）**：「……变量模板展开可能被滥用来创建新的 `.git` 文件夹，git 在初始化新仓库时会采纳并合并它。恶意模板仓库可被用来读取 Forgejo 主机上的任意数据，并在主机上执行任意进程，构成远程代码执行攻击。」
- **rcleveng**：「Codeberg 提示该仓库请求量激增，搜索请求无法处理……有镜像吗？」
- **Sphax**：「页面打不开，但愿这个端点是在我的 Tinyauth 后面。」

## 10. JEP 544：提前编译（AOT）代码编译
`64 分 / 24 评论` — https://openjdk.org/jeps/544

**摘要**：OpenJDK 的 JEP 544（Leyden 项目，John Rose 主导）目标是把应用代码在「训练运行」中编译成本地代码并存入 AOT cache，让 HotSpot 启动时就能拿到优化过的本地代码，从而改善启动与预热时间；生产负载变化时仍由 JIT 动态生成代码以维持峰值性能。明确非目标是不提供 AOT-only 模式，应用会同时使用 AOT 与 JIT，仅支持 AArch64 与 x64。

**为什么值得关注**：Java 启动/预热慢这个老问题终于有了官方正统方案，云原生场景（serverless、CLI、短生命周期服务）受益最直接；但也意味着 Java 在「一次编写到处运行」上进一步收缩。

**评论**：
- **java-man**：「希望以后能有 AOT-only 模式（编译成原生），甚至交叉编译。」
- **cyberax**：「Excelsior JET 25 年前就干过这事。可惜 Sun/Oracle 从没跟他们合作把原生应用落地——那本可以救下桌面端的 Java。」
