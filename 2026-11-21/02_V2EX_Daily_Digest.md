**为什么值得看**：这是站内少见的、不以跑分为依据的横向对比。争论焦点最后落到“许愿式玩具”和“企业复杂工程”是两种完全不同的评测场景，比谁强谁弱有用得多。

## 4. 较大程度使用 AI coding 后很难进入心流状态
`1258448` · 24 回复

**摘要**：手写代码时是长时间单进程专注，一个问题啃到底；现在给 AI 派任务、点发送，注意力立刻飘走（刷手机、做别的事），几分钟回来看结果，不满意再让它改，循环往复还带情绪起伏。作者把这种状态叫“多进程工作”——进程切换频率比以前高得多，切换开销就是注意力被打断的成本，这也解释了“AI coding 之后反而更累”。他最后退回了最原始的 auto completion，“那种确定性和清净感又回来了”。

**评论**
- **6楼 @marcogray ❤2**：现状描述得很实——“现在日常 coding 就是回到工具里敲 OK，敲完就切回来刷视频刷新闻。就是日常被切得很碎，以前看短视频多了就这样了，注意力不行”。
- **15楼 @gybin02 ❤1**：给出可操作解法——“一次只让它改一个小功能，改完我就过一遍 diff，脑子一直在线上，反而比以前手写还专注。最怕的是让它一次改一大坨，等半天回来一看，看不懂也懒得看了”。
- **4楼 @sentinelK ❤1**：从工程管理角度反打——如果你的真实工作状态真像那条曲线，说明公司的开发流程有问题。“一线开发者因为有信息差，做出的决策往往都比较短视、局部，这会导致代码快速腐坏。”他认为古法编程和硅基编程的节奏其实没差，“只不过你的角色从一线变成了组长”。

**为什么值得看**：AI 提效叙事里最少被讨论的成本是注意力税。15 楼那条“小步 diff”是目前看到最落地的对冲方式。

https://www.v2ex.com/t/1258448

## 6. 开源一个 Agent 长期记忆系统：262k 多跳 48.3%
`1258680` · 1 回复

**摘要**：作者是 21 岁中医专业大三学生，没有 CS/AI 背景，10 月中才开始研究 API，两周多做出了开源记忆系统 WhaleYing Memory（Apache-2.0）。在 MemoryAgentBench 的 Conflict_Resolution（substring exact match，不是 LLM judge）上：262k 单跳 93.2%（论文基线 GPT-4o 60 / BM25 56），262k 多跳 48.3%（CAR 论文 41，BM25 仅 3）；全程在一台无独显的 i5-13420H / 16G 轻薄本上完成。它解决三个具体问题：同一事实多版本时谁知道哪个已被取代、长上下文里别检索到旧值、多跳问题逐跳凑齐证据。

**评论**
- 评论区只有 **1楼 @cryptitalk** 提问“多跳是什么意思？”，**暂无高赞讨论**——这条是因为项目本身值得读代码才推的，不是因为有热议。

**为什么值得看**：作者自己给的对照最有说服力——同为 262k，多跳任务直接读全文只有 5.3%，加记忆系统后 48.3%；单跳也能从 64% 拉到 93%。他的判断是单跳瓶颈在“记忆有没有找对”，多跳还额外依赖作答模型的证据组合能力（换作答模型 25.3% → 48.3%）。长上下文 ≠ 记忆，这组数字把差别量化了。
