https://www.v2ex.com/t/1246683

摘要：作者指出 FastAPI-MCP 的两个痛点——endpoint 变多导致 MCP tools 占满 context，以及列表类接口返回上百 K/MB 直接撑爆 context。他的解法是借 GraphQL 思路：利用 FastAPI 的 return annotation，把每个 endpoint 当作 GraphQL 节点、返回类型当作子节点树，做成 query/mutation schema，从而支持"只 pick 需要的字段"。一套组合拳同时解决 tools 膨胀和响应过大。为什么值得关注：这是目前 MCP 服务设计里最实际的工程问题，帖子无评论，但思路对做 Agent 工具链的人直接可用。
