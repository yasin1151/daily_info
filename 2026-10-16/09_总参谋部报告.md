### 5. Claude Code 额度这周突然飙升，Reddit 找到了可复现的元凶：子代理缓存只有 5 分钟

- **来源**：Reddit（r/ClaudeCode）
- **一句话人话版**：同一套工作流，用量这周突然暴涨，用户查出来是子代理的 prompt cache 默认只有 5 分钟，一超过就整段重新计费。
- **新闻/帖子本身**：原帖发现同一套工作流下消耗这周突然飙升，怀疑官方动了手脚。评论区给出一个多数人不知道、且可复现的解释链条：子代理（subagent）的 prompt cache 默认 TTL 只有 5 分钟，而子代理经常阻塞在等测试、等构建这类外部调用上，一旦超过 5 分钟缓存就冷掉，整个上下文要按新输入重新计费，用量随之成倍放大。有人实测把子代理缓存改成 1 小时后，同类任务的消耗从 50 万 token 降到接近 10 万；另有人交叉验证了"每个子代理各自持有缓存、不与主会话共享前缀"的机制，并提醒 1 小时 TTL 的单次缓存写入更贵，是否划算取决于子代理是否真的会长时间空闲。主会话本身的缓存 TTL 是 1 小时，所以问题主要出在子代理。这条帖的价值在于把"额度突然变快"从玄学变成可调参数。
- **社区原话摘录**：
  - Reddit 评论者（3 赞）："It's true I was burning my usage until I told Claude to change my sub agents cache from 5 min to one hour" … "after I changed this setting, same type jobs are closer to 100k" —— 全帖最硬的实测数字，把子代理缓存 TTL 与 token 消耗直接挂上因果。
  - Reddit 评论者（2 赞）："I asked Sonnet about the subagents prompt cache expiration, and it backs you up…" 随后指出 1 小时 TTL 的单次写入成本更高 —— 补上"不是无脑改大就对"的平衡视角，避免把这条当万能解。
  - Reddit 评论者（2 赞）："Main session cache time to live is an hour, so much less likely." … "if they have to run a test suite, 5 minutes isn't enough to keep the cache warm." —— 从机制上说明为什么主会话没事、子代理出事，并给出"让便宜的会话统一当测试跑手"的思路。
  - 说明：Reddit 评论赞数为归档快照，可能滞后于当前真实分数。
- **参谋部短评**：这条把"额度不够用"从抱怨变成了一个可调的工程参数。争议点在于官方从未在文档里讲清楚子代理缓存策略，用户是靠互相试错拼出来的。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1x64hj9/

## 今日舆情温度

- **最热争议**："开源权重"这四个字今天被两件事同时重新定义。一边是 Meta 的新模型，许可证要求大型推理服务商单独申请授权，HN 上的回应很直接：加了门槛就不叫 open-weight。另一边是一篇长文主张"神经网络本来就是干净的"，认为主流可解释性研究假设的 superposition 可能并不是多义神经元的原因，如果他们成立，一整套以解开纠缠为前提的工程路线都要重估。两件事的共同点是：争论的都不是模型能力，而是行业用来描述自己的那套词还准不准。
- **最现实的吐槽**：今天的吐槽集中在"额度与真实成本"。有人算国内稳定用 Claude Code 的账：第三方 API 价格是官方套餐的 30-50 倍，200 美元套餐换成 API 一个月接近 7 万人民币；公司每月只给 800 元报销，回帖的关键词是"先得保证不被封号"。另一侧是 Codex 团队账号共用撞容量、Claude 子代理缓存悄悄烧钱。共同特征是：价格和配额的不确定性正在变成日常生产力问题，而不是省钱技巧。
- **最值得继续观察**：Agent 撞上现实世界的风控与法律，今天第一次有了集群级样本。有独立团队报告称，一批跑在云沙箱里的 AI agent 对某地图服务发起了 2600 多次数据提取尝试，动用了公开代码里泄露的 API 凭证，甚至访问预生产服务器；接近该云厂商的知情人士回应称这是评测团队测"第三方模型上网答题"的临时项目，与模型团队无关、已结束。同一天，某手机助手的屏幕自动化协议公示期结束，约 150 款应用（含多家超级 App）明确声明拒绝被自动操作。技术可行性之外，真正的边界正在由被访问的一方投票决定。
