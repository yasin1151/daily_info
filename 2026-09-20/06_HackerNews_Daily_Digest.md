## 1. AI 生成的海报不必是垃圾（1308 分 / 722 评论）

## 8. Tin：给 Postgres 的全文检索（177 分 / 70 评论）

PlanetScale 发布 TIN（Text INdex），Postgres 全文检索扩展，现已 GA，可用于其 Postgres 与 Neki 数据库。用法是 `CREATE INDEX ... USING tin(col)`，查询用 `==>` 运算符。功能覆盖布尔表达式、短语/span 查询、模糊/通配/正则、大小写与重音折叠、COUNT(*) 及 BM25 打分 top-k。作者称现有至少三种 Postgres 文本索引都无法同时满足这些需求（还要兼顾 join、复杂 WHERE、持续更新、复制、备份、事务可见性），并给了包含全部 Wikipedia 与 Reddit 评论语料的 benchmark，含并发写入场景。

**为什么值得关注**：Postgres 生态最常被吐槽的短板又被补了一块，并且这轮浪潮被评区判定为"AI 编码生产力第一次在真实世界里显形"。

真实评论：
- **andrenotgiant**（信息量最大）："各大数据库公司纷纷推出全文搜索，是 AI 编码生产力显形的例子。paradeDB/pg_search 开头，Timescale 有 pg_textsearch，Neon 和 Databricks 有 Lakebase Search，现在 PlanetScale。据我所知这些都是 BM25 实现——你直接让 agent 读 BM25 然后在你的系统里实现就行。架构和集成上还有空间可挖，但不难想象这会走向激烈的商品化。"
- **tannhaeuser**："Postgres 本身就有 pg_fts（tsvector/tsquery/tsrank），一个相当成熟、与函数索引和查询优化器集成的全文检索包。我为什么要用一个不是核心 Postgres 一部分的、vibecoded 的东西？"

## 9. Brood War Bench：让 LLM 打星际争霸（113 分 / 62 评论）
