### 2. Alpine 的 OpenSSH 只要发一个超长密码，就能登录任意无密码账号

- **来源**：HackerNews（546 分、106 评论）｜Alpine 官方安全公告
- **一句话人话版**：一个 30 年前的 C 库返回值习惯，让整个 Alpine 生态的 sshd 可以被一次连接绕过认证。
- **新闻/帖子本身**：musl 的 `crypt()` 在密码超过 256 字节时返回字符串 `*` 作为错误标记，而 `/etc/passwd` 里「未设置密码」账号的密码字段恰好也是 `*`，两者一比较就判定匹配成功。攻击者只需发一个 257 到 1024 字节的超长密码，无需重试即可登录 `root:*` 或 adduser 创建的无密码用户。触发条件是跑 Alpine 的 openssh-server、开启 `PasswordAuthentication yes`，且机器上另有一个正常哈希账号。3.16 至 edge 全中，容器里不跑 sshd 不受影响。修法是升级后必须重启 sshd，只做包升级不重启无效。
- **社区原话摘录**：
  - HN 评论者（5 条回复）：“都 2026 年了还在用 C 写这种东西简直不可想象……就像因为喜欢火柴所以拿火柴搭桥，这是纯失职。” —— 情绪最激烈的一条，矛头指向用 C 维护认证栈这件事本身，而不是某个补丁。
  - HN 评论者（3 条回复）：“musl 的 crypt() 在 key 超过 256 字节时返回 *。而 * 正好是每个无密码账号的存储值，于是『哈希』匹配、登录成功。一个号称最遵守 POSIX 的 C 库这么干，太疯狂了。” —— 根因讲得最清楚的一条，哨兵值和「无密码」共用了同一个字符串。
  - HN 评论者：“我一直说别用 Alpine 和 musl，但总有人回我静态链接值这个价。” —— 把讨论拉回老争论：镜像体积和静态链接的收益，是否值得承担 musl 的这类风险。
- **参谋部短评**：这是本周最严重的供应链级漏洞，Alpine 是容器镜像的事实基底。真正该盯的不是补丁本身，是有多少 CI 和集群节点只做了包升级、没有重启守护进程。
- **链接**：https://alpinelinux.org/posts/2026-11-05-openssh-password-authentication-bypass/

- **参谋部短评**：这是「agent 替你上网」时代的新隐私面——问题不在训练数据，而在每一行访问日志里都躺着用户身份。值得继续盯官方是否给出解释和开关，而不是等下一条 issue。

## 今日舆情温度

- **最热争议**：模型到底有没有悄悄变差。r/ClaudeCode 那条 920 分的帖子把体感派和实证派彻底分开：一边是「重复九次、越改越回去」的具体经历和「发布前腾算力所以静默量化」的产业解释，一边是每天上万条请求的团队说毫无感觉、并怀疑用户的提示词和项目早就改过。争论没有裁判，因为双方都没有同一套可复现的评测，最后只沉淀出一条共识——把否决过的方案写成文件，比等厂商回滚有用。
- **最现实的吐槽**：额度。今天几条讨论指向同一件事：额度不是在模型上被吃掉的，而是在结构上被吃掉的。有帖子实测订阅配额约等于 API 定价但缓存读只按四分之一计价、小模型反而被溢价；有人发现没装任何 MCP 每个会话也自带一万四到两万上下文，而且这笔基线每轮都随请求发出；还有人指出内置搜索子代理默认继承主模型，每次文件检索都按旗舰价扣额度。真正让人焦虑的不是单价，是这些看不见的常驻开销。
- **最值得继续观察**：开源权重在一天里被推了好几步——2.8 万亿参数的完整权重带着「防云厂商白嫖」的限制条款放出，两个国产 agent 模型把训练配方和数据一起开源，一个 650 亿稠密模型宣称用十分之一预算在终端任务上压过更大的模型；而另有一家 coding 模型反其道收紧权重，只做定向共享。同时一条更硬的信号是：自主流程跑出九百多个内核提权漏洞的候选补丁，API 成本一百二十万美元。这几件事今天都缺社区实测，先记在观察位。
