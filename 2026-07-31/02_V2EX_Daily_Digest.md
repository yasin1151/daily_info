## 没人讨论新版 MCP 协议吗？无状态化、交互式 UI、长任务支持

**帖子链接：** https://www.v2ex.com/t/1230872（19 条回复）
**节点：** 程序员

**背景：** Anthropic 2026年7月28日发布新版 MCP 规范，核心变化是将状态从 Server 移至 Client，使 Server 实现无状态化，同时引入 MCP Apps（支持交互式 UI）和 Tasks（支持长时间任务）。这是 MCP 协议发布以来最大的一次架构升级。

**主要内容：** 新版 MCP 的核心进步：Server 支持无状态化（stateless），通过将状态管理迁移到 Client 端，解决了以往 sticky session 架构下 Server 崩溃后服务中断的问题；MCP Apps 引入 iframe 实现的交互式 UI，支持多个组件联动（类似微前端）；Tasks 支持长时间后台任务；企业级认证和权限管理得到完善。社区讨论分化：一部分人认为进步显著，尤其对复杂业务流程的交互式 UI 需求很刚需；另一部分人认为当前"skill + curl"的方式已经够用，MCP 的 tool 占用的 token 太多且渐进式披露不好用。

**精选评论：**

- V2EX 17 楼 @xue777hua："这次的升级最核心的就是把 state 消除掉，从 server 移动到了 client, 从而保证 server 是 stateless，从而保证可扩展性...如果协议不支持 stateless，MCP 和 HTTP 没有啥大的本质区别" —— 精准点出本次升级的本质：不是加新功能，而是修复架构缺陷。
- V2EX 5 楼 @yh7gdiaYW："MCP 规范里现在实际只有 tool 在用，resource、prompt 都已经路边一条了" —— 来自开发者的诚实观察——规范的三个核心概念在实际生态中只活了一个。
- V2EX 18 楼 @ychost："MCP Tool 太占用 Token 了，不好渐进式披露，tool_search 也不好用，还是 CLI 好用，--help 可以一点点加载子命令" —— 用 CLI 的层级式帮助对比 MCP tool 的批量 token 消耗，指出了 MCP 协议在当前模型上下文窗口限制下的实际痛点。

**为什么值得关注：** MCP 是 Agent 工具链的底层通信协议，这次无状态化架构升级对企业级部署至关重要。但社区反馈中"skill + curl 够用""CLI 更好用"的声音说明 MCP 至今仍未成为无可争议的标准——这与 Claude Code/Codex 的 CLI-first 设计哲学直接相关。

## memU：给 Claude Code、OpenClaw、Hermes 装上共享记忆层

**帖子链接：** https://www.v2ex.com/t/1231096（4 条回复）
**节点：** 分享创造

**背景：** V2EX 用户在分享创造节点发布了一款开源项目 memU，定位是面向多 Agent 用户的轻量级跨工具记忆层。核心卖点是将代码从 3 万行缩减到 500 行，让 Agent 负责思考、memU 只做存储和检索。

**主要内容：** memU 的目标是解决多 Agent 用户的"记忆孤岛"问题——Claude Code 配好的项目环境切到 Cursor 又要重新讲一遍。实现上采用了极简 500 行核心架构，去掉了传统记忆框架中的多阶段 LLM 提取链、查询改写器、重排器等组件。核心数据：每轮检索零额外 LLM 调用，p95 延迟低于 35ms，每轮额外 token 开销约 120 tokens。所有记忆以纯 Markdown 文件存储在本地，可用 VS Code/grep/Git 直接管理。支持本地离线模式和云端同步模式。

**精选评论：**

- V2EX 2 楼 @greatbody："需要申请 key？你们这个插件会回传数据到你们服务器么？回传什么数据？" —— 用户对云端同步模式的隐私担忧，直击跨设备数据共享的安全信任问题。
- V2EX 3 楼 @yidinghe (OP)："@greatbody 恐怕是把整个上下文都传到服务器上，介绍里面说了 'Across Devices'" —— OP 的回复反而加重了隐私担忧，说明产品在数据安全方面需要更强的沟通。

**为什么值得关注：** 500 行核心实现是 AI 记忆层赛道的一个有趣信号——当底层模型足够强时，中间件层可以大幅瘦身。和多 Agent 工作流的兴起（Claude Code + Codex + Cursor + Hermes 并行使用）直接相关。但隐私和云端同步的信任门槛是目前社区最关注的未解决问题。
