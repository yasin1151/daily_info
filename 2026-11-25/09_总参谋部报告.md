### 1. 「托管的大模型不为我工作，只为它母公司工作」——HN 870 分大帖
- **来源**：Hacker News（870 分，367 条评论）
- **一句话人话版**：一个开发者想让 agent 帮他买正版音乐，结果发现模型肯帮他扒歌，却不肯绕过 Bandcamp 的人机验证。
- **新闻/帖子本身**：作者用 Claude Code 写了个 skill：从 Instagram reel 里认出歌曲，找到乐队 Bandcamp 页面去买正版。Bandcamp 加了人机验证后，模型拒绝绕过；但同一个 skill 里"从 YouTube 扒歌下到本地"的路径，模型照做不误。一条给乐队付钱，一条一分不给。作者的结论不是"模型不肯帮我黑站"，而是这些模型只为允许它工作的公司工作：合规、法务、商业利益高度一致，用户利益不在其中。
- **社区原话摘录**：
  - HN 评论者："Claude refused to help me hack the ads out of my smart TV, which is my right by law under the DMCA. (Fortunately codex did help me, for now)." —— 同一件事换到给自己买的电视去广告，Claude 拒绝、Codex 接了；他的判断是用户正在失去对"自己买的东西"的控制权。
  - HN 评论者："It permitted itself to build a Duo Lingo style clone application... but it refused to use the example sentences and native-speaker audio that the Sejong Institute publishes." —— 一位家长让 Claude 用世宗学堂的免费教材做韩语背单词 app，模型只肯用单词、拒绝用例句和母语音频，坚持自己另写例句，结果根本没法给孩子用。
  - HN 评论者（反方）："While it's fun to tell people ... this isn't really true... competition forces companies to find enough value for their customers that they keep paying for that product." —— 反驳意见：所有商品都在公司利益和用户利益之间取舍，把这件事说成 AI 独有的背叛，属于过度演绎。
  - HN 评论者（拿数据反驳）："We have 8k agent replies from real users of our open source battle system... I sent them all to Jev to categorize if there was a refusal. There only were 21." —— 他把八千条真实 agent 回复交给模型分类，只找到二十一条拒绝，认为"拒绝很普遍"这个前提本身需要证据。
- **参谋部短评**：这条值得盯，不是因为结论新，而是反例都极具体：拒绝的理由是内容版权，可用户要的恰恰是付费买正版。争议点在于"厂商安全策略"和"用户正当需求"由谁划线。
- **链接**：https://michaelharley.net/posts/2026/11/01/llm-agents-work-for-their-parent-companies-not-for-you/

### 2. GLM-5.4 用「循环层」换智能，HN 1162 分：夸架构透明，骂「马拉松式思考」
- **来源**：Hacker News（1162 分，374 条评论）、中文 AI 早报
- **一句话人话版**：智谱发布 GLM-5.4，把 28 层跑两轮来提升能力、不靠堆参数，代价是模型会长时间自我怀疑。
- **新闻/帖子本身**：这是智谱第一款不用"堆参数"换智能的旗舰：750B 基座里 28 层做两轮循环，官方称效果相当于 2 至 3 万亿参数级模型，并已在 GLM Coding Plan 全量开放，V2、V3、团队版额度升到 1.5 倍，V1 老用户没加。200 个真实编程场景里，视觉 Coding、界面复刻、长程任务表现突出；官方自己也提示模型容易进入长时间的"雷霆大思考"。权重计划开源，API 待安全评估后开放。
- **社区原话摘录**：
  - HN 评论者："constantly second guessing themselves even when working with the simplest of things ... time to completion is dramatically higher compared to frontier unless you're dealing with ridiculus tps performance." —— 抱怨"马拉松式思考"：概念上最简单的事也要反复自我怀疑，单次看不明显，按天按周累积，完成时间远高于前沿模型。
  - HN 评论者："Q3.8 27B felt like it was over-thinking to me at 20 tokens/sec. At 115 it seems just fine. Claude may go back and fourth just as much but you don't see it." —— 认为"想太多"很大程度是速度问题：同样多的思考，在 115 tok/s 下就不刺眼，而闭源模型只是把这段过程藏起来了。
  - HN 评论者："I love the transparency... a refreshing change from the locked-down approach of the western companies" —— 少数正面声音：智谱把架构和训练细节写出来，比西方实验室的封闭做法更有参考价值。
  - HN 评论者（算代价）："for GLM 5.3 at least this drops AA index from 32 to 23, which is a lot"。 —— 他也承认把推理档位调低能省钱，但综合指数会从 32 掉到 23，等于退回小一号模型的水平，省时间和保质是硬取舍。
- **参谋部短评**：真正要看的不是跑分，而是"循环层加长思考"在 agent 连续任务里的时间账。今天这条争论已经可以量化：同样的活，多花几倍时间换回多少分。
- **链接**：https://z.ai/blog/glm-5.4 ｜ https://news.ycombinator.com/item?id=50609685

### 3. 5.9GB 的 27B 三值模型，真能在 Mac mini 上干 agent 活
- **来源**：Hacker News（270 分，92 条评论）
- **一句话人话版**：有人把 Qwen 27B 压到 5.9GB，在 Mac mini 上跑出接近满精度的 agent 能力，评论区一边实测一边泼冷水。
- **新闻/帖子本身**：Ternary Bonsai 2.5 27B 用三值量化，体积仍是 5.9GB，主打 agentic coding 与本地私有知识工作。SWE-bench Verified 从上一代 60.8 升到 75.6（满精度基座 80.6），Terminal-Bench 2.1 从 52.8 到 60.1，AppWorld 从 51.2 到 90.5；主要修的是上一代"想太多、循环重复"的毛病。H100 上 291 tok/s，RTX 4090 上 204 tok/s，Apache 2.0，llama.cpp 与 MLX 都能跑。
- **社区原话摘录**：
  - HN 评论者（Mac mini M5 Pro、24G 内存实测）："about 22-25 tokens/s... I can get up to 128k context in memory easily which makes it potentially useable for agentic coding"，并补了一条实测：25 个测试里修好一个真实 bug、没有弄坏别的。 —— 少见的可复现数据，说明"能用"已经不只是演示。
  - HN 评论者："Bonsai 2 I would describe as Certified Usable... probably on par with Luna or Sonnet, definitely not Opus." —— 给的是分级判断：多步 agent 工作流能跑，但别按"接近 Opus"来期待。
  - HN 评论者（泼冷水）："My neighbour's cat scored equivalent to Opus 4.6 this week... Is it entirely worth the hype: no." —— 质疑跑分口径：小模型在 SWE-bench 上追平半年前的前沿，多半是基准漂移加上挑题。
  - HN 评论者（上一代踩坑者）："I tried the V2 and it was unfortunately really bad. It ran but it got stuck in loops and the output was comparatively poor." —— 他补了一句这次的进步在于能在原版 llama.cpp 上跑，管理成本降了；但上一代"卡在循环里出不来"的印象还在。
- **参谋部短评**：这条的价值是"本地可用"的证据链第一次比较完整：速度、上下文长度、真实修 bug 都有数字。争议在分数能不能等同于体感，评论区已经给了否定答案。
- **链接**：https://prismml.com/news/bonsai-2-5-27b ｜ https://news.ycombinator.com/item?id=50633922

### 4. 13 个 subagent 对 1 个 Codex：烧掉 4400 万缓存 token 换 3.5 分
- **来源**：Reddit
- **一句话人话版**：有人用同一句需求分别让"13 个专职 subagent"和"纯 Codex"各做一个应用，质量 8.5 对 5，成本差五倍。
- **新闻/帖子本身**：作者给 Codex 装了分析师、架构、前后端、DBA、DevOps、安全、测试等 13 个 subagent，用一份 AGENTS.md 规定什么任务调哪个，再用同一句需求各建一个任务管理应用做对照。耗时 13 分钟对 74 分钟，输出 token 3.6 万对 10.2 万，缓存 token 124 万对 4431 万（35.8 倍），质量 5/10 对 8.5/10，差距全在工程细节：模块拆分、数据库迁移、57 个测试全过、Argon2id 存密码、HttpOnly cookie、独立安全审计报告。作者结论：要成品上 swarm，要快速糊一个纯 Codex 更划算，且 swarm 吃掉五小时额度的一半。
- **社区原话摘录**：
  - Reddit 评论者（2 赞，归档快照）："Stop using cloud models. With self hosted model there is no token limit - when better, the more agents you launch, the cheaper it gets." —— 提出本地模型替代路线；但这条把自建硬件的固定投入和电费完全略过了。
  - Reddit 评论者："it just had more instruction from you on what you wanted"，并补一句 "you are not the DM in an RPG session"。 —— 认为差距来自指令的具体程度，subagent 真正的价值是隔离上下文和控制并发，不是扮演十几个角色。
  - Reddit 评论者："Man's token budget got absolutely vaporized but hey, at least the furnace spat out a 8.5." —— 一句吐槽把性价比讲清楚了：预算瞬间烧光，换来的是能交付的成品。
- **参谋部短评**：这是今天最实用的一份账本，尤其是缓存 token 涨 33 倍这一栏，多数人只算输入输出。争点在于质量分是否值五倍钱，取决于你做的是演示还是交付。
- **链接**：https://www.reddit.com/r/LLM/comments/1y46zee/

## 今日舆情温度

- **最热争议**：托管模型到底为谁工作。HN 那条 870 分的帖子把"模型拒绝帮用户做合法的事"归结为厂商利益，反方则说所有商品都这样、这叫过度演绎；同一天另一批人又在算 13 个 subagent 烧 4400 万 token 值不值。争论焦点已经从"模型多聪明"换成了"它听谁的、怎么组织"。
- **最现实的吐槽**：额度与等待。有人记录单个任务几分钟吃掉 2% 周额度、一次会话里子 agent 把上下文顶到 240k 掉 15%；GLM 用户抱怨最简单的改动也要"马拉松式思考"；Neon 的 Pro 用户说两个五小时额度用完周额度只剩 80%；本地模型那边则在算 22 tok/s 到底够不够干活。共同点是瓶颈不在能力，而在账单和等待时间。
- **最值得继续观察**：三条线都指向 agent 的"最后一公里"。一是 AI 开始被允许批准 PR，权限边界怎么划还没有真实使用反馈；二是 Agent Skills 类项目在开源榜上集中出现，经验正在被做成可安装的模块；三是 5.9GB 的本地 27B 已经有人跑真实任务，数据不出本机的路线开始有工程证据。明天该看的是第一批踩坑帖，而不是又一轮跑分。
