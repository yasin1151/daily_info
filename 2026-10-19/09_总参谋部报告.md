### 1. Codex 5x 撑不过两天，半夜重置成了续命机制

- **来源**：V2EX 程序员节点（多个同题帖）
- **一句话人话版**：一批 Codex 用户同时抱怨套餐额度缩水，5x 两天见底、10x 也撑不住，只能等官方不定期重置。
- **新闻/帖子本身**：V2EX 程序员节点当天冒出三四条讨论同一件事的帖子，分别有 27、14、13 条回复。抱怨的核心很一致：随便问几个问题 10% 额度就没了；下午三点开始用、七点下班只剩 40%。评论区对原因的分析比官方说明更具体——有人实测新版模型的 tps 从 20 到 30 提到了 50 到 60 甚至 80，但周总量没变；有人指出 fast 档现在是 2 倍消耗、默认上下文窗口还大了一倍；也有人给出根本判断：Plus 的月额度折算下来只有两百多美元，再省也是这些。于是每周两三次的“重置”变成事实上的续命手段，而这次重置发生在半夜，专门有人发帖吐槽“欺负国人”。
- **社区原话摘录**：
  - V2EX 5 楼："我用 Claude Code Max 5x 的 Opus 5.5 做主力开发，配合 ChatGPT 5x 的 GPT-6.1-Sol High 偶尔做一下 review，结果就是前者周额度能用 5 天左右，后者 2 天周额度就没了，全靠 reset 撑着。" —— 最具体的一组横向对照，说明两家订阅制的实际可用天数差了一倍以上。
  - V2EX 8 楼："额度缩水，所以隔三五差的进行重置，还让用户感恩戴德。" —— 把“重置”从福利重新定义成厂商的节奏控制手段，这是当天被引用最多的一句情绪总结。
  - V2EX 10 楼："别说 5x 了，就连 10x 都一样的缩水严重，下午 3 点多才开始用，7 点多下班就只剩下 40 多了。" —— 高价位档同样被打穿，说明问题不在档位选错，而在计价方式本身。
  - V2EX 另一帖 1 楼（被追问最多的一条）："opencode go 的 dsv4f，挺耐用的，或者顶着封号风险再搞一个 claude pro 来用。" —— 讨论已经从“怎么省”转向“换谁”，替代工具清单成了这类帖的实际产出。
- **参谋部短评**：这是今天最能反映订阅制真实成本的一条。争议点不在“够不够用”，而在计价单位从月费变成了“每周能烧多少美元额度”，而重置节奏由厂商单方面决定。

### 2. 一个人的 Claude 三部曲：开卡成功、顺利升 5x、十天被封

- **新闻/帖子本身**：第一帖楼主说自己不会编程，在 PC 端直接开 20 美元 Pro，用得太猛不够用，升 100 美元 5x 时触发验证，用闲鱼办的马来西亚/印尼驾照过验证，再用 Revolut 付款成功。期间他用模型复刻了待办清单、做了信用卡工具，感慨“普通人也可以轻松定制满足自己需求的 app”。第二帖就是结局：被判定违反地区规则并封号，而他自认最后一个操作是“插入了手机，让 Claude Code 帮我分析卡顿发热的原因”。同日还有一帖是 iOS 端升级 Max 扣费不到账、客服推诿。

### 3. DeepSeek 开源 763B 新模型，顺手把搜索接口打到 0.75 美元/千次

- **来源**：HackerNews（521 分、252 条评论）、AI 早报
- **一句话人话版**：DeepSeek 把网页、App、API 全量切到 V4.1-Flash-1017 并开源权重，同时开放自研搜索与抓取接口，按成功请求计费。
- **新闻/帖子本身**：新模型 7630 亿参数、1M 上下文，MIT 许可开源，官方称推理、编码、Agent 任务和视觉基准都有提升，靠基于自反馈的强化学习增强了从零搭完整项目的能力。更受关注的是配套的两个原始接口：搜索接口支持 site:、lang:、after: 等运算符，抓取接口把单页转成 Markdown；计费不按 token 也不按条数，只按“成功请求”算，失败、空结果、超时都不收费。HN 上讨论的分裂点很典型：一边算价格，一边问反爬能力。另外通过 API 在常见 harness 里触发的搜索目前不收费，11 月 1 日起按次计费。
- **社区原话摘录**：
  - HN 评论者（意译）："对比一下：Brave Search API 每千次 5 美元，Kagi API 12 美元。" —— 直接把定价放进竞品坐标里，这是这条帖被顶上首页的主要推力。
  - HN 评论者（意译）："这类服务对付反爬怎么样？遇到 Cloudflare 勾选框或者 Anubis 会怎样——报错、拿到垃圾内容，还是真的能拿到我要的正文？" —— 最尖锐的提问，指出便宜的价格表背后真正的变量是能不能穿过反爬，而不是接口写得多漂亮。
  - HN 评论者（意译）："fetch 凭什么收钱？我以为抓取是本地 harness 干的。" —— 代表相当一部分人的第一反应；下面有人解释出网 IP、渲染、反爬和 Markdown 清洗才是成本所在。
  - HN 评论者（意译，唱衰派）："这个价格迟早会飞涨，AI 公司需要更多钱。" —— 提醒补贴期定价不能当长期成本基线，这也是 11 月 1 日开始计费后最该复算的一笔账。
- **参谋部短评**：价格战是真的，但落点在“成功请求”和反爬通过率上，实际单位成本要按自己的目标站点重算。值得继续盯的是 11 月 1 日计费切换后的真实账单。

### 4. Anthropic 承认九成代码由 Claude 写，于是给每个 PR 配了个 AI 评审

- **来源**：Reddit r/ClaudeCode
- **一句话人话版**：官方博客公开了 Claude Code 团队的新评审流程：代码九成由模型写，于是每个 PR 加一个 AI 评审，并给评审轮次设硬上限。
- **新闻/帖子本身**：官方给出的数字是：带真实评审意见的 PR 比例从 16% 升到 54%，需要五轮以上评审的 PR 从 8.9% 降到 1.5%；文档这类低风险改动在自动检查和安全检查通过后可无人批准直接合并。但规则同时写明，agent 的 approve 永远不算人的 approve，只要你下过 prompt，你就算这个 PR 的评审人之一。评审轮次超过三轮就让作者停下来重想方案，起因是曾有一个 PR 一夜跑了五十多轮。可直接抄的部分是开 PR 前先跑代码评审与安全检查、维护一份记录反复出现问题的评审清单。
- **社区原话摘录**：
  - Reddit 评论者（84 赞）："I just have a review skill that maintains itself. … It got to the point where it catches almost everything before it gets to me." —— 把评审规则做成会自我更新的资产，用定时回扫自己被纠正过的地方写回技能，比手工维护文档更省事。
  - Reddit 评论者（8 赞）："80% of the time I find issues I have to get fixed before I can accept it. And that's already with tdd, adversarial review, mutation tests, fuzzing and a dst and chaos harness." —— 反方最有力的一条：铺了 TDD、对抗式评审、变异测试、模糊测试和混沌测试，仍有八成产出需要人修；他补充说多数问题源自目标文档写得含糊。
  - Reddit 评论者（2 赞）："if a fix fails twice, the agent stops patching and rereads the whole thing from the top. Two misses usually mean its picture of the code is wrong, not the line it keeps editing." —— 把三轮上限讲成了机制而不是口号：两次修不好说明模型对代码的心智模型错了，继续打补丁只是烧 token。
- **参谋部短评**：官方的数字好看，但社区那条“八成仍需人修”是针对另一套配置的实测，两者不构成直接反驳。争议点在于 AI 评审能不能替代人的判断，而不是能不能提效。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1x7palj/

### 5. 上线前先考你一遍 AI 写的代码，HN 评论区几乎一边倒不买账

- **来源**：HackerNews（238 分、81 条评论）
- **一句话人话版**：有人做了个工具，在代码推上生产前弹问卷考你是否真懂这段 AI 写的代码，HN 的反应基本是嘲讽。
- **新闻/帖子本身**：作者把 hook 插进现有编码 agent 工作流，每次 push 前弹一份问卷，检查你是否理解即将上线的代码。动机很真诚：大家一边推 AI 生成的代码，一边心里发虚，怀念几个月前“大致还看得懂”的状态。但 HN 的反馈几乎一边倒，认为“加一道测验”解决不了理解力流失，只会增加一道形式主义关卡。唯一建设性的声音来自一位做过同类开源工具的人：他最后选择保持可选，而不是做成强制门禁。
- **社区原话摘录**：
  - HN 评论者（意译，抓住落地页标语）："'外包你的思考'——不好意思，你说什么？" —— 一个反理解力流失的工具用了“外包思考”当宣传语，被当场抓住，这条奠定了整栋楼的嘲讽基调。
  - HN 评论者（意译，最有说服力的反对）："我用 LLM 写码分两种：一种我在意，我会真读，逼它按我的心智模型来；另一种我只是要个差不多能用的方案，那我根本不读。这个 hook 要么问我早就知道的，要么问我根本不在乎的。" —— 把问题拆成两类任务，指出问卷对两头都无效，中间地带才是它想象的用户。
  - HN 评论者（意译）："我们从微观管理代码，进化到了微观管理工具和 markdown。" —— 一句话概括了这类“给 AI 工作流加流程”产品的通病：管理成本转移了，理解力没有回来。
  - HN 评论者（意译，反问）："你听过'悬崖底下的救护车'这个说法吗？" —— 意为一辈子在补下游的洞，暗示真正的解法是别让不懂的代码进流水线，而不是在上线口拦。
- **参谋部短评**：产品本身可能不成立，但它是“AI 代码审查疲劳”第一次被做成产品，HN 的集体反应比产品更有信息量：开发者不相信流程能换回理解力。
- **链接**：https://sphinx-six-theta.vercel.app/

## 今日舆情温度

- **最热争议**：今天的争吵几乎全落在“额度”这一个词上，但各方说的不是同一件事。Codex 用户在算每周能烧多少美元，Claude 用户在算一个号能活几天，DeepSeek 这边则在把搜索从免费推向按次计费。表面是三条不相干的新闻，底下是同一个问题：订阅制 AI 编程的真实计价单位已经变成“配额 + 重置节奏 + 风控存活期”，而这三样都由厂商单方面决定。V2EX 上那句“额度缩水，所以隔三差五重置，还让用户感恩戴德”之所以传播，是因为它说中了这种不对称。
- **最现实的吐槽**：最具体的一条不是骂价格，而是算账方式变了。有人指出真正的成本大头不是输出而是重复读上下文——30 万 token 的会话每一步都在为这 30 万付费，所以压小上下文比降低思考档位有效得多；也有人实测 80 万 token 压到 3 万到 5 万几乎等于清空，能指定保留什么，但“你不知道自己不知道什么”才是致命处。再叠加缓存 TTL、fast 档双倍消耗这类隐性系数，用户对“我的钱花在哪”基本处于失明状态。
- **最值得继续观察**：第一是 OpenCode 披露的密钥事件，旧系统被未授权访问，部分用户存在 Console 里的第三方 API 密钥可能暴露，官方称影响 1.4% 的 Console 用户并已邮件通知，Anthropic 表示已撤销其认为受影响的密钥——只要在里面存过 key，吊销重建是当下最该做的事。第二是 agent 权限护栏，有数据库教授在播客里说 agent 建库分支的占比已从 30% 涨到 80%、"每个月都有个生产库被 agent 删掉的故事"，而他维护的项目发现超过六成开源数据库项目已有 agent 提交的代码。能力跑在权限模型前面，这个缺口本周还会继续出现。
