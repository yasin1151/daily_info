### Aaron Levie（Box CEO）——产出差距拉到历史最大

核心论点：**AI 采用率最广，但人与人之间的产出差距也是史上最大。** 两年前就算在最对齐的领域（编程），顶尖高手增益也就 30-50%，因为要大量时间擦模型的屁股、上下文太短做不了长任务、交互高度同步。现在模型能吃长得多的任务、harness 支持长任务作业、训练数据更好、还有多 agent 并行——**两年内上限从 30-50% 拉到 5-10 倍**。他说“这个距离只会继续拉大”。

**为什么值得看**：对工具选型的含义很直接——中间层不会收敛，“用真前沿”和“没跟上”差一个数量级。

### Unsupervised Learning — Ep 96：Nebius CTO 谈在被 AWS 叫醒之前跑赢超大规模厂商

**一句话总结：AI 云的护城河不是 GPU，是软件；而“推理优化”这件事，整个行业基本还没开始做。**

嘉宾是 Nebius CTO（Yandex 分拆出来的原班基础设施团队），主持 Jacob Efron（Redpoint）。

**几个信息密度最高的点：**

- **“Neo Cloud 这个词我恨透了。”** 起步时这么叫的只有五到七家，现在按宽泛定义三到五百家。Nebius 自我定位不是 Neo Cloud 而是“the AI Cloud”，下一个对手是 AWS 和 Google Cloud——“我们收入大概只有 AWS 的 1%，但我们在跑”。

- **软件才是护城河。** 2024 年负责 GPU 采购、自研机箱固件、建网络的团队只有 40-50 人，软件组织已经 200 人。产品假设是“同一个平台既能服务几万张 GPU 的互联集群，也能服务只跑半小时一张卡的自助客户”——把大规模算力当零售卖。

- **存储是被全行业低估的**。“两年前做网络存储我谈的是几百 MB 到几 GB 每秒；现在客户常规就在从单个共享文件系统拉 700 GB/s。”他承认两个判断失误：存储，以及单个客户的规模——“30 兆瓦，五年前能装几十万台服务器，现在有时候一个客户都不够。”

- **Disaggregated prefill/decode：都在谈，没人做对。** 原话是“我们处在一个所有人都在谈、没人正确实现的阶段”。难在运维和 SLA 承诺上；他们有给最挑剔客户的分离式部署在跑，但承认是“手工味很重”的方式。新架构（整机架超快互联）反而让一部分老问题在机架内自然消失。

- **最狠的一句：“作为一个行业，我们什么优化都没做（we didn't optimize shit）。”** 拿开源推理服务器直接跑新模型，结果大概率很平庸——不快也不便宜。95% 的客户跑的不是原版开源模型，都是改过/微调的；真正落地的场景是“窄域、专用 agent”——这时客户根本不在乎成本，**在乎结果的可预测性和拿到结果的实际秒数**。模型剪枝、选择性压缩“还有大量未被探索的潜力”。

- **瓶颈不是电、不是 GPU，是执行力。** 他列了一长串缺货（GPU、CPU、NVMe、变压器交期以年计、光模块、电工），然后说唯一真正的瓶颈是“把这堆问题同时装在一个脑子里并穿过去的能力”——“经验丰富的项目经理，是我职业生涯里见过最稀缺的岗位”。

- **超大规模厂商为什么没赢下这块：** 芯片短缺下得先喂自己的训练；给整个栈改造网络/存储以适配 AI workload 是巨额投资，得由足够大的业务 justify，而这块对 AWS 只是“几十亿美元级”的小生意。他预计芯片短缺结束（两到五年）后它们会全力进来，问题是“我们够不够快长到能跟它们平起平坐”。

- **他真正在看什么：** 不再关心模型更大更聪明，近期也看不到值得下注的新架构。他关注 agent 侧的“结果优化”——**按 outcome 计价的商业模式怎么成型**，以及 harness 按任务演化。他说现在有些 agent 跑好几分钟根本不打后端 LLM 请求，因为负载已经退回成代码、质量门和工具调用——**“这块才开始吃 CPU”**，这是他判断未来 AI 落地的关键。

- 另外解释收购 Tavoli（web search）的动机：search 和 sandbox 是长任务 agent 的基础积木，正在做“托管推理 + agentic 工具”的组合。

## 三、对自研引擎 / Agent 工具链的三点可行动含义

1. **验证层正在变成产品，而不是 prompt 技巧。** Vercel 把安全审计做成独立流水线，Sonar 在讲“每个 loop 都要独立验证”，而 Anthropic 那边每天三万次自动放行。两件事不矛盾——正因为放行量大，才必须有一条不依赖模型自觉的独立闸门。自研引擎该有的是这条闸门，不是更长的 reviewer prompt。

2. **“少验证”和“多验证”的分歧还没定论，别过早站队。** Thariq 说强模型终将自我正确，Nebius CTO 说模型压缩/窄域专用才是出路。共同点是：两者都假设**任务域收窄**。所以引擎设计应对“窄域专用 + 可预测结果”优化，而不是追求用通用大模型包打一切。

3. **瓶颈从模型侧转移到编排侧和 CPU 侧。** Nebius CTO 那句“agent 跑几分钟不打一次 LLM，负载退回成代码和工具”——意味着工具链的性能预算要重新算：不是 token 成本，是**工具调用、质量门、沙箱启动的延迟**。这也是 Nikunj 用 Codex + Claude Code 双跑找“热路径和延迟”的现实理由。
