### 1. PHP 两个未认证 RCE，补丁发了也升不上去
- **来源**：HackerNews（953 点 / 528 条评论）、V2EX
- **一句话人话版**：PHP 官方紧急发布补丁，修复两个未认证远程执行漏洞，影响 5.4 以来的所有版本；但补丁发布和升级这两条链路都出了问题。
- **新闻/帖子本身**：PHP 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 同日发布，修复两个关键 RCE。第一个是请求恰好落在 `memory_limit` 的边界、触发 OOM 时，PHP 留下半初始化的内部数据，之后又把这份数据当作合法数据使用；在 Apache mod_php 下，未认证请求在应用代码运行之前就能触发，默认配置即可 RCE，PHP-FPM 也能被利用。第二个是致命错误出现在错误时点，内部状态指向上一请求的内存，worker 复用后形成 UAF。影响范围是 PHP 5.4.0 及以上全部版本，CVSS 9.2（编号泄露时一度被传成 10.0）。发布过程同样失控：CVE 编号提前一天泄露，一份 PoC 视频被误发，有厂商在协调发布前六小时就推送了含修复的镜像。V2EX 当天的帖子则在质疑协同披露流程本身。
- **社区原话摘录**：
  - HN 评论者（运维视角）：「FML. Can't get in to update our servers because of MFA and our director, who gets the codes, isn't in」 —— 补丁发了也升不上去，最后卡在双因素认证和请假的主管身上，这是绝大多数真实事故的现场。
  - HN 评论者（托管 PHP 二十年）：「这是我第一次需要预防性下线服务器」 —— 半原话。做了二十年托管的人第一次主动关机，比任何 CVSS 分数都更能说明严重程度。
  - V2EX 13 楼（4 赞）：「一旦补丁发布，通过逆向和问题定位，会被几乎所有漏洞研究组织、黑灰产等等渠道获得具体的利用方法并扩散。这个时间大概在发布后 15 分钟左右」 —— 最实用的提醒：补丁一旦发布，攻防就立刻开始，防守窗口以分钟计，不是以天计。
  - V2EX 12 楼：「我们发现了漏洞，我们做好了补丁，我们发漏洞详情后你就会被打，所以我们要拖几个小时再把补丁丢出来」 —— 把官方公告的内在逻辑说破了，也是对“先通知时间、后给补丁”的质疑。
- **参谋部短评**：今天唯一横跨中英文社区、且评论全是一线处置细节的题。值得盯的不是漏洞本身，而是镜像滞后和“补丁发布即被逆向”这条时间线，运维清单得按小时排。
- **链接**：https://news.ycombinator.com/item?id=50180873 ｜ https://thephp.foundation/blog/2026/10/21/todays-php-security-release-and-how-were-strengthening-php-security/ ｜ https://www.v2ex.com/t/1250646

### 2. LiteLLM 装包即中后门：发布管道本身被打穿了
- **来源**：HackerNews（402 点 / 125 条评论）
- **一句话人话版**：PyPI 上 LiteLLM 1.107.0 的安装包被植入后门，一装上就在后台偷 SSH 私钥、云凭证和各家 AI 的 API key。
- **新闻/帖子本身**：1.107.0 的七个 wheel（Linux / macOS / Windows）全部被植入三个文件：`cook.pth` 加载窃密脚本，抓 SSH 私钥、云凭证、CI secret、AI 工具 token、浏览器密码，连 LiteLLM proxy 数据库里的各厂商 key 一起加密外传；`sitecustomize.py` 启动一个后台守护进程，每小时从 GitHub 上的文件读取服务器地址，再下载并执行。因为走 `.pth`，任何 Python 进程启动都会触发，哪怕从不 import litellm。上游 GitHub 里没有这些文件，唯一痕迹是 sdist 的 `pyproject.toml` 多了一行 `data = "cook"`。安全公司判断，这是私有发布流水线用被改过的源码构建，中高置信度。这是同一项目年内的第二次投毒。
- **社区原话摘录**：
  - HN 评论者：「uv/npm 的默认应该带 24–48 小时 cooldown，装更新的版本应该是个需要刻意为之的操作」 —— 把防线前移到“延迟升级”，用时间换社区先踩雷，代价是永远慢一拍。
  - HN 评论者（引官方 issue）：「企业客户有私有 registry 在发禁运版补丁，还有一个 10/27 才披露的漏洞——不付钱的人就等着中招，这个 optics 很难看」 —— 吐槽披露策略被商业化：付钱的人先拿到补丁，开源用户留在窗口里。
  - HN 评论者：「sandbox 规则和权限弹窗都挡不住，人已经疲劳了，brew 说 59 个包过期就升，agent 时代只会更快」 —— 这段说的是供应链防线的真实状态：不是技术不够，是没人再逐条读 diff 了。
- **参谋部短评**：LiteLLM 是 AI 应用的标准中间层，凭证面极大。值得盯的是“没有 provenance 就查不出来”这一点，以及 agent 自动升级会不会把这个暴露窗口压到接近零。
- **链接**：https://news.ycombinator.com/item?id=50181114 ｜ https://safedep.io/litellm-pypi-compromise-credential-stealer-backdoor/

### 3. Claude Duet：会主动找你的 agent，争议卡在要不要给它密码库
- **来源**：HackerNews（279 点 / 231 条评论）
- **一句话人话版**：Anthropic 发布了一个不用你去找它、它每天早上主动来找你的个人 agent，能自己在云电脑上干活，付钱前要你点批准。
- **新闻/帖子本身**：研究预览，Opus 5.5 驱动，美国 Pro / Max 用户 waitlist，独立 iOS / Android 应用加 web。定位是主动型：每天早上给一份 brief，自己在云电脑上执行，遇到发消息、付钱这类敏感操作要人工批准（演示里一笔 640 美元的卫生许可费正在等 approve），接 6000 多个 connector，沿用已有的 memory 和 skills，一个线程走到底。官方 FAQ 也承认它会误判紧急程度、会漏掉两次检查之间进来的事。同一天它和 ChatGPT Dot 正面对打，评论区因此格外热闹：一边是全权托管派，一边是“这东西能碰我的密码吗”。
- **社区原话摘录**：
  - HN 评论者（58 条回复的根帖）：「过去一个月让 Dot 几乎全程代办买了辆车，现在正在京都买房，用我完全不会的语言，跟无数环节对接，没出岔子」 —— 全权托管派的极端样本，也是这个品类目前最有说服力的用户证言。
  - HN 评论者：「它接了 1Password。是我脱节了，还是把密码管理器交给 LLM 是馊主意之母？」 —— 质疑的落点很具体：不是能力不够，而是单一凭证库被 agent 接入后，一次误判就是全损。
  - HN 评论者（51 条回复）：「我理解 AI 的重要性，但我真的看腻了 HN 头版每天都是 LLM 公告」 —— 这条本身是舆情信号：产品节奏已经快到让核心读者产生注意力疲劳。
- **参谋部短评**：能力不是争议点，授权粒度才是。值得盯的是 approve 流程会不会被用户点成肌肉记忆，以及官方已经承认的“误判紧急程度”在真实付钱场景里怎么兜。
- **链接**：https://news.ycombinator.com/item?id=50186037 ｜ https://claude.com/product/claude-duet

### 4. Claude Code 里 compact 一次掉 11% 额度，一句活没干
- **来源**：Reddit r/ClaudeCode
- **一句话人话版**：一位 20 美元 Pro 用户按建议压缩会话，几秒后用量跳到 11%，什么都没做；跟帖给出了可执行的额度口径。
- **新闻/帖子本身**：楼主抱怨 5 小时窗口太紧：额度刚归零时按提示执行压缩，几秒后用量跳到 11%，一句活没干；被限流后让 Claude 继续，用量又瞬间从 0% 冲到 40%。35 赞的长回答给出一套口径：不要压缩，超过 400k 上下文就开新会话，并让模型写 handoff.md 记录进度；聊天缓存默认 1 小时、API 更短，隔一阵回到旧会话会重读全部上下文，可能一次吃掉 5 到 10 的窗口额度；中途换模型同样会重读全文。另一条补充更关键：每一轮都在重读整个会话，成本随上下文线性增长，不只是缓存过期时才算钱，他自己的日志里一步就背着约 390k token，所以在 150k 到 200k 之间交接比等到 400k 更省。
- **社区原话摘录**：
  - Reddit 评论者（35 赞）：「Chats have one hour cache (by default, API has less like a fourth of that or something).」并建议超 400k 就开新会话加 handoff.md —— 把额度问题拆成缓存 TTL 和上下文体积两个变量，是整串里最具操作性的一条。
  - Reddit 评论者：「every turn re-reads the whole session, so the cost grows with context size, not only when the cache expires」 —— 纠正了“缓存没过期就不花钱”的普遍误解，并给出 150k 到 200k 的交接阈值。
  - Reddit 评论者（6 赞）：「I get a lot done with the pro plan. I don't spin off lots of parallel agents.」 —— 反方经验：Pro 够用的前提是不开并行子代理，把额度问题还原成使用方式问题而不是套餐问题。
  - 同帖另一条高赞回答走更彻底的路：「never compact, split your project into checkpoints /clear after completing checkpoint」 —— 把会话当一次性工作单元，用里程碑而不是压缩管理上下文，代价是每次重开都要重建认知。
- **参谋部短评**：这条最能解释“续跑一下额度就没了”的体感，而且给了可执行阈值。值得盯的是压缩行为已经变过（现在会连带压掉此前累积结果），网上流传的老经验可能已经失效。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1xa7t5w/ ｜ https://www.reddit.com/r/ClaudeCode/comments/1x9a6kc/

### 5. 让 Codex 写个中等模块，它跑了 15 小时、写了 2 万行
- **来源**：V2EX
- **一句话人话版**：有人把功能和计划都沟通清楚后交给 Codex，它连续干 15 小时产出 2 万行，烧掉一个 20x 账号的 7 周额度，楼主说不敢合并。
- **新闻/帖子本身**：楼主说需求边界和开发计划事先都对齐了，Codex 连续工作约 15 小时、写了 2 万行代码，耗掉一整个 20x 账号的 7 周额度，结论是“我是真不敢合并啊，2 万行 review 都得一星期”。评论区迅速分成两派：一派认为模型有强迫症式的过度设计倾向，一派反问提示词和约束是谁给的，认为收敛是操作者的工程责任。整串最有价值的部分不是谁对，而是两派各自给出了可复用的做法：一边是“把代码砍到 2000 行但测试必须全绿”的硬约束，一边是“你自己没限制好怪谁”的责任划分。
- **社区原话摘录**：
  - V2EX 19 楼（5 赞）：「让它煮鸡蛋，它可以把消防车喊到楼下，厨房配备全套灭火装备，依旧还没开始煮鸡蛋。」 —— 今年最好用的 agent 过度设计比喻，一句话说清了“基础设施齐备但目标没动”的失败模式。
  - V2EX 14 楼（4 赞）：「你不发提示词和上下文，我很难为你发声啊。你说你指挥了，但他落实得有偏差我还能帮你说一下，你自己没限制好怪谁？」 —— 反驳派核心：agent 的收敛是操作者的工程责任，不是模型缺陷。
  - V2EX 1 楼：「感觉这个模型有点心理疾病，过度强迫症和疑神疑鬼，一般这个时候我会让他‘将代码缩减到 2000 行，但保持所有单元测试通过’。」 —— 可直接抄的收敛话术：用行数上限加压测全绿同时约束，比笼统说“简单点”有效。
- **参谋部短评**：争议不在模型强弱，在无人值守的默认行为。值得盯的是“长时任务 + 大额度账号”这个组合——产出量已经不是瓶颈，review 成本才是。

## 今日舆情温度

- **最热争议**：PHP 那两条 953 点和 220 点的帖子连起来看，吵的是“AI 该记多少功”。一边是官方把漏洞发现归功于 agent 规模化扫洞，并宣布向防御方投入大量 token；另一边是参与方自己的复盘写明：没有特殊 harness，也没用未公开模型，靠的是研究者对 PHP 漏洞史的了解——2004 年那篇关于 memory-limit 的旧研究就是线索来源。HN 的共识是归因有问题，V2EX 则盯着“为什么先通知时间、后给补丁”。两条线指向同一件事：披露节奏被加速了，协调机制没跟上。
- **最现实的吐槽**：额度。Claude Code 用户压缩一次掉 11%、每一轮重读整个会话；V2EX 上 15 小时 2 万行烧掉一个 20x 账号的 7 周额度；Cloudflare Workers 在小流量下极便宜、请求量一上来就是天价账单。共同点是“看不见的计量”——用户能感知的只有额度突然归零，看不到钱具体花在哪一步，于是所有解释都靠猜。
- **最值得继续观察**：agent 的凭证与权限边界。今天有三条独立线索指向同一处：LiteLLM 的发布管道被打穿，偷的正是 AI 工具 token 和 proxy 里的各厂商 key；Railway 承认客户环境变量可能已被解密，要求全员轮换；Reddit 上有人复盘子代理从没读过 .env，却用 grep 把整行键值带回聊天记录，而写在规则文件里的禁令根本命中不了 grep。共识正在形成：围栏要架在工具输出和挂载层，不在提示词里。

## 可以跳过

- GitHub 趋势榜首那批“给 agent 加约束、加记忆、降 token”的项目，star 涨幅很猛，但只有 README 自述，没有开发者评价和使用反馈。
- 几篇关于“LLM 能不能学到程序这一层”的理论讨论，质量不差但全是立场加类比、没有实验，赞数也无法反映真实热度，更适合当背景观点。
- 引擎社区今天的热帖集中在插件授权争议和启动器升级事故，与 AI、工具链舆情关系不大。
- 各类“AI 让某个岗位完了”的框架帖，今天没有新事实，只有立场复述。
