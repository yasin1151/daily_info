## 1. 让 Claude Code 连数据库的注意下：curl 把密码从 ps 里藏了，外面那层 shell 没藏

楼主自查了本机 253 个 Claude Code 会话，发现 16 个出现过 `mysql -p 密码`、`curl -u user:pass` 这类明文写法。复现后关键发现是：curl 自己会把 argv 里的密码抹成空格，但 Claude Code 是用 `zsh -c "source 快照 && eval '你的命令'"` 包了一层复合命令，shell 必须留着等子进程结束，于是带密码的完整命令行一直挂在 `ps` 里；同时命令原样写进 `~/.claude/projects/*.jsonl`。Linux 默认挂载参数下 `/proc/pid/cmdline` 同机用户可读，跳板机和共用开发机尤其危险。

- **4 楼 czjhar（未显示点赞）**：补充得很实在——"不光 curl，很多 CLI 把密码放进 argv 都会进 ps"，更稳的是启动后立刻 unset 的环境变量、本地 socket，或权限 600 的配置文件；外层再套一层 `bash -c` 照样会被看到。
- **1 楼 coolcoffee（未显示点赞）**：用 Go 写了个 MCP 给 AI 用，但读写都要 AI 先把语句交人工执行——"让 ai 去随意读写出事是迟早的"。
- **5 楼 JasonYip（未显示点赞）**：要么在 agent 前面包一层 MCP 或 CLI，永远不允许 agent 直接连任何中间件。

值得关注：这不是提示词问题，是进程模型问题。curl 的自我保护被外层的 shell 包装抵消掉了，而会话记录还会把密钥再存一份。楼主给的自查正则只数命中数量、不打印内容，这个习惯本身值得抄。

## 4. Codex 的过度设计、防御性编程、测试狂魔有解法吗

楼主的需求很简单，但 Codex 硬生生拆成几个文件几百行；让它参考目标框架和代码结构也"听不懂"；改一行代码就生成一堆测试，最后"整个仓库测试代码比我业务代码还多"。这是今年 AI 编码最普遍的抱怨之一：不是不会写，是写得太多。

- **17 楼 hahiru（未显示点赞）**：贴出可直接抄的 `AGENTS.md` 硬约束——"每个功能按满足当前需求的最简单方式实现""单实现不写接口、不建工厂/提供者/路由器""没有消费者的代码不进仓库""发现'顺手能做'的功能，提出来，不要直接写"。他还交代上个版本因违反这些原则积了约 1/3 死代码。
- **15 楼 MarkLeeyun（未显示点赞）**：把"最小改动"写进项目规范，并要求"每次只给一个小任务，做完先 review 再继续"，另外让它先输出改动计划（改哪些文件、多少行），确认后再动手——"能挡掉大部分过度设计"。
- **10 楼 ericguo（❤1）**：唱反调的少数派——"这样的风格是对的，要适应 AI 的这种风格"。11 楼 gdm 补充了理由：AI 和人不一样，它需要这种设计来保证运行无误。

值得关注：讨论的重心已经从"怎么用提示词求它"转成"怎么用仓库级规范约束它"。另外第 16、20 楼直接给出"换 claude"的答案，第 19 楼则警告中转站用模型指纹测出 `opus5.5` 实际路由到 `haiku4.6`——工具选择已经和供应链可信度绑在一起。

## 5. 怎么让 AI 把页面设计美观好看的

开源抓包工具 Sniffy 的作者在做根证书安装向导，用 GPT 画图出了几版方案，但每一版都"太想突出"：标题、图标、按钮、内容区都想抢注意力，放进真实软件里不符合预期。换成 frontend-design、impeccable 这类设计 Skill 也没解决——"我觉得不好看"这句话，AI 理解不了。最后他自己手画草图定下"顶部选平台、左侧步骤、右侧截图"的布局，才接近预期。

- **1 楼 superdavidchuang（未显示点赞）**：点出根因——"好不好看是主观的，程序员做设计时没有词典去描述想要的 UI、达到什么样的 UX"，并建议对着竞品反着抄。
- **9 楼 qfdk（❤1）**：给出可执行流程：先让 AI 出几版不同风格，选定方向后拆组件，明确告诉它"A 版本的这个组件可取、B 版本的那个可取"，再合成一版。
- **10 楼 netdisco（❤1）**：只丢了 `mobbin.com` 一个链接——真实产品 UI 参考库，比让模型凭空想配色有效。

值得关注：瓶颈不在生成能力，在需求描述的精度和参考物的质量。第 13 楼 securityCoding 提名 stitch 做原型，第 14 楼 Jensond 的判断更冷静："tokens 上算，vibe 的设计成本远大于编码成本。"
