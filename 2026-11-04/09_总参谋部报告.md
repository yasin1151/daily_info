### 1. Postman 悄悄给 Claude Code 装了插件，还顺手改了其他 Agent 的行为

- **来源**：Hacker News（928 分、301 条评论）
- **一句话人话版**：用户升级 Postman 桌面版后，发现机器上多出插件、启动钩子和 Claude Code 插件，而 Postman 还想替用户信任自己写进去的启动项。
- **新闻/帖子本身**：一位用户检查 12.33.4 版 Postman 的安装结果，发现多了用户级 Postman 插件、启动指令钩子、远程 MCP 连接、Claude Code 插件，以及独立安装的 Postman CLI。随后 Codex 反复报 MCP 认证警告，还把 API 相关任务自动路由到 Postman 的 skills。举报者认为最严重的一点是安装程序试图自动信任自己写入的 startup hook：一个 API 客户端不该越过边界，去改用户其他 coding agent 的行为。评论区几乎一边倒。
- **社区原话摘录**：
  - HN 评论者：“Postman went from a great lightweight tool to a bloated up-selling mess.” —— 从顺手的轻工具变成臃肿的推销机器，这是评论区的共同基调。
  - HN 评论者：“从好工具变成近乎病毒只用了几年，居然还有人用”，并推荐了 Bruno —— 情绪很重，但指向的是安装器行为，不是功能本身。
  - HN 评论者：团队几年前就搬去 Bruno，“请求定义能进 git，但说实话这些工具现在都不太需要了” —— 说明替代方案早已存在，这次事件只是加速了迁移决定。
- **参谋部短评**：值得关注的不是 Postman 一家，而是 Agent 插件生态开始互相改行为：装了 A，B 的行为也会被改。这条信任边界由谁来划定，目前没有人回答。

### 2. “直接改模型权重修好 Qwen”刷屏之后，被逐条拆解

- **来源**：Hacker News（860 分、189 条评论）、技术博客、AI 早报
- **一句话人话版**：一篇称模型不看数据、直接改权重就把 Qwen 数学能力修好的帖子刷屏，随后有人指出实验条件和摘要说的并不是一回事。
- **新闻/帖子本身**：研究者的做法是让模型在 Python 环境里加载 Qwen3.5-0.8B 权重，用练习题做最多 50 次前向测试，然后直接改参数，不用梯度也不碰评测集；只动 0.016% 的权重，MATH-500 就从 7.9% 升到 48.1%，GSM8K 从 13.8% 升到 67.1%，换成本来循环就少的 Gemma 3 270M，则没有效果。spaCy 作者 Matthew Honnibal 随后逐条拆解：摘要让人以为“只看裸权重”，但那个设定只出现在部分实验里，网络规模也只有 1.7 万到 17.2 万权重；而改进 Qwen 数学能力和游戏网络的部分，模型其实是在写 Python 程序、有工具和反馈。原帖在 HN 拿到 2921 分、879 条评论，是这两天最大的技术热点。
- **社区原话摘录**：
  - HN 评论者：“原文对自己做了什么、为什么这么做，讲得比这篇清楚，这篇没教给我任何新东西。” —— 认为批评文只是换个角度重述，没有提供新证据。
  - HN 评论者：反过来指批评者“同样不诚实”，理由是仅凭权重推断模型用途本身就是新出现的涌现能力，塞不进上下文只是工程限制 —— 这一派认为发现的意义不该被实验瑕疵抹掉。
  - HN 评论者（本地复现帖下）引《亨利四世》的台词：格伦道尔说自己能从深渊唤出精灵，霍茨波回“我也能，谁都能喊，但它们会应召而来吗” —— 能读出权重不等于读得对，这是全场最克制的判断。
- **参谋部短评**：这场争论本身比结论更有价值：两方争论的焦点都在怎么解读这件事，而不是事实本身。能力大概是真的，但“源代码时代结束”离证据还很远。

### 3. 让 Claude Code 连数据库的人注意：curl 把密码藏了，外层 shell 没藏

- **来源**：V2EX
- **一句话人话版**：有人自查本机 253 个 Claude Code 会话，发现 16 个把数据库密码明文写进命令，密码在 ps 里挂了整整几分钟。
- **新闻/帖子本身**：楼主统计了自己机器上的 253 个会话，其中 16 个出现过 `mysql -p 密码`、`curl -u user:pass` 这类写法。复现后发现关键点：curl 自己会把 argv 里的密码抹成空格，但 Claude Code 是用 `zsh -c "source 快照 && eval '你的命令'"` 包了一层复合命令，shell 必须留着完整命令行等子进程结束，于是带密码的整行一直挂在 ps 里；同时命令原样写进会话记录文件。Linux 默认挂载参数下，同机用户可读进程 cmdline，跳板机和共用开发机尤其危险。
- **社区原话摘录**：
  - V2EX 4 楼：“不光 curl，很多 CLI 把密码放进 argv 都会进 ps”，更稳的是启动后立刻 unset 的环境变量、本地 socket，或权限 600 的配置文件 —— 补充得很实在，把问题从单个工具扩大到一类做法。
  - V2EX 1 楼：自己写了个 MCP 给 AI 用，但读写都要 AI 先把语句交人工执行，“让 ai 去随意读写出事是迟早的” —— 这是运维岗的典型立场：可以辅助，不能放权。
  - V2EX 5 楼：要么在 agent 前面包一层 MCP 或 CLI，永远不允许 agent 直接连任何中间件 —— 直接给出边界方案，比讨论提示词有用。
- **参谋部短评**：这不是提示词问题，而是进程模型问题。Agent 工具默认把方便放在安全前面，这种“能用但会漏”的默认值值得每个团队排查一遍。
- **链接**：https://www.v2ex.com/t/1254223

### 5. 一天开 50 个 agent 线程，四个月后瓶颈反而变成了注意力，token 不再是主要瓶颈

- **来源**：r/ClaudeCode
- **一句话人话版**：一位把工作几乎全丢给 agent 的作者说，产出确实变多，但每周结束像开了一整周会。
- **新闻/帖子本身**：作者四个月里把大部分工作交给 agent，某些天同时跑 50 多个线程。问题在于每个线程迟早会回来找人：测这个、批那个、纠正那个、把那个转走，每一次都是一次上下文切换。他引用 BCG 三月对 1488 名美国员工的调查，称 14% 的 AI 使用者经历过所谓“AI brain fry”，重度监督 AI 的人报告精神疲劳高 12%、信息过载高 19%，并主动声明这是自陈数据、只有一轮，仅供参考。他正在做的改动是停止把线程数当目标，改做一个只显示“有多少决策在等我、每个项目朝哪走”的小面板。
- **社区原话摘录**：
  - Reddit 评论者（16 赞）：“stop building! Stop building 10 projects at once. Aim for 2 at maximum” —— 来自 LLM 研发团队的工程师，认为同时开十几个项目，一个月内必然透支，任何面板都救不了结构问题。
  - Reddit 评论者（7 赞）：“four months of nonstop work, have you shipped anything?” —— 最尖锐的质疑：持续加功能可能是多巴胺循环，用“一直在推进”替代“做完并交付”。
  - Reddit 评论者（3 赞）：把所有请求压成同一形状：做什么、为什么、具体改动、拒绝会怎样，批量审批才读得快 —— 可落地的降本手法，“拒绝会怎样”还能筛掉不需要人介入的请求。
- **参谋部短评**：并行 agent 的成本正从 token 转移到人的评审带宽，这是最容易被“吞吐量翻倍”的说法盖掉的一项。线程数不是产能指标。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1xh5cum/

## 今日舆情温度

- **最热争议**：权重空间编程究竟是能力突破还是叙事包装。反方抓住的是实验条件被摘要简化：说好“只看裸权重”，但实际改数学能力那部分用了工具和反馈；正方抓住的是能力本身可复现，本地 27B 模型也能读出权重含义，塞不进上下文只是工程限制。两边都有具体证据，也都在选择性强调；这类争论最后通常不是谁说服谁，而是等下一轮复现。
- **最现实的吐槽**：钱和额度。一边是 Plus 用户逐条算降智与额度合并，讨论升级、拼车、多账号轮换；另一边是 Claude Code 用户把周额度按 token 类型拆成换算表，发现真正烧钱的是冷缓存——子代理默认 5 分钟缓存，跑个长测试就整段重写。订阅制下，用户已经开始自己给算力做配给。
- **最值得继续观察**：Agent 的权限与转售边界。Postman 安装器试图自动信任自己写入的启动钩子，让一个工具越界去改另一个工具；同时 Anthropic 新版使用政策明确自 11 月 12 日起禁止未经授权转售或代理 Claude，靠“订阅转 API”做中间层的服务从灰色变成明文违规。两条线指向同一个问题：Agent 时代的访问权到底归谁。
