### 1. 消费级显卡跑 125B 大模型：Strata 让"必须上云"的假设松动了
- **来源**：HackerNews
- **一句话人话版**：一个开源项目把 125B 参数的 Qwen3.8-Flash-Next 塞进普通游戏 PC，有人实测比宣传还快，也有人怀疑数字有水分。
- **新闻/帖子本身**：开源项目 Strata 宣称让 125B 参数的 Qwen3.8-Flash-Next 在本机跑起来，NVIDIA/AMD 均可，12GB 显存起步，MoE 版本宣称 8GB+ 也能跑，全程本地推理、数据不出机器。发到 HackerNews 后拿到 550 赞、269 条评论，是当天技术区最热的一条。讨论焦点很快从"能不能跑"转向"跑得多快、代价是什么"：有人贴出 4090 上的实测速度，有人提醒这类 README 多是 AI 生成、数字要警惕，也有人质疑它是不是偷偷压低了 KV cache 精度来换速度。
- **社区原话摘录**：
  - HN 评论者（4090 实测）：“On my machine (Nvidia 4090, 128GB DDR5, Ryzen 7950x3d) I'm getting 124 tokens per sec” —— 4090 实测 124 tok/s，比宣传还快，是支持派最硬的一条证据。
  - HN 评论者（质疑者）：“Is these another one of those repos where it turns out that claude decided to quant the KV cache to q4 or smaller? The Readme doesn't say, but it's all AI generated” —— 提醒这类 AI 生成 README 的项目，速度数字可能来自偷偷降低 KV cache 精度。
  - HN 评论者（老卡用户）：“I've been playing with this on a 3090 and it FLIES... (php code base security audits)” —— 3090 这种老卡也能跑得飞起，还给出了实际用途（PHP 代码库安全审计）。
- **参谋部短评**：本地私有化大模型的门槛在肉眼可见地下降，但"AI 生成 README 加未说明的量化档位"是这类项目最常见的坑；关注点应该是它到底牺牲了什么精度，而不是单看 tok/s。
- **链接**：https://github.com/Niko1221/Strata

### 3. AI 大厂集体开始"做减法"：Claude 把 Cowork 和聊天合成一个入口
- **来源**：Claude 官方博客、X
- **一句话人话版**：Anthropic 把 Cowork（大任务）和聊天、Design 合并成一个 Claude，不再让用户自己选入口；同期 OpenAI、Meta 的人也在讲同一件事——功能堆太多，用户累了。
- **新闻/帖子本身**：Anthropic 公告将 Cowork 与聊天、Design 不再分区，Claude 自动判断任务需要什么，同时上线 Claude Docs 和 Claude Slides（beta），可在对话里直接写文档、生成幻灯片并导出 PPT/PDF，未来数周在 Pro/Max 先灰度。官方原话是，两个都用过的人说最烦的是要决定任务归哪边，所以他们决定不让用户再选。同一时间，OpenAI Codex 负责人、Meta AI 高级总监在 X 上给出同一诊断：产品复杂度被丢给了用户，采用率上不去是产品问题，不是模型问题。
- **社区原话摘录**：
  - Claude 官方博客：“People used both, and told us the frustrating part was deciding where a task belonged... So we stopped making you choose.” —— 官方直接承认分区是用户负担，改为由模型自己路由。
  - X OpenAI Codex 负责人（6762 赞）：“Only things being worked on are simplifications, more efficiency for more usage, groundbreaking features or new models... feedback is clear that you all want things to get simpler.” —— 竞争对手同期也在做减法，说明这是行业级共识，而不是单家策略。
  - X Meta AI 高级总监：“100 个拉杆的飞机驾驶舱” —— 把 AI 产品的连接器、权限、模型选择、token 用量比作驾驶舱里的上百个拉杆，认为采用率低是产品问题而非模型问题。
- **参谋部短评**：入口收敛、由模型自己路由，是 agent 工具链接下来一段时间最确定的产品方向；值得盯的是"合并之后额度与配额怎么算"，那才是用户真正的敏感点。
- **链接**：https://claude.com/blog/cowork-is-now-claude

### 5. 大模型对 Vue.js 的支持不如 React？评论区罕见地形成了共识
- **来源**：V2EX
- **一句话人话版**：楼主一句引战帖，结果评论区没吵起来，反而一致同意：不是玄学，是训练语料加语法结构的问题。
- **新闻/帖子本身**：楼主发帖质疑"大模型是不是对 Vue.js 的支持不如 React"，还半开玩笑地归因于"估计不是亲生的"。评论区没有按惯例分成两派互喷，而是罕见地给了同一个技术解释：React 语料多，ui=f(state) 是纯 JS 函数、对 LLM 友好；Vue 的 .vue 三段式与 .value 模板语法让模型多一层理解负担。讨论还延伸到"AI 时代选框架"——当 AI 更懂某一个框架时，会不会形成马太效应，让开发者进一步向它集中。
- **社区原话摘录**：
  - V2EX 9 楼（2 赞）：“AI 出现之前大家还会争论 React 还是 Vue；有了 AI 之后基本都转向 React 了……AI 更懂 React，进而形成良性循环。” —— 点出 AI 正在从辅助工具变成影响框架选型的力量。
  - V2EX 12 楼（2 赞）：“vue 是给人写的，封装了很多反程序设计（A 可以直接到 C，但 vue 设计成 A 先到 B 再到 C）……最典型的就是 .value，AI 也经常犯。” —— 从语法结构层面解释为什么模型容易在 Vue 上出错，是这帖最有信息量的一条。
- **参谋部短评**："AI 更懂哪个框架"已经开始反向影响技术选型，这对以 AI 辅助为主的团队是真实变量；长期看会继续加固 React 的生态优势，值得留意。
- **链接**：https://www.v2ex.com/t/1246345

## 今日舆情温度

- **最热争议**：Opus 5.5 到底有没有被削弱。主流声音（全场最高赞）坚持"没削弱、都是社区情绪"，理由是模型本身就非确定性、拿单次体验当证据不成立；但少数做研究和数据科学的用户给了具体反例，说"读文档、逐主题输出"这类初始 prompt 的质量明显下滑。折中的解释最有说服力：算力紧张下可能有调优，但远没有 Reddit 说的那么严重。每逢新模型发布都演一遍的周期性情绪，这次也不例外。
- **最现实的吐槽**：钱花了还是不够用。有人每月砸 400 美元订阅仍常年撞限速，想再加一档，被社区用"我 Max×5 全天多会话都够用"直接反证——问题在用法不在额度；另一头是开发者在抱怨"代理给自己堆过程债"，改一个电机常数要走七步流程、光规划就烧掉三分之一额度。额度与 token 税是今天最集中的两类抱怨。
- **最值得继续观察**：AI 大厂集体转向"做减法"。Anthropic 合并入口、OpenAI Codex 明确只做四件事、Meta 的人把现在的 AI 产品比作上百个拉杆的驾驶舱——三家口径一致地承认功能堆叠让用户累了。接下来要看的是：入口合并之后配额与计费怎么变，以及"由模型自己路由"会不会带来新的不可控感。
