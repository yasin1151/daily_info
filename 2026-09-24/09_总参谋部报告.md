### 1. Opus 5.5 的账本之争：官方说省 65%，实测说 32 分钟吃掉 18% 额度

- **来源**：V2EX、Reddit r/ClaudeCode
- **一句话人话版**：新旗舰发布第二天，围绕"到底省不省钱"的争论盖过了所有跑分讨论。
- **新闻/帖子本身**：Anthropic 发布 Opus 5.5 后，V2EX 上出现当天的实测帖：有人贴出官方口径的逐项对比，也有人给出自己的真实消耗。与此同时 Reddit 上出现一条专门算 token 账的帖子，指出真正的变化不是单价——输出单价比上一代只便宜约 20%——而是完成任务所需的 token 与轮次更少，官方数据里最低 effort 档的错误捕获率 72% 已经高于旧模型最高档的 56%。同一天 OpenAI 把 GPT-6 Sol 与 Luna 的 API 价格再度砍半，两家一起把 agent 的 token 成本曲线往下推了一档。争论的落点是：如果新模型的地板高过旧模型的天花板，很多人搭的"便宜模型干简单活、贵模型干难活"的路由分层就会失效。
- **社区原话摘录**：
  - V2EX 13 楼（未显示点赞）："审查一个模块用了 32 分钟，用去 cursor ultra other models 18% api 额度。" —— 实测派的冷水：降价的百分比好看，真实任务里额度依然是硬约束。
  - V2EX 18 楼（楼主，未显示点赞）：贴出官方自己统计的对比——"每次请求成本 $0.264→$0.094（-65%）、每次提问 $5.30→$2.29（-57%），但每 100 次提问被用户打断次数从 5.0 升到 8.0"，且这一项官方自己标注为"更差" —— 省钱的代价可能落在体验上，这是官方数据里最容易被忽略的一行。
  - Reddit 评论者（快照无梯度）："Per-token price is absolutely a lever they can walk back once adoption settles… But tokens-per-task and turns-to-done is a property of the model, not the price sheet."（单价是厂商随时能收回的杠杆，但"每任务 token 数"和"几轮做完"是模型本身的属性，不在价目表上）—— 把争论拆成定价与效率两个独立变量，是这条帖里方法论最清晰的一条。
  - Reddit 评论者（快照无梯度）："If that holds in real work it quietly breaks the routing a lot of us set up."（如果这在真实工作里成立，它会悄无声息地毁掉我们很多人搭的路由分层）—— 说明模型换代会让任何固定的成本架构反复失效。
- **参谋部短评**：值得继续盯。焦点是"单价"还是"每任务总成本"——前者是营销数字、后者才是账单；官方自己承认的打断率变差也需要后续验证。
- **链接**：https://www.v2ex.com/t/1244181 ；https://www.reddit.com/r/ClaudeCode/comments/1wo56ql/

### 2. 公司把 ChatGPT 从 Business 升到 Enterprise，额度反而两小时就跑完了

- **来源**：V2EX
- **一句话人话版**：有公司原用 Business 套餐，升级到 Enterprise 后每人每月只有约 20 美元额度，两小时跑完。
- **新闻/帖子本身**：楼主所在公司原用 ChatGPT Business（5 小时限额加周限额），切换 Enterprise 后变成每人每月 500 credits（约合 20 美元），用完要向管理员申请；他的 500 credits 在 Codex 和 Work 上不到两小时跑完，Usage 页显示 1001/1000、预计 40.06 / 40 美元。回复把换算讲清楚了：Enterprise 的 credits 就是按 API 原价折算，所以"升级"之后研发的实际可用额度可能只有原来的零头。凡是在做 AI 席位统一采购的人，都值得拿这条核一遍自己的账。
- **社区原话摘录**：
  - V2EX 13 楼（未显示点赞）："1 美元 = 25 credits，Codex 扣 credits 等同于按 API 原价付费，非常不划算"；并算出 Business 下上一代模型的 5 小时额度约 16-20 美元、周额度 100-120 美元，所以"公司升级之后，月额度只有之前的 5 小时额度了" —— 最完整的一张账单换算，直接推翻"升级"的直觉。
  - V2EX 11 楼（未显示点赞）：对接同事的口径是 1 credit 固定等于 0.04 美元，"500 credits 肯定不够，一个高级模型任务就花完"；他认为 Enterprise 主要是给需要数据隐私的企业，"人均 20 美元预算不该上这个" —— 指出卖点与需求错配，是本条最能落地的判断。
  - V2EX 1 楼（未显示点赞）："给研发的预算参考——一个月 200-300 美元 API 是底线。" —— 一句话给出行业内的预算经验值。
- **参谋部短评**：值得盯。企业采购把 API 原价包装成"credits"后，额度数字看起来大、实际很小，这类争议接下来很可能出现在更多公司的采购评审会上。
- **链接**：https://www.v2ex.com/t/1244246

### 3. 撞限之后它自己接着跑：一个默认打开的"静默扣费"

- **来源**：Reddit r/ClaudeCode
- **一句话人话版**：编码工具在额度恢复后会自动把任务接着跑完，代价是整段上下文重新写缓存、按 2 倍 token 计费。
- **新闻/帖子本身**：用户发现夜里撞到 5 小时限额后，工具在额度恢复时自动把任务接着跑完，于是发帖问这是不是新功能。评论区确认这是约一个月前加入的自动续跑，桌面版设置项在左下角。但重点迅速转向副作用：自动续跑会让整个上下文重新写一次缓存，而缓存写入按 2 倍 token 计费，50 万上下文等于白付约 100 万 token。已经有人因此吃亏：周日深夜跑任务、在午夜重置前撞限，醒来发现它已自动续跑，这一周额度还没开工就被吃掉一大块。
- **社区原话摘录**：
  - Reddit 评论者（快照无梯度）："It's dangerous though. If you let it auto continue you guarantee you re-cache the entire context. Cache writes cost 2x tokens. So if you have 500k in context, you pay 1 mill tokens for absolutely nothing."（这功能挺危险，让它自动续跑就会保证重写整个上下文缓存，而缓存写入按 2 倍计费，50 万上下文等于白付 100 万 token）—— 把"好用的功能"直接翻译成账单风险，是本帖信号最高的一条。
  - Reddit 评论者（快照无梯度）："Yeah, that hit me hard on Monday… it had auto-continued after the weekly reset. I lost a good chunk of this week's usage before I even started."（周一被这个坑惨了，它在周额度重置后自动续跑，我还没开工就损失了本周一大块额度）—— 真实事故复现，说明它与周重置叠加时损失最大。
  - Reddit 评论者（快照无梯度）："/config or /settings is always per-project. You have to edit ~/.claude/settings.json manually to have it apply globally."（设置是分项目生效的，想全局关闭只能手改配置文件）—— 直接给出可执行修复，避免用户以为关过一次就全局生效。
- **参谋部短评**：默认开启、极容易被忽略的扣费行为，长期跑夜间任务的人建议先确认这个开关。争议点是它到底算省心还是偷钱，取决于上下文有没有先压缩。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1wo5eaw/

### 5. "旗舰模型越来越不会说人话"：一场关于后训练对齐的争论

- **新闻/帖子本身**：楼主感觉最新旗舰比上一代更像人话，怀疑是不是错觉。讨论很快转到后训练目标上：在强化学习的跑分目标下，"说人话"是低效指标，模糊和婉转对 Agent 和 Coding 场景是噪声，反而降低统计意义上最优解的信噪比。回复里有人预测文学大模型与业务大模型未来会彻底分家，并点名了具体的开源写作模型。这类讨论比"哪个模型好用"更有信息量，因为它指向的是对齐目标本身。
- **社区原话摘录**：
  - V2EX 4 楼 / 6 楼（同一位用户，未显示点赞）："'人话'里包含太多模糊和婉转，而现实任务本质是定量的；对 Agent 场景，'讲人话'是噪声信息，降低了信噪比。" —— 本贴信息量最高的一条，把体感问题翻译成了训练目标的取舍。

- **参谋部短评**：这条的价值在于把"手感"变成了可讨论的工程问题。值得继续盯的是写作用途与 agent 用途会不会真的分成两条产品线。

## 今日舆情温度

- **最热争议**：今天吵得最凶的不是模型能力，而是"降价到底算不算真便宜"。有人贴官方数据说每次请求成本降 65%，同帖就有人回"审查一个模块用了 32 分钟，吃掉 18% 额度"；另一批人把争论拆成"单价"和"每任务 token 数"两个变量，并提醒单价是厂商随时能收回的杠杆，只有"几轮做完"是模型属性。这场争议之所以热，是因为它直接决定大家要不要重算成本架构——而模型每换代一次，任何固定的路由分层就会被推翻一次。

- **最现实的吐槽**：额度、账单和稳定性。企业采购方向出现了戏剧性一幕：从 Business 升到 Enterprise，研发人均额度反而只剩约 20 美元、两小时跑完；个人方向则是撞限后自动续跑，悄悄重写缓存，"周额度还没开工就被吃掉一大块"。稳定性方面，有人连续两天遇到"消息流中的错误"，从开发者工具里抓到统计上报接口反复超时，排除了自家网络的问题。一句话总结这轮吐槽：能力宣传越来越响，账单越来越难算。

- **最值得继续观察**：一是 agent 工具链开始出现"硬化"痕迹，有用户发现子代理被强制限制在 200 次工具调用后停止，而且只有 fork 出来的子代理带这个上限，恢复后的子代理容易抢进度、草率收尾；二是模型方的价格承诺能不能兑现，"永久降价"和"额度重置"这类承诺会在下一两个版本里被验证；三是 AI 做科学发现的数据来源争议，社区已经提前把训练数据与署名问题摆到台面上。
