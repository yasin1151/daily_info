## 9. 网站缓存排查实战：为什么清了所有缓存还是旧页面（4 回复）
🔗 https://www.v2ex.com/t/1245607

**摘要**：本期最硬的纯技术帖。结论：WordPress 挂了对象缓存 + CDN 之后，清缓存必须从最里层往外——先 Redis，再 Nginx FastCGI 整页缓存，最后 CDN；顺序反了等于白清。原因是任何两次清理之间都有窗口期，窗口期进来的请求会拿"还没清的那层"的旧数据把"刚清完的那层"重新填满。判断招数两个：`curl -sI` 看 cf-cache-status / x-cache 命中哪层；加随机参数对比（带参数新、不带旧 → 卡在 Nginx 或 CDN）。

**社区讨论**：
- **#1 bobox**："redis 缓存去掉就行了。没必要。" **#2 abigeater** 附议"Nginx/Redis 选一层去掉就好"——两位都在劝减层。
- **#3 CharlieLiu（楼主）回应**：留着 Redis 是替 MySQL 扛动态请求和后台查询；"真要精简，一般也是先摘它——全页缓存对访客的收益更直接。"
- **#4 UEFI**（质疑机制）："修改文章不应该主动刷新缓存吗？"并提出自己只留 CDN 缓存这一层。
