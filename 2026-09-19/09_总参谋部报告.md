### 1. 国产 AI 编程工具被逆向出来：登录后把你整个 Git 历史打包传走

- **来源**：HackerNews（242 分）＋ V2EX 同题跟帖
- **一句话人话版**：有人清磁盘时发现本地缓存占了 700MB，逆向一看，某国产 AI 编码客户端会把整个工作区打包加密直传云存储。
- **新闻/帖子本身**：发帖人清磁盘时发现该工具本地目录占了 700MB，追查后确认：登录状态下，这款国产 AI 编码桌面应用会把整个工作区打包上传，内容包括完整 `.git` 历史、LFS 缓存、reflog 和全局配置。他逆向安装包还原了链路：先向官方服务端申请云存储直传签名和本轮 RSA 公钥，本地 `tar.gz` 加 AES-256-CTR 加密、用 RSA-OAEP 包住密钥，再直传对象存储、绕过自家应用服务器。最讽刺的一点是私钥只在云端，本地那几百 MB 密文用户自己也解不开。V2EX 上有开发者做了几乎同样的逆向，还发现设置里两个相关开关即使显式关掉也不会被读取。厂商回应称问题出在"代码库索引"里的仓库文档上传、早期默认开启、云端生成后立即销毁。
- **社区原话摘录**：
  - HN 高赞评论者（242 分帖内）：“工业界在隐私上普遍随便，但这次跨过了另一条线：零提示、极度侵入、针对几乎必然是私有甚至禁止出境的数据、还没有明显开关——这就是恶意软件。” —— 这条把争议从"有没有遥测"抬到"这是不是恶意软件"的定性问题。
  - HN 评论者：“闭源 Agent 无论中国的还是美国的都是红旗。要用就用声誉好、用户多到有人会发现恶意代码的开源 harness，目前是 Opencode 和 Pi。” —— 代表"换工具"一派，把结论直接落到具体替代品。
  - V2EX 3 楼：“真的是垃圾国产，真不该相信。” —— 情绪化但真实，反映部分开发者对国产闭源工具信任度的直接崩塌。
  - V2EX 5 楼（3 赞）：“已经卸载了，怎么查？” —— 更务实的追问：事情曝光后，用户想知道自己机器上有没有留下痕迹、怎么自查。
- **参谋部短评**：重点不是"有没有遥测"，而是"设置里关掉也没用"。这类事会长期影响开发者对闭源编码 Agent 的信任，值得继续盯厂商后续怎么改、开关是否真的生效。

### 2. Claude Code 把「会话」这个概念删掉了：一个项目变成一群云端线程

- **来源**：X（Anthropic 一方四人同时发声）＋ 产品官方博客
- **一句话人话版**：Claude Code 的 Projects 被重构成"一个项目常驻一个 agent"，它自己把任务拆成多个云端线程并行跑，你关电脑任务还继续。
- **新闻/帖子本身**：这是 Claude Code 一次架构级动作。新的 Projects 不再是资料文件夹，而是持续对话：Claude 按目标拆任务、启动并协调多个并行云端线程，每个线程是独立的云会话，可以在各自分支写代码、跑测试、提 PR，并共享同一份记忆。目前 Pro/Max 公测，Team/Enterprise 尚未开放。官方同时承认一个关键缺口：线程在云端运行，电脑离线也继续跑，但暂时还不能访问你本地电脑或内网的文件与工具，本地支持"很快到"。Pro/Max 上已有的 Projects 照旧运行，随后逐步放量。
- **社区原话摘录**：
  - X 平台 Claude Code 负责人（2352 赞，中文转述，非逐字原话）：管理 session 这件事已经不再是他工作的一部分——想到什么就直接发过去，Claude 把它拆成 threads，而 project 记住了他的工作习惯；他说现在很大一部分编码都在这里完成。 —— 官方负责人用自己的工作方式背书新架构，是这轮发声里最重的一条。
  - X 平台 Claude Code 团队成员（1041 赞，半原话）：“比一堆 session 舒服得多。” —— 一句话点出架构本质：每个 project 一个 agent，管记忆、派生 subagents 执行任务。
  - X 平台 Anthropic 成员（356 赞，半原话）：她每天都在用，因为“可以在更高的抽象层操作”——一次抛出一批任务就去做别的，Claude 对所有事都有上下文，随时能给聚合状态更新。 —— 这条最贴近普通用户视角：卖点是省掉"盯着会话"的心力。
- **参谋部短评**：这是"多会话聊天"向"常驻 agent ＋ 记忆 ＋ 子任务编排"的正式转向。官方自认本地文件访问还没打通，这块空白既是第三方工具链的窗口，也是接下来几周最该盯的放量节奏。

- **一句话人话版**：有人本周只用两天就把 Claude 周额度烧光，另一头 Codex 第一次出现一个完整周期没重置额度，两边都在猜官方是扩产能还是限量。

### 5. 「不做逐字生成，只输出结构化决策」的模型，被开源小模型复刻了

- **来源**：HackerNews（528 分，今日榜首）＋ V2EX 两帖
- **一句话人话版**：一条不走 token 生成、直接给出选项概率的新路线，官方版还在造势，社区已经用浏览器里的小模型做了个仿制品，精度还糙但形态被验证了。
- **新闻/帖子本身**：先有 V2EX 两个帖子介绍一种放弃自回归逐字生成、只按预先定义的 Schema 返回类型化概率与评分的模型（例如 PASS 0.92 / FAIL 0.06 / NEEDS_REVIEW 0.02），称最高 250K tokens/s、1200 RPM、响应低至 70-500ms，定位是 Agent 任务路由、内容分类、自动审核、风控过滤这类高频判断。随后有人在 HackerNews 上发布了独立复刻版（与官方无关）：把"语义 if"搬进浏览器，不再让模型逐 token 生成 JSON，而是直接读它对几个选项的 choice logits 并归一化成概率，模型下载后完全本地推理，输入不出页面。评论区一半在质疑命名与归属，一半在贴实测错误案例。
- **社区原话摘录**：
  - HN 评论者（关于复刻版）：“它跟 Jev 团队没关系，只是用普通小模型去模仿 Jev 的行为。最小模型在我的 M2 Max 上跑一次要 0.5–2 秒，并不算快，而且蹭 Jev 这个名字法律上也说不清。” —— 同时质疑技术性能与项目命名，是这条帖里信息量最高的反对意见。
  - HN 评论者（实测不满）：“我出的题正确答案是第 1 项，它每次都选第 3 项，还标 80% 置信度。” —— 直接用一次失败演示说明：读 logits 得到的高置信度并不等于判断正确。
  - V2EX 2 楼（3 赞）：“需要自部署。” —— 四个字点出这类方案在企业落地的第一道门槛。
  - V2EX 1 楼：“难道说 Flink Agent 终于有可能的场景了吗？” —— 把新形态和对流式数据处理框架的想象连起来，反映开发者已经在琢磨它该放在哪一层。
- **参谋部短评**：Agent 架构里最贵的一环是"每一步都调大模型做判断"。如果"不聊天只决策"的形态成立，成本和延迟结构会被重写；但社区实测显示精度还很糙，现阶段更适合当作观察对象而不是生产选型。

## 今日舆情温度

- **最热争议**：隐私与信任。一边是国产编码工具被逆向出"关掉开关也照传"的完整链路，评论区直接把它定性成恶意软件、并顺势劝人换开源 harness；另一边是 Claude Code 与社区围绕"模型重要还是 harness 重要"继续吵——有开发者认为没有任何模型能仅靠提示词就稳定写好代码，正确做法是把信任从模型移到 harness 规则里，于是争论从"选哪个模型"变成"你怎么验证你的 harness 真的在起作用"。两条线指向同一个问题：当 agent 开始替你操作文件和承担判断，你到底信任谁、怎么验证。
- **最现实的吐槽**：额度与成本。Reddit 上有人两天烧光一周额度，评论区拆出两层原因：平台侧改动让消耗涨了四成以上，补偿机制加了又收回；使用侧则是"同一件事并行跑两个模型等于付两遍钱"，而且每轮都重发整段对话，长会话里改错别字和做深度推理单价一样。V2EX 那边有人两天用完周额度想升级，也有人翻出上月的重置异常。共同的抱怨不是"贵"，而是规则不透明、没人算得清。
- **最值得继续观察**：Claude Code 的云端线程群能不能真跑通。官方一边说线程可以并行写代码提 PR、关电脑也继续，一边承认还访问不了本地文件和内网工具。"云端编排 ＋ 本地能力后置"这个顺序会不会成为其他厂商的标准动作，以及本地能力什么时候补齐，直接决定 agentic 编码是留在玩具阶段还是进入日常工作流。另一个信号是"每步都调大模型"的成本模式是否会被"只决策不生成"的新形态挤掉一块。

## 可以跳过

- 多篇"某某 CEO／投资人发文表示"的内容：无论是要说软件产量超过史上总和，还是 agents 已占推理多数，都只有喊话没有评论区反馈，缺少现场感，更适合当背景观点而不是舆情。
- 面向家庭场景的 AI 助手发布：产品能力描述得挺细，但当天几乎没有真实用户帖和使用反馈，看不出可用性，只能算发布通告。
- 一批模型与产品更新速览：限时免费、桌面客户端上线、办公套件开放等，有信息量但这是商业动作，当天没有形成社区讨论或吐槽，读者直接看官方公告更准。
- 代码托管趋势榜的当日项目：只有 star 数和项目简介，没有维护者与使用者的真实评价，热闹程度与信息量不匹配，等有人真的用出问题再谈更有意义。
- 一篇"用数学省下大量内存"的工程复盘：写得漂亮，但讨论基本停留在实现细节和参数推导，离普通开发者的日常工作较远。
