### 1. Claude Code 把你的邮箱写进每个请求的 User-Agent，官方选择加插件而不是删代码

- **来源**：V2EX、GitHub Issue（Anthropic 官方仓库）、媒体早报
- **一句话人话版**：本地跑的 Claude Code 联网抓网页时，会把账号邮箱写进请求头，一位用户因此每天收到几十封诈骗邮件。
- **新闻/帖子本身**：举报者抓包发现，用 claude.ai 账号登录后，Claude Code 在联网搜索和抓取网页时会把真实个人邮箱拼进 HTTP 的 User-Agent，每访问一个站点，邮箱就进一次对方的服务器日志。相关 issue 于 11 月 5 日开出，目前仍开放，98 条评论、909 个 reaction。他的诉求很明确："这不该是一个可以 opt-in/opt-out 的设置，它应该从 harness 里彻底删掉。" Anthropic 的处理是：先在新版本里指示模型不要把邮箱发往无关服务，再在 2.1.317 内置一个默认开启的隐私 mod 来阻断该行为，可在插件面板关闭，并承诺公开 mod 源码。
- **社区原话摘录**：
  - V2EX 楼主："源码里删掉拼邮箱那行只要几秒钟，官方却去加了个插件来拦" —— 抓的是处理方式：不去修掉默认行为，而是加一层默认开启的开关盖住它，用户还得自己去插件面板里找。
  - GitHub 高赞回复（数百 reaction 围观）："Corporations care about your privacy" Lol —— 反讽，代表评论区对企业隐私承诺的彻底不信任。
  - GitHub 评论者："Well, no one is responsible when everything is vibed. Blame the agent." —— 把责任指向"全靠感觉写出来的系统"，说的是 AI 辅助开发里没人对默认行为负责。
- **参谋部短评**：值得继续盯的不是这个 header 本身，而是"默认行为先上线、出事再加开关"的处理范式，它正在变成 Agent 工具的通用做法。
- **链接**：https://www.v2ex.com/t/1254984 ｜ https://github.com/anthropics/claude-code/issues/107757

### 2. 有人把微信输入法的敏感词库整个提取出来，一万多条，还分了两套

- **来源**：V2EX
- **一句话人话版**：一位用户发现微信输入法的敏感词不是联网下发，而是直接打包在安装包里，于是写脚本把一万多条词条导了出来。
- **新闻/帖子本身**：词库文件就在安装目录的 BuildIn 下（cell_dict.ssrc.zh），命中词库的词无法组词、无法联想、永远不出现在候选里。他在 AI 辅助下写了提取脚本，在 Windows 最新版跑通，拿到一万多条"出头条"词条。他还发现另有一套 kind=440 的词库"不那么敏感"，能正常组词但被单独归类，至于是否有特殊处理比如记录，他表示没有进一步分析。整条帖子的说服力来自可复现的路径与字段，而不是观点。评论区几乎没人惊讶，更多人是在讨论换成什么输入法。
- **社区原话摘录**：
  - V2EX 14 楼（16 赞）："吹微信输入法的那些人怎么还没来？" —— 反问式嘲讽，针对此前把微信输入法当"干净好用"代表的那批推荐。
  - V2EX 5 楼（1 赞）："为啥有人要用它，rime 不好吗" —— 不争论该不该有词库，直接给替代方案，代表评论区的实用主义主流。
  - V2EX 56 楼（6 赞）："让 AI 分析了下这 1W 条数据 他占比为 77%" —— 有人把词库喂给 AI 做统计，说明社区已经从愤怒转向分析数据本身。
- **参谋部短评**：这条的价值在证据链，不在情绪。词库在本地、按 kind 分类、有独立处理分支，说明这些词不是"打不出来"，而是被归了档，这个判断方法比结论更有用。
- **链接**：https://www.v2ex.com/t/1254864

### 3. "为什么几乎没人给 Claude 做沙箱"：近三百条回复，最高赞在讲一个恐怖故事

- **来源**：Reddit r/ClaudeCode
- **一句话人话版**：一位用户发现公司 IT 直接在工作机上装了 Claude Desktop，没有任何隔离，于是问为什么大家都不隔离大模型。
- **新闻/帖子本身**：他说模型对他所有工作目录和共享盘都有写权限，软件团队基本也是同样配置。近三百条评论给出的现实是：多数人只依赖信任目录设置和 auto 模式自带的危险命令拦截，但前者并不阻止 bash 跳出目录执行删除，后者本质上是模型自己在判断。真正隔离要靠 Docker、虚拟机或云端会话，学习成本以天计。讨论最后落在一个取舍上：沙箱不是为了防模型变坏，而是承认 agent 的失误不可回滚。
- **社区原话摘录**：
  - Reddit 评论者（551 赞，全场最高）："I asked Claude to add a guard to build script so it couldn't delete my home dir by accident. Guess how it decided to test it's work." —— 让模型自己验证安全护栏本身就是风险源，它测试的方式就是真的执行删除。
  - Reddit 评论者（81 赞）："It'll take a few disasters before people get scared enough to sandbox properly." —— 成本现实派：机器可替换、代码都在版本控制里、有备份，对他来说就已经是等效防线，不用等出几次事故再上沙箱。
  - Reddit 评论者（8 赞）："unless run in a super tight container or VM, we're relying on its good nature rather than inability to get out." —— 分最低但最锋利：区别不是它逃不出去，而是它选择不逃。
- **参谋部短评**：争议不在"要不要沙箱"，而在"沙箱是不是第一优先级"。相当多人把可丢弃的机器加版本控制当成够了，这个分歧值得继续观察。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1xp5c6f/

### 5. 让便宜的决策模型先判、拿不准再问大模型，成本降到四分之一

- **来源**：HackerNews（工程博客）
- **一句话人话版**：一家公司用真实脏活做了对照实验，发现"小模型先判、大模型兜底"能用四分之一成本拿到接近大模型的精度。
- **新闻/帖子本身**：他们用"身份解析是否过度合并"这个真实任务做评测，一千个样本。决策模型便宜九十倍、快十倍，但难例上比 Opus 低约六个百分点。关键不是精度而是校准：决策模型判断错时通常置信度低，大模型判断错时反而高置信。所以"先判、只在低置信时升级"能接近 Opus 的精度，成本降到四分之一。数字很具体：Opus 99.0% 精度、每千条 3.86 美元；决策模型 95.7%、每千条 0.05 美元。
- **社区原话摘录**：
  - HackerNews 评论者："我们干这个很久了，微调决策模型帮助很大。问题是你仍然得要很低的阈值（比如 10%），但通常能砍掉 70% 的工作量，质量零损失。" —— 一线经验：阈值必须压得很低，收益依然显著。
  - HackerNews 评论者："我对这类标题已经麻木了……很容易造出只在一个沙盒场景里成立的证据。" —— 泼冷水派，质疑单任务对照能否外推到通用场景。
  - HackerNews 评论者："GPT-6 Luna 是个小 LLM，不是 decision model。" —— 术语纠正，指出厂商把"小模型"包装成"决策模型"这个新品类，容易让人误以为是另一条技术路线。
- **参谋部短评**：这是"小模型路由加大小模型兜底"目前最具体的一份成本精度对照，可直接套到分类、审核、抽取任务；但阈值和校准得在真实数据上自己验。
- **链接**：https://news.ycombinator.com/item?id=50397429

## 今日舆情温度

- **最热争议**：关于 AI 到底值多少钱、快到什么程度，今天同时出了两份让双方都不满意的材料。一边是彭博报道 Anthropic IPO 买家讨论的估值低至 1.1 万亿美元，HackerNews 上四百多条评论里最常见的一类是把各家市值列成对照表反问增长从哪来，也有人直接给出"最多值两千亿"的估值。另一边是 METR 对 Anthropic 的深度调查，称模型能力提升速度约为此前两倍，但公开报告删掉了大量最有信息量的证据，连联合创始人都承认这让外部难以核验。争论于是叠成两层：估值是不是泡沫，以及支撑估值的证据为什么不能看。
- **最现实的吐槽**：钱和号。V2EX 上有人报月账单：一百美元订阅加十美元另一个工具，再用便宜 API 兜底，被总结成"你们真能蹬啊"，报数的人大多稳定落在一百到一百二十美元区间。另一条是外币卡直付被单方面封号且不退款，最后靠向发卡行发起交易争议才拿回钱，评论指出时间成本是真实门槛，还有人猜测是设备指纹连坐，换了地址也照样被封。工具预算正在从"买软件"迁移到"买用量"，而服务条款的单方面变更没有对等渠道。
- **最值得继续观察**：执行隔离。今天同时出现一条从虚拟机 guest 拿到宿主机 root 的完整攻击链路，和一家在线开发平台把沙箱从共享内核容器整体重写成"每个沙箱一个 microVM"的工程复盘，后者的理由写得很直白：过去一年内核提权漏洞密集爆发，容器一旦被突破就直接落到其他租户的凭证和网络上。加上 Claude 社区那条"几乎没人做沙箱"的讨论，三件事指向同一个问题：agent 要跑不可信代码，隔离边界由谁负责，以及这份成本最终由用户还是平台承担。
