**OpenAI Codex & ChatGPT 负责人 Thibault Sottiaux：安全基建是下一个主战场**

他给出两个相当激进的判断。第一，"对几千万行代码做形式化证明"已经不再是荒谬的事，而是在设计新系统时应该纳入考虑范围的选项。第二，也是点赞更高的一条（3500+）："我可以很有把握地说，人类从来就不太擅长写安全的基建设施。终局会是所有人都用上超安全的基建和软件，但在到达那里之前我们要经历一段动荡。"

**前 Anthropic Claude Code 成员 Thariq：agent 的好用点是"基于位置的提醒"**

他分享了自己最喜欢的一类 agent（文中举例 Instinct）prompt："帮我记录上次洗衣服是什么时候。如果超过 5 天，就在工作日我到家 30 分钟后提醒我，并且一直催到我确认或者推迟为止。"这条拿了 2350 多赞，是当天互动量最高的一条 builder 内容。

值得关注：注意这个 prompt 的结构，它同时包含持久状态（上次时间）、条件判断（超过5天）、事件触发（到家后30分钟）、以及催办循环（直到确认）。这已经不是一个"问答"，而是一个常驻的、由环境和时间驱动的小程序。agent 工具链里最缺的恰恰是这类"状态 + 触发器"的原语。

**Vercel CEO Guillermo Rauch：agent 的杀手级应用是"随着时间为你做事"**

他的原话："Doing stuff for you over time 才是 agent 的杀手级应用。"举例是 Muse 和 Instinct 这类产品：夜里整理记忆，早上提醒你事情，在你和它上次交互过去 N 天后主动来消息。支撑这一切的是 Vercel Schedules："像打了兴奋剂的 Cron"，可以在运行时定义、无限扩展、并且跑在 Sandbox 之外，所以能按需低成本的调起算力。

同一天他还宣布 Grok 和 Cursor 可以直接在 Vercel 上构建、部署、扩展（"SpaceXSI 🤝 Vercel"），并画了一条闭环：订阅 X、用 agent 工具写、部署到 Vercel、在 X 上分发、用 X Money 变现，评论说"这个环快闭合了"。

值得关注：这和上一条 Thariq 说的是同一件事的两个层面。scheduler 正在从"运维组件"升级成"agent 的一等公民"，而且要求是运行时可定义、沙箱外执行、按调用计费。自研引擎如果还按"一次请求一次响应"来设计，会很难承接这类长驻任务。

**Box CEO Aaron Levie：企业里 agent 数量会是人的 100 倍，卡点在 context**

他的推演是：企业里将有 100 倍于员工数量的 agent 在数据系统上干活，而每一次部署的成败都取决于 agent 能不能拿到做决策、做研究、执行任务所需的关键 context。问题在于企业 90% 的数据是非结构化的，散在文档、合同、营销素材、研究资料、财务计划、设计文件里。因此 Box 与 NVIDIA 合作做混合检索，把词法搜索和语义搜索结合起来，同时保证遵守企业的安全、访问控制和数据治理策略，让 agent 只能碰它被允许碰的数据。

值得关注：这条把"RAG 不够用"讲得很具体，真正的门槛不是召回率，而是"混合召回 + 权限不越界"这两件事必须同时成立。做企业内部 agent 的话，权限模型应该和检索一起设计，而不是后接一层过滤。

**Unsupervised Learning Ep 97：JEV 创始人谈决策模型、benchmark 疲劳，以及为什么大厂错过了它**

核心观点：AI 的瓶颈不在智商而在可靠性。行业把模型压成单一维度的分数来比较，却没人对"这东西能不能在软件里稳定跑起来"负责。

JEV 创始人兼 CEO 在自家"系统一"决策模型发布约一个月后，给了一个不太客气的判断：人们已经不再关心新模型发布，因为被"跑分惊艳、上手拉胯"忽悠了太多次。他不认为这是市场问题，而是方法问题。做模型的人盯着任务的形状和榜单位置，一周能拼出一个 demo，但形状本身几乎不产生价值，真正难的是把抖动、失败模式和老实的可靠性讲清楚。他的北极星是让模型像 SQL 那样与供应商无关，由软件来调用它，而不是围着模型的怪脾气改代码。

对做 agent 工具链的人，最值钱的一段是他对 KV cache 的批评：几乎所有编码 agent 的产品设计都被这个只能追加的状态绑住，于是路由失效、子 agent 拿不到该拿的上下文、压缩只能靠猜，上下文越滚越大然后模型开始变笨。他还说，很多聪明算法之所以失败，是因为人们用 LLM 去做本该写在代码里的离散决策。另外几个硬判断：编码 agent 的真实提速大约 20% 到 40%；多模态会可测量地拉低智能，图像能力大约只有文本的十分之一；GPT-3.5 时代的智力其实早就够干大量"简单活"，只是没人认真去用。

说到 Anthropic 的估值，他的看法是：里面有一批预期不是基于产品层面的，而是基于对 AI 未来的误解，有人按"在建神"来定价，那这里就会有错配，"let them cure cancer 会变成玛丽·安托瓦内特的 let them eat cake"。

原话："任务的形状一点都不重要，真正重要的是它到底有没有用。"

值得关注：如果 KV cache 的"只能追加"真的是 agent 架构的天花板，那自研引擎里值得做的就不是再叠一层上下文压缩启发式，而是换一套状态管理，让路由、子 agent 上下文、压缩这三件事从同一个可枚举的状态里长出来。
