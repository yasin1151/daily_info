## 三、播客

**Training Data：Box 创始人兼 CEO Aaron Levie 谈「在 AI 时代重塑自己」与企业级 AI 扩散**

这一期信息密度很高，核心观点整理如下：

关于应用层 vs 模型层，他认为这两年市场已经把账算清了：模型和企业真实工作流之间存在巨大的鸿沟，无论是只押模型本身（long superintelligence），还是押应用层，都会在某个时刻收敛，当你把这道鸿沟填得足够深，你自然会有数据、有领域知识，然后自己去做模型，形成自己的飞轮。他用历史类比：AWS 创造了数万亿美元市值，但因为 AWS 而存在的软件同样创造数万亿美元，「如果你十年前看 AWS 在建什么，你绝不会预测到 Snowflake 或 Databricks 的存在」。他判断模型会极度值钱，但把模型带进银行、生命科学、医疗、政府工作流的软件，会是一个巨大的软件生意。他还补了一句反垄断视角的观察：如果一两家实验室拿走 95% 的价值，它们迟早会被国有化，所以它们自己其实也想要一个健康的竞争生态。

关于 token 补贴，他认为这是暂时现象：当这些公司上市，就会被资本主义同一套规则约束，数万亿资本规模已经超过了补贴能撑住的阈值，而且最终还是得为训练付费。他还指出一个有趣的多方博弈：Meta、SpaceX、中国、NVIDIA 这四类玩家并不需要按 Anthropic/OpenAI 的毛利结构在 inference 上赚钱，他们完全可以把推理压到 10% 毛利，只要换来巨额算力集群的买单。

关于开源权重，他的判断很精辟：采用率「比人们想的更高，比企业真正想要的更低，比五年后低得多」。他归因 30% 以上给「新鲜感」，并举了个很实在的反面例子：开源模型有时候 token 效率更低，甚至「会在链式推理中途突然说中文」，这在银行场景里就很尴尬。他引用 Decagon 的 Jesse 的说法：闭源继续指数增长，但每一个成熟的使用场景会被剥离到开源，只要满足两个条件之一，确实更便宜，或者做 post-training 能得到 x% 的性能提升。最终会形成混合形态：用 Fable 或 5.6 做编排，把长尾任务外包给便宜模型，或者反过来，默认用便宜模型，遇到真正难的再弹给重模型。结果是「两边花的钱可能各占 50%，但开源模型那边的 token 量是 10 倍」。

关于 Box 自己的 agent harness 和 eval，他讲得最具体。Box 有数百亿文件，每个文件都含关键企业信息，但企业基本不知道里面有什么。他们建的 harness 吃透了自己文件系统、权限结构、搜索引擎的领域知识，工具有拉全文、抽 chunk、动态做 embedding，能一次做多个搜索、重排、再读全文。他给出量化对比：相比直接把 Box API 交给外部模型，基于自己 harness 的准确率和延迟都明显更好。eval 上他们有两个：一个是公开的 complex work eval，覆盖生命科学、金融服务、公共部门、科技等领域的文档中心化任务；另一个是在 Box 自己的数据集上做 holdback eval。他能看到模型改进半点的变化，然后按成本和准确率阈值设默认模型，同时允许客户自选模型。谈到模型赛况，他的说法是「基本和 coding 表现高度相关，但有一个例外，某些用例里 Gemini 好得不成比例」，可能是工具使用能力和生态使然；Fable 5.1 是明确见过的 SOTA，而 Grok、Muse、Fable 这一档和下一代 GPT 现在是「完全的赛跑」。

关于系统记录（system of record）和 agent 的关系，他给 SaaS 公司的判断是「必须两件事都做，只做一件就会输」：一是造一个在你的产品上强 10 到 20 分的 agent，不是靠把外部 agent 打瘸，而是你自己 eval 拉满、深度调优；二是必须 headless，把 API 暴露给 Claude 和 ChatGPT 等平台，让外部 agent 能通过 MCP 或确定性 API 调用你。他举自己的例子：现在用 Salesforce 的频率比以前高了一个数量级，就是因为通过 Claude/ChatGPT MCP 进去问 CRM 数据。他还讲了一个客户给的灵感：一个后台 agent 持续监测文档是否满足公司治理政策、是否需要进入归档或 legal hold，等于让合规负责人「坐在每个员工旁边」。他甚至说，如果 LinkedIn 开放 MCP，他愿意付 10 倍价钱。

关于产品 UI，他认为通用 chat 会一直是标配，但企业的主体是后台流程，真正的形态是 dashboard、workflow、queue、task list，而不是聊天框。他的预测很尖锐：五年后企业 90% 的 token 是用户从未发起过的，用户只是看到一个任务出现，然后去 review。

关于为什么 AI 扩散比 coding 慢得多，他给了一个很值得记住的框架。coding 有五六个得天独厚的属性：代码的价值几乎 100% 由能生成的文本量代表；模型对代码是超量训练的；每个 AI 实验室都把 coding 当日常基准；受众是史上最技术化的人群，遇到 MCP 连接错误会自己去开端口而不是打 IT 电话；而且是极高薪的垂直领域。把其他知识工作按「像 coding 的程度」排个直方图，法律紧随其后，因为大量价值来自坐在电脑前审阅和撰写文档；而销售代表就在很靠后的位置，因为他的价值创造受制于客户是否回复、是否有预算、下周二能不能见面，这些外部限速因素 AI 无法消除。还有一个常被忽略的差异：coding agent 时代根本没有注册流程，你把 GitHub 给它就行，「知识工作里没有『给我你的 GitHub』这个东西」。他提醒硅谷要做好扩散比预期慢得多的准备，但这恰恰全是应用层的机会，是「万亿美元级别的应用层 AI 价值」。

关于持续学习（continual learning）和权重 vs 上下文，他说得很谨慎但很清醒。他认同这个方向，但指出真正的阻碍在企业侧不在研究侧：研究员容易假设世界像他一样，能访问一切，但律师的访问面只有手上那五个项目，隔壁同事在做竞争对手的项目，两边之间不能有任何一份文档流通，必须存在硬隔离。所以「权重里放什么、上下文里放什么」需要一个明确的决策标准，他想要一张 T 型对照表，核心变量是数据的变动频率和烘焙进权重带来的准确率增益之间的权衡。他认为最终会按垂直行业分化：像 Eli Lilly 做药物发现，没有隔离问题，他们就是想要一个「我们怎么做药物发现」的模型；而律所这类场景则完全不同。

关于公司内部怎么落地 AI，他给了几个实操：Box 二十年要求所有人只能用公司自己的系统，所以「任何被无序数据记录过的业务问题，100% 都能在系统里搜到」，这是他们能做 AI 优先的底层原因。他们不搞 token max，而是看员工 token 用量排行，发现前三名里可能一个在浪费一半 token，另外两个在干很牛的事，于是公司两周内把整个团队叫进一个房间，让那个人做完整 demo 分享。他们设了 AI 卓越中心和内部 AI 专职人员。他也坦承差距：有些部分的技术栈客户可见产品交付速度提升了 2 到 3 倍，但每次跟 Anthropic 的朋友聊完，还是觉得「我们还有很长的路要走」；而且因为客户把数据安全和合规托付给你，Box 不能删掉代码审查这些环节，「我们在生产力上永远会有一个折扣」。

关于给创业者的建议，他说自己既羡慕又不羡慕年轻创始人：羡慕的是现在两个人能做出五年前 40 人项目的东西；不羡慕的是「每一个好点子，立刻就有五个竞争对手」，他们当年有两年时间可以安静打磨产品。他的最终判断是，在 AI 能极快造东西的世界里，胜负手转移到「谁真能把东西送到客户手上」：应用层有万亿美元级别的东西可抢，会建团队、能触达企业的公司会赢。
