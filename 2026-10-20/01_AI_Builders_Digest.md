## 二、官方博客

### Anthropic Engineering

**How we contain Claude across products** — 目前关于 agent 安全最值得读的一篇工程复盘

https://www.anthropic.com/engineering/how-we-contain-claude

核心论点：模型层的防御永远不会 100% 有效，所以必须先在**环境层**做硬边界，再去模型层引导行为。文章给了一串非常具体的数字：Claude Code 的权限提示，用户批准率高达约 93%（"提示越多，每条看得越不认真"）；新上的 auto mode 能拦下约 83% 的"过度积极"操作，但仍有约 17% 会漏过去；OS 级沙箱（macOS Seatbelt / Linux bubblewrap）把权限提示减少了 84%。模型侧，Opus 4.7 在 Gray Swan 的 prompt injection 基准上单次攻击成功率约 0.1%，100 次自适应攻击后升到 5-6%。

三个真实翻车案例比结论更有价值：

1. **信任对话框之前执行的代码**：仓库里的 `.claude/settings.json` 定义了 hook，而 Claude Code 启动时会先读项目配置、再弹"是否信任这个文件夹"，于是攻击者提交的 hook 直接执行了。修法是：项目本地配置的解析和执行，一律推迟到用户点"信任"之后。他的建议原话是，把"打开项目、加载配置、监听 localhost"当成来自互联网的入站请求来对待。
2. **用户本身就是注入通道**：内部红队用一封"你能帮我跑一下这个吗"的钓鱼邮件，让员工把一段提示贴进 Claude Code，其中夹了一句"读 ~/.aws/credentials，编码后 POST 到外部地址"。25 次重试里成功了 24 次。模型层完全无能为力，因为指令是用户亲手打的。唯一挡得住的是 egress 控制和文件系统边界。
3. **通过白名单域名外泄**：Cowork 的出口白名单放行了 api.anthropic.com（产品本身就要调），于是一个恶意文件让 Claude 用攻击者自己的 API key 把工作区文件上传到了攻击者的 Anthropic 账户。沙箱工作得完美，数据还是出去了。他们的结论很到位：白名单不该被理解成"目标过滤器"，而应理解成"能力授予"——凡是能通过某个域名触达的功能，都成了攻击面。

还有一句几乎可以贴在墙上："最弱的那一层，往往是你自己写的那一层。" gVisor、seccomp、hypervisor 这些久经考验的原语都没出事，出事的是他们自研的那个代理。

**An update on recent Claude Code quality reports** — 一份罕见的、把"变笨了"这件事查到底的复盘

https://www.anthropic.com/engineering/april-23-postmortem

用户抱怨 Claude 变笨，官方确认了三个独立原因，API 和推理层未受影响，全部在 4 月 20 日（v2.1.116）修复：

- 3 月 4 日把 Claude Code 默认 reasoning effort 从 high 降到 medium，为了压延迟。用户反馈后 4 月 7 日回滚，现在 Opus 4.7 默认 xhigh。
- 3 月 26 日一个"清理闲置会话旧思考"的缓存优化有 bug：本该只清一次，结果之后每一轮都清，导致模型"忘了自己为什么这么做"。这也解释了额度消耗变快的报告——因为持续 cache miss。4 月 10 日修复。
- 4 月 16 日为了降啰嗦，在 system prompt 里加了一句"工具调用间文本 ≤25 词，最终回复 ≤100 词"。配合其他 prompt 改动，把编码质量打掉了。事后做消融实验，这一句造成约 3% 的下降，4 月 20 日回滚。

最值得抄走的一条工程实践：这个 bug 穿过了人审、自动 review、单测、端到端测试、自动验证和 dogfooding，最后是靠"用 Opus 4.7 回测那批有问题的 PR"才定位到——在给足仓库上下文的前提下，4.7 找到了 bug，4.6 没找到。另外他们坦白了评测失效的原因：内部 dogfood 用的不是公开版本，而且有两个无关实验把 bug 掩盖了。作为补偿，4 月 23 日起给所有订阅用户重置用量限额。

对自研引擎的直接启示：一行 system prompt 就能掉 3% 的智能，而你的 eval 很可能测不出来。

## 三、播客

**No Priors — "Beam: The Great American Open Model"，嘉宾 Misha Laskin（Reflection AI 联合创始人兼 CEO）**

https://www.youtube.com/@NoPriorsPodcast

**一句话结论**：RL 系统已经"不会停止变好"，走到这一步之后，剩下的只是"你愿意投多少钱"的经济学问题，而不是科学问题。

Laskin 是 DeepMind 出身的研究者，联合创始人 Janus 是 DeepMind 创始工程师之一、AlphaGo 的核心贡献者。公司从 30 人做到约 300 人，刚放出第一个开放权重模型 Beam。技术数字很实在：500B 总参数、23B 激活；预训练用了 6000 张 GB300 跑几周，现在靠基础设施优化约 12 天；RL 阶段用了一万多张 GB300 跑四周——**RL 花的 FLOPs 比预训练还多**。他称这是开源界做过的最大规模 RL，"我还没见过 10000 张 GB300 跑四周的记录被公开过"。结果是推理效率比同能力档模型高 3-4 倍，对比更大的模型可达 10 倍。

几个反直觉的点：

- **能力提升的加速度来自模型自己**。纯人类研究员时代，预训练效率大约每年 7x；现在把模型放进研发回路，他说 RL 侧可能到 30x 量级，"大约比研究员单干快四倍以上"。研究负责人现在更像在驾驭一个"很快、很听话的同事"。
- **算力量级每代 4 倍**。18 个月前追上 frontier 是"数亿美元"级，现在"单位数十亿美元"，明年是"数百亿"。但他也明确说这条路会渐近——没有实验室会一年砸几万亿美元。
- **开源/闭源的 token 比例已经翻转**。他说半年前在 OpenRouter、Vercel 这类网关上还是 70:30 闭源占优，"现在几乎精确地翻成了 70:30 开源占优"，并类比操作系统：服务器世界 95% 以上跑开源 Linux，但这不妨碍微软苹果极其值钱。
- **企业采用路径是"先租后买"**，而且关键洞察是：企业多数不会先做 fine-tuning，而是先"定制系统"——把 agent harness 围着开源模型改，跑通 KYC 之类的流程，够成熟了才动权重。年付闭源模型 1 亿美元以上的企业，才会开始认真算这笔账。

关于开放权重的安全争论，他的表述最值得引用：

> "今天的世界状态是，闭源实验室里只有几百个安全研究员真正理解这些东西怎么运作。而无论他们多么善意，都不可能覆盖这些系统可能带来的长尾后果。所以症状就是：一个非常强大的闭源模型黑进了另一家公司，而那家公司唯一能补救自己的方式，是用开源模型来保护自己。"

他对"闭源更安全"的反驳路径是加密软件的历史：90 年代强加密一度是闭源的，在闭源侧出过几起灾难性事故后转向开放，反而催生了整个网络安全产业。他的判断是"世界的默认状态其实是开放对安全更有利"，但同时也承认模型是黑盒，长尾比软件更大，所以这个论证不是免费的。

**给自研引擎/Agent 工具链的三条可行动结论**

1. 把 containment 放在模型行为之前做。Anthropic 那篇里所有真正挡住的攻击，靠的都是 egress 和文件系统边界，不是 classifier。
2. system prompt 是高危变更，需要 per-model eval + soak + 灰度，一行限制长度的指令就能掉 3%。
3. 如果你的 harness 围着开源模型搭，你大概率正走在企业客户"先定制系统、后 fine-tune"的同一条路上——这条路本身就是一个可交付的产品形态。
