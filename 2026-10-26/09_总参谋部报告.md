### 1. 一句"Codex 是不是越来越比不上 Claude"，把 V2EX 的不满全引出来了

- **来源**：V2EX 问与答（25 楼）
- **一句话人话版**：楼主只抛出一句疑问，25 层回复几乎一边倒批评 Codex，但没人真的卸载它。
- **新闻/帖子本身**：帖子本身没有任何论证，就是一句"有没有感觉 Codex 越来越比不上 Claude 了"。评论区把不满集中在两点：一是 opus-4.5 之后 Codex 的输出啰嗦、无效兜底、代码越改越散；二是即便承认它更弱，多数人仍然双持。原因高度一致——不是能力，而是担心 Claude 封号。也有人给出反向暴论：如果 Anthropic 不封号，涌进来的用户量会把 Opus 的额度摊薄到降智水平。整层楼没有人为 Codex 辩护，也没有人真的弃用，这种"边骂边用"的状态本身比结论更有信息量。
- **社区原话摘录**：
  - V2EX 4 楼："起码编程方面是 opus-4.5 一路用过来 gpt 从来没有能代替的时候，永远啰里八嗦、无效兜底、车轱辘话、分散的屎山代码往上糊。" —— 最激烈的差评，问题不在答不出，而在输出结构和代码组织，这是长期使用后的具体体感。
  - V2EX 8 楼："我之所以现在还在用 Codex 是因为 Claude 会封号。" —— 一句话点出真实留存原因：不是更强，而是更不容易失去账号。
  - V2EX 7 楼："从 opus5.5 发布到现在这段时间差距太明显了，基本上是不可用的状态。不过我说句暴论，要是 a 畜不封号，涌进来的用户量也会分分钟把 opus 降智到 luna 的水平。" —— 把"封号"重新解释成配额保护机制，说法很冲，但代表了一批人的真实推断。
- **参谋部短评**：这条记录的是切换成本已经不由模型能力决定。谁更强成了次要问题，账号风险反而成了竞争壁垒，也顺手替对手保护了算力配额。做工具选型时，可以把它当一份用户留存原因表看。
- **链接**：https://www.v2ex.com/t/1251671

### 2. 同时开十三个子代理做游戏，睡一觉醒来账号被封了

- **来源**：Reddit r/ClaudeCode（原帖 + 归档快照赞数）
- **一句话人话版**：有人用多代理流程给游戏做动画，并发一度开到十三个，第二天发现 Pro x20 账号被封。
- **新闻/帖子本身**：楼主在做一个小游戏，把搞不定的动画交给自动化流程处理，子代理一度开到十三个，然后去睡觉，醒来发现账号已被封禁。他怀疑是并发子代理触发风控。评论区把这件事扩大成一场对自动封禁系统的不信任：有人复现了同类封禁，最后靠让另一个模型读本机聊天日志才定位到触发点——游戏内的一句提示写的是"用这个法术伤害你自己"，正好落在用户福祉政策的判定范围。还有人卡在申诉环节：被停权的账号无法登录，也就无法提交申诉。楼主后续更新说账号已经恢复。
- **社区原话摘录**：
  - Reddit 评论者（53 赞）："Anthropic automatic ban system is total BS and somehow they don't care to fix it or remove." —— 把问题定性为系统性的自动封禁缺陷，而不是用户违规，这是整层楼最主要的情绪来源。
  - Reddit 评论者（52 赞）："use the spell to damage yourself" —— 复现者贴出的具体触发句，等于给出了政策误判的样本：风控按字面判定，不看这是游戏文案。
  - Reddit 评论者（30 赞）："support page is useless because it requires you to log in" —— 指出申诉死循环：被封就登不上，登不上就申诉不了，她的建议是尽早走信用卡拒付。
- **参谋部短评**：值得继续盯的不是个案，而是多代理长时间跑剧情、游戏类内容时会批量生成"攻击性语境"，而风控按文本判定。做内容生成类 agent 的团队应把这条当已知失效模式，提前准备日志和申诉材料。
- **链接**：https://www.reddit.com/r/ClaudeCode/comments/1xcnj51/

### 3. 十年前的 CNN 读皮肤镜照片，赢了两个前沿大模型 20 个百分点

- **来源**：HackerNews（370 分 / 182 评论）
- **一句话人话版**：一位皮肤科医生拿 2015 年的老架构和两个前沿模型比读皮肤镜照片，老模型准确率高出一大截。
- **新闻/帖子本身**：作者用公开数据集里 200 个经活检确认的病灶做六分类，包括 30 例黑色素瘤。基于 Inception v3 的 CNN 在单张 H100 上微调约 20 分钟，六分类准确率 62%；两个前沿模型都只有 42%。黑色素瘤单项是 27% / 37% / 43%，老模型并不占优，但整体差距依然明显。这个 CNN 还能整个跑在手机浏览器 WebGPU 里，图片不出设备。文章真正想说的不是"小模型更强"，而是专用模型加高质量标注、加明确任务边界，在垂直场景里依然能打败通用前沿模型，成本和隐私还更优。文中还给了一个直观反例：一个厚度不足 0.8mm 的早期黑色素瘤，两个模型都判成"脂溢性角化，可以出院"。
- **社区原话摘录**：
  - HN 评论者（机器学习工程师）："拿一个微调过的 CNN 和通用模型在这么小的数据集上比，这文章一点用都没有。" —— 方法学质疑：200 例样本、专用模型对通用模型，这个比较本身就不公平。
  - HN 评论者："问题是 LLM 就是一台万能盒子……一旦手里只有锤子，所有问题都变成钉子，你打不过'零投入、零学习、十秒出答案'。" —— 反方最有分量的一条：通用模型赢的不是准确率，而是接入成本。
  - 该帖的高信号发言高度集中在方法学之争，可读原话以这两条为代表，社区原话不足三条。
- **参谋部短评**：这场争论的价值不在"小模型打败大模型"，而在任务边界和标注质量被重新摆到台面上。做垂直 AI 产品的团队，先回答该不该用 LLM，再谈用哪个模型，比追榜单有用。
- **链接**：https://lynchlab.net/llm-skin-cancer

### 4. API 价格几个月砍掉八成，有人把降价时间线捋了一遍

- **来源**：HackerNews（58 分 / 79 评论）
- **一句话人话版**：一位开发者把 6 月到 9 月的降价事件按时间排开，结论不是厂商良心，而是模型已经商品化。
- **新闻/帖子本身**：文章统计的具体动作包括：某旗舰小模型一次降价 80% 到每百万 token 0.2 美元输入、1.2 美元输出；某中端模型的"临时低价"转为永久；某版本把缓存读价降了 75%，而对 agent 场景来说缓存读占 token 开销的 96% 到 99%，等于总成本降七成；另一家新旗舰直接给出 2/10/0.2 的定价，同一天还写明"所需算力更少，价格反映这一点"。作者引用的网关数据是：单位 token 成本已降到四月的 43.3%，但企业总支出仍在涨，因为模型变强的速度快于变便宜的速度。
- **社区原话摘录**：
  - HN 评论者："token 早晚会变成运营商流量套餐，早晚会有无限量。" —— 认为推理最终会走向包月制，价格战会以套餐形式收尾。
  - HN 评论者（反驳）："推理成本随用量线性增长，流量套餐的边际成本近似为零，两者不一样。" —— 直接指出类比失效：算力没有可复用的闲置带宽，包月在这个行业行不通。
  - HN 评论者："我们因为 OpenAI/Anthropic 的 cybersecurity 拦截，转去用了更便宜的 Kimi 和 GLM。" —— 现实注脚：安全策略会把客户推给竞品，降价不是影响选择的唯一变量。
- **参谋部短评**：这轮降价对成本敏感的团队是真实利好，尤其是缓存读价这一项。但"总支出还在涨"提醒得很到位：实际账单由能力升级和使用策略共同决定，只盯单价会算错。
- **链接**：https://minimaxir.com/2026/10/cheap-llms/

### 5. Epic 办了一场"鼓励用 AI"的 Game Jam，把自家开发者社区点着了

- **来源**：Reddit r/UnrealEngine（347 分 / 244 评论）
- **一句话人话版**：Epic 公布 AI MegaJam，宣传语直接写"Vibe your way to $50k"，规则鼓励使用任何 AI 工具。
- **新闻/帖子本身**：这场赛事的规则允许并鼓励使用任何 AI 工具，团队最多五人、代理数量不限。争议的直接起点是 Epic 最初把"必须使用 AI"写进规则，后来撤回改成可选。楼主是每年都参加 MegaJam 的 UE5 开发者，说看到公告时下巴差点掉地上。这是本周该版块最大的舆情事件：往届冠军公开表态抵制，而天天在工作中用 AI 的职业工程师则指出，问题不在 AI 本身，而在把 AI 当卖点、鼓励批量产出；真正该做的是把 AI 用在动作捕捉、材质提取这类辅助流程上。
- **社区原话摘录**：
  - Reddit 评论者（143 赞）："Honestly, Sweeney makes it really, really hard to keep using Unreal. I despise the man and what he stands for." —— 不满已经从一场活动上升到对决策层的不信任，甚至影响是否继续用这个引擎。
  - Reddit 评论者（86 赞）："the fact they retracted the initial HARD REQUIREMENT to use AI tells me they're not even confident in this whole thing themselves." —— 抓住规则从强制改成可选这个细节，认为官方自己对这条路线也没底。
  - Reddit 评论者（49 赞）："As a professional software engineer who uses AI daily at work, this game jam seems really out of touch." 并主张把 AI 用于"deriving mocap, static meshes, and textures from cell phone video" —— 不是反 AI，而是反对把 AI 当卖点，属于社区里最有建设性的一派。
- **参谋部短评**：值得继续盯的是 Epic 会不会在赛事规则上再退一步。真正的分歧不是用不用 AI，而是工具厂商该不该替创作者定义"正确的工作方式"；这条舆情会外溢到其他引擎和工具生态。
- **链接**：https://www.reddit.com/r/UnrealEngine/comments/1xdhtzz/

## 今日舆情温度

- **最热争议**：表面上吵的是"Codex 还行不行"，真正在吵的是账号安全。V2EX 那层楼里几乎没人替 Codex 辩护，却也几乎没人卸载，理由清一色是"Claude 会封号"；同一天 Reddit 上又出现多代理跑游戏文案被自动封禁的复现案例，还卡在"被封就登不上、登不上就申诉不了"的死循环里。两件事拼起来看，工具忠诚度已经让位给账号风险，能力差距反而被放到第二位。
- **最现实的吐槽**：额度。有人用四个账号的额度表对齐本地日志，算出 headless 模式比交互式多吃约五成额度，随即被做托管 agent 的开发者用"网关侧看不到差异"反驳，讨论最后落到"用脚本喂交互式会话"这种绕法上。另一头是省 token 插件的实测：四个插件里只有一个在大任务上真省三成，同一个小 bug 上反而贵两成，评论直接点出"你往 Claude Code 里加的东西越多，烧的 token 越多"。
- **最值得继续观察**：Claude Code 两名核心成员在同一天宣布离开，其中一位主导桌面版，另一位说很快公布下一步，产品线迭代节奏是否会放缓值得盯；同时有消息称部分 Claude 用户将受到影响，但目前只有转述、没有官方说明，先别当结论。另一条线是 GitHub 榜单前五里挤进四个"给 agent 用的技能包"，安全审计、前端设计、SEO 各占一格，竞争焦点正从模型强弱转向技能生态；但这类项目目前几乎只有 README 和 star 数，缺真实使用反馈，先观察不入选。

## 可以跳过

- 国内某 Agent 平台开放"技能付费"、某编程工具 1024 加场送额度：只有抽成比例和补贴数字，没有任何开发者真实评价，属于招商稿。
- GitHub 榜单上的多智能体炒股框架与紫微斗数排盘：前者 11 万星更像流量现象，回测好看不等于实盘可用；后者与 AI 无关，是领域数据的整理工作。
- 一位数学教授说"AI 让批改作业失去意义"：265 条评论里讨论质量不错，但落点在教学法与考核制度，离工具和产品决策较远，更适合当背景观点。
- 一篇 2015 年的旧文重提《我为什么是程序员》：情绪共鸣强，20 条评论大半在谈职业焦虑，事实信息量低。
