## PODCASTS

**Training Data —「Box's Aaron Levie: On Reinventing Yourself in the AI Age and Enterprise Diffusion」（2026-09-15）**

这期信息密度很高，核心论点整理如下：

1. **应用层 vs 模型层不是零和。** Levie 认为 2020 年代最大的误判是低估了「模型能力到企业实际工作流」之间那道桥的深度。现在「模型 wrapper」反而跑通了，因为企业真正需要的是理解它自身流程、能接进核心数据的那一层。他类比数据栈：十年前没人能预测在 AWS/GCP 之上会长出 Snowflake、Databricks 这样的数十亿美元生意，智能这一层会重演，「模型极其值钱，但把模型带进银行、生命科学、医疗、政府的实际工作流，那是很多软件」。

2. **token 补贴是一定会结束的现象。** 他的逻辑是纯毛利视角：模型公司一旦上市，就会被同样的资本主义法则约束，把训练成本算进去之后，长期补贴不可持续。而且 Meta、SpaceX、中国厂商、NVIDIA 这四类玩家不一定需要在推理上赚同样的毛利，所以「同规格 token 价格长期往下走」是基本确定的，价值会更多落到应用层。他也不认为会有一两家 lab 拿走 95% 的价值，理由是那样反而会招来反垄断甚至国有化，「两三家最大的 lab 自己也会更喜欢现在这种有健康竞争的局面」。

3. **开权重模型不会和闭源此消彼长，而是「剥洋葱」。** 他引用了 Decagon 的 Jesse 那个他曾公开认同的观点：闭源继续指数增长，但每个成熟下来的用例会被剥离到开权重上，条件是「确实更便宜」或者「做后训练能换来 x% 的性能」。结果是出现一种看着很矛盾的双重叙事：Anthropic、OpenAI 的营收一飞冲天，开权重也同时在指数增长。他举的两种编排形态也很具体：要么用最强模型做 orchestration，把长尾任务甩给便宜模型；要么默认用便宜模型，偶尔把太难的东西弹给重模型。混合下来可能是各占 50% 花费，但开权重那边吃掉 10 倍的 token 量。

4. **harness 和 eval 是他们真正的护城河。** Levie 说 Box 的 agentic harness 掌握了文件系统、权限结构、搜索行为、以及「人在十个文件里怎么挑出那一个」的启发式；对比直接把 Box API 交给外部模型，他们在准确率和延迟上都要明显更好。他们做两套 eval：一套是面向生命科学、金融、公共部门、科技等领域的文档中心化 complex work eval，另一套拿 Box 内部真实数据和员工使用方式做 holdback eval，靠它追踪每个模型「涨了半个点」的增量，再按成本/准确率阈值决定默认模型，客户也可以从 model garden 里自选。他也承认在部分用例上某些模型因为 tool use 生态更好而表现「不成比例地强」，不完全跟 coding 排名一致。

5. **持续学习 / 把上下文烘进权重，在企业里卡在权限墙。** 他非常认可这个方向（马上要和 Engram 的 Dan 通话），但指出研究者的心智模型常常是「我能访问一切」，而律师的世界是五个项目、门对门就不能有文档交叉，甚至不能被同一模型同时看到。每天还会有人被加进或移出项目，上下文随之变化。他的开放性判断是：这个问题会在持续学习上被突破，而且垂直场景差别极大，比如制药公司（Eli Lilly 那类）想要一个「我们怎么做药物发现」的模型，那几乎没有「教会与国家的界限问题」，而法律、金融就完全不同。

6. **系统记录（system of record）要做两件事，不是一件。** 一是做一个在你自家产品上「可证明比通用 agent 强 10 到 20 个点」的 agent；二是必须 headless，把 API 通过 MCP 之类的通路暴露给 Claude、ChatGPT 等平台。他举自己的例子：现在用 Salesforce 的频率比过去高一个数量级，因为是通过 Claude/ChatGPT 的 MCP 在问 CRM 数据；他半开玩笑说「如果能 MCP 进 LinkedIn，我愿意付 10 倍的钱」。他不太喜欢「收过路费」这个说法，因为「没人有过好的过路费体验」。

7. **chat UI 不会消失，但企业 90% 的 token 你不会主动发起。** 他预测五年后，企业里 90% 的 token 是用户从未启动过的：后台 agent 读每一份合同、盯每一条日志、分流每一个安全事件，人拿到的只是「这里有个任务，你来 review 一下」。真正被释放的是那些「应该做但一直雇不起人做、所以从来没发生」的流程。这也是他判断应用层空间巨大的核心理由，以及为什么纵向玩家（懂流程、知道该有哪些按钮和 tab）会比横向产品更有位置。

8. **为什么 coding 扩散最快，其他知识工作慢得多。** 他列了五六个 coding 的「天生好自动化」属性：代码的价值几乎 100% 由生成的文本承载；模型被超量训练过；所有 lab 都把 coding 当竞技基准、自己每天就在用；使用者是史上最技术的受众，撞到 bug 或 MCP 连接错误会自己修而不会叫 IT；且是超高薪行业，10% 生产力提升就已自动有价值。他建议按「与 coding 的相似度」画一个直方图，法律因为「价值大量来自一个人坐在电脑前读和写大量文本」而紧随其后，而销售代表就很远，因为他们的价值受外部客户是否回复、是否有预算限制。他还点出一个很少有人说的差异：coding 里「把 GitHub 接上就行」，而知识工作的世界里没有「give us your GitHub」，数据在老系统、遗留文件共享里，权限还得靠人去开。「硅谷得准备好，扩散会比大家想的慢很多」，而这恰恰是应用层的万亿机会。

9. **公司内部落地做法。** Box 的优势是二十年坚持所有信息都进 Box（会议纪要、路线图、演示、财务文档），数据架构天然对 agent 友好。他们有一个 AI 卓越中心、有内部 AI FTE，但明确说不搞 token 排行榜：看 token 消耗不是为了排名，而是发现「这个人这么用，值得开个内部培训」。他举的例子是一个团队被叫进会议室，让那位用得最好的同事做完整 demo，同时公开感谢 Mick。

10. **给创始人的话。** 他既羡慕又不太羡慕年轻创始人：看到两人团队做出五年前要 40 人的产品，但反过来，现在每个好点子都会瞬间冒出五个竞争对手。他认同 Scott/Matane 那一派的理解：既然 AI 让构建变快，胜负就转移到「谁真能把东西交到客户手上」，这是明确的企业扩散之战，搞错这个 mandate 的会直接出局。
