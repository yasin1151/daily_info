## 1. 一名漏洞研究员决定赶在 AI 替代他之前，先把自己替代掉
https://www.v2ex.com/t/1259624

**摘要**：作者是二进制漏洞研究员。今年五月，他用 agent 接上 Ghidra MCP 审计一台 IoT 设备，一个下午就挖到了漏洞并复现成功，于是对自己的岗位产生了很真实的危机感，决定先做工具替代自己。第一版把固件当作“一本书”：先用 Ghidra 反编译全部二进制，模型再给 8 万多个函数写摘要，标出 1017 个可疑函数。抽样复核后，几乎全是误报：有的输入早已被过滤，有的入口根本走不到，还有不少是模型自己编出来的。反思后的版本只做一件事：把固件里的事实整理清楚交给 agent，自己不跑模型、不判断哪里是漏洞。

**评论**：
- 2 楼 huruiqing001122：“底层技能被替代是必然的，越是底层的技能越机械，AI 越擅长；稍微高一点，架构啊、技术路线啊，AI 还凑合；再高一点产品设计，用户需求分析与提取，AI 就跟不上了”。这条把“AI 先吃掉哪一层”讲得最清楚。
- 5 楼 jackOff：“活下来的都是适应性强的人”。这是被替代焦虑下最标准的回答。
- 1 楼 lihijugtb：“思路的转变很好，值得借鉴”。这位读者是冲着方法论来的。

**为什么值得看**：这是一份少见的、肯把 AI 误报率摊开讲的一手工程记录。1017 个“漏洞”几乎全是假阳性，说明把模型放进逆向流程，难点不在推理，而在事实层——模型会替你下结论，但它不该下结论。

## 5. 在家里先搭一遍公司的整套 AI 架构当灰度环境，有人这么干吗
https://www.v2ex.com/t/1259799

**摘要**：楼主公司要建一套面向 AI 的完整架构，他的做法是先在家里复刻一遍：一台 NAS、一台显卡机、几台 Mac，分三层搭——基础设施（代码仓库、CI 调度、镜像仓库、容器部署、监控与链路追踪）、AI 中台（模型网关、Agent 编排、调用记录与评测、统一身份权限和 Key 管理）、业务交付（Agent 拆卡 → 开发、评审、测试 Agent 提 PR → 自动检查 → 合并队列 → 打版本 → 构建镜像 → 灰度 → 全量）。同事在公司报的问题（任务排队、长任务续聊失败、偶发 401、内存被打爆）先在家复现、做 A/B 对比，修好后再推回公司。他主动征求“这么做没意义”的反对意见。

**评论**：

- 6 楼 kloudmuka：“我试过，但实际效果有限，最多只能验证业务链路能不能跑通，很多关键的东西只能在生产环境中复现”。这是有实践经验的人给出的结论。

- 1 楼 moefishtang：“为什么要浪费家里的电费和算力资源给公司用，让公司开测试环境”。这是最直接的一句。

**为什么值得看**：技术人能验证链路，但验证不了规模和人性。这条最有价值的地方是 7 楼的那句提醒，而不是架构图：一旦你的业余算力被看见，它就会被算进工期。

## 6. 用本地 IM 替代硬编排：一个同时运行 10-20 个 Agent 的人怎么管理它们
https://www.v2ex.com/t/1259752

**摘要**：作者迭代了三个多月的 agent orchestrator，他的观点是：随着 harness 工具成熟和模型后训练增强，早期用工作流（coze、dify 那类）拆任务的编排，要解决的问题已经变了——不再是上下文长度和指令服从，而是让多个 agent 并行、发挥不同模型的特性、提高单位时间产出（他引用了海外正火的 software-factory 概念）。他主张用本地 IM 的聊天窗口替代可视化硬编排，让协作“自然涌现”，同时能操控多家厂商订阅的模型。

**评论**：
- 2 楼 fengshenx：“大项需求不建议走 Agent Team，应该在 PR 层拆掉。Side Project 图快可以走 Dynamic Workflow，比 Agent Team 快，没有 Agent 之间互相拉扯。现在最合适的标准开发是 1 个 Leader 带一群 Worker”。这条把编排问题还原成工程边界问题。
- 6 楼 fengshenx（❤1）：“我通常都是 10～20 Agent 干活儿，很多 Coding Plan 并发太低，所以我混着用”。规模是真的，限制也是真的。
- 4 楼 jacketma：“一般是将 States 状态统一保存在一个地方，一个 agent 完成了去通知另一个 agent 起床干活之前都去读 States 先”。这是最简单、也最能落地的协作协议。

**为什么值得看**：多 agent 编排最容易变成 PPT 概念，这条的可信度在于回复者是真在用 10-20 个 agent 干活，而且给出的结论很反直觉：不要在 Agent Team 层拆需求，回到 PR 层。
