## 1. 别说开发了，这把运维真给干没了把
`程序员节点 · 74 楼` · https://www.v2ex.com/t/1251410

楼主认为运维这个"必须养着的辛苦活"正在消失：以前凌晨 2、3 点上线要有人盯着，现在 AI 挂个定时任务，几分钟就忙完；AI 写脚本、写 SQL、干运维都比人强，还能 24 小时不休息。

评论区基本不争论"会不会取代"，而是直接争"权限给到哪一层"——三条回复给出了两套已经在生产跑的方案：

- **2楼 MisterQ ❤11（最高赞）**：「你公司胆这么大呢，运维的活都敢全交给 AI」
- **4楼 ronen ❤3**：「ai 运维发现磁盘报警 顺手把 data 目录删了怎么办。」
- **30楼 zengxs ❤2**（实战派）：「k8s 配合 rancher-ai-mcp + grafana-mcp + victoria metrics mcp 给 ai 接入线上只读权限，组件状态、线上日志、线上指标都打通了……让它给我 yaml 配置，我大致 review 一下没问题就可以更新。现在管理一个大约 300+ 核的生产集群，线上比较稳定还没出过事故。」
- **13楼 jheroy ❤1**：「固定流程化的工作直接让 AI 写程序，用程序来执行；非流程化的，让 AI 写一个 mcp 工具，把线上能让 AI 操作的事情全封装成 mcp 工具……剩下的 1% 的危险操作 AI 干不了，人看了没问题就执行脚本。」

**为什么值得看**：这场讨论的价值不在情绪，在于两个可抄的工程答案——「AI 只拿只读权限，写操作由人生成+review」和「把所有危险动作封装成 MCP 白名单」。顺带一个冷水：AI 删库的段子不是玩笑，是权限模型没设计好的必然结果。

- **3楼 106npo**：「问题是没人按 api 价格用啊，都是用套餐的。套餐可是不降反升的，单价涨 30%。」

回复里最有信息量的不是功能清单，而是对"为什么吃灰"的诊断：

- **6楼 v2gba**（活得最久的一类用法）：盯机票降价、按条件提醒、把 8 元保号号码交给 agent 代接电话并双向收发短信、带个人 context 的行程规划、长视频先让 AI 看一遍再决定要不要看。

## 5. Mac 本地跑大模型实测：54 tok/s，一年省下 API 费 ≈ 一台 Mac mini
`问与答节点 · 2 楼` · https://www.v2ex.com/t/1251179

楼主给公司做推理成本优化：团队每天 2000+ 次摘要/分类调用，走 API 一个月约 ¥2000，而工单分类、报表摘要、字段抽取这类任务 3B 模型就够。实测 M1 Pro 32GB + llama.cpp + Qwen2.5-3B Q4_K_M（2GB）：生成 54 tok/s、prompt 解析 551 t/s、内存 3.2GB 挂后台无感，部署就三步 brew + 下 gguf + llama-cli，团队用 llama-server 起 OpenAI 兼容接口，改个 base_url 即可。顺带判断：DeepInfer 要 Linux + NVIDIA SM100/昇腾 950 级别，"中小企业看看就好，现阶段 vLLM 是甜点位"。

- **1楼 spike0100**：「分类走本地部署的决策模型效率还能更高点。」
- **2楼 skallz**（反方，零赞）：「你这个需求，搞一下国内免费的模型多搞几个号，负载均衡不就免费搞定了吗，速度还更快。」

**为什么值得看**：这是"把 90% 的流水活从贵模型上摘下来"最具体的一版数据，含吞吐、内存、部署成本。反方提出的薅免费额度方案虽然免费，但在合规和稳定性上不可持续，正好构成一组对照——本地小模型的价值不只是省钱，而是任务不出内网。

## 7. 纯 Go 实现的生图应用，本地部署模型
`程序员节点 · 5 楼` · https://www.v2ex.com/t/1251491

楼主用 go + mygo + stable-diffusion.cpp 做了个本地生图桌面客户端：无 cgo、不是 WebView、不是 Electron，界面原生绘制；macOS 走 Apple 芯片，Windows x64 走 Vulkan（N/A/I 卡通吃）；支持 Z-Image Turbo、Qwen Image 2.1/Edit 2511、FLUX.2 klein 4B、ERNIE-Image Turbo 等，只要是 stable-diffusion.cpp 支持的都能跑。动机是 ComfyUI 的节点图对"只想写句话出张图"的人太重，且量化/目录/内存门槛全靠搜教程。功能上按本机内存标注「流畅运行/可能较慢/内存不足」，同模型可装多份配置、共用文件只下一次。

- **1楼 Atukey**：「界面很好看，没有接触过 mygo，刚看了下文档，你觉得 mygo 的 Native UI 相比较 wails 有什么提升？」
- **4楼 cdx**：「不需要 webview 来渲染 ui 界面，没有在一些机器的 webview 的兼容问题，启动速度很快，占用小，性能好，没有通信损耗。」
- **5楼 Atukey**（追问边界）：「Native UI 好像没法播放视频吧。」

**为什么值得看**：一个"去 Electron"的本地 AI 桌面客户端样本，同时把 mygo 这个原生 Go UI 框架的实际能力边界（性能好、多媒体弱）暴露出来。做本地 AI 工具选型时可以省一轮试错。
