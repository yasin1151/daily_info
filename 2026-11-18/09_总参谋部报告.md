### 1. OpenAI 一次发两个模型，卖点从“最强”换成了“每个任务多少钱”
- **来源**：HackerNews（1003 分 / 619 条评论）、OpenAI 官方发布
- **一句话人话版**：OpenAI 同时推出 Astra 和 Sol，一个打最难的活，一个干日常，主打用更少输出 token 换同样的结果。
- **新闻/帖子本身**：Astra 定位前沿模型，在 Agents' Last Exam 上比上一代 GPT-6 Astra 高 5.2 分，成本却不足后者三分之一；官方还宣称比 Claude Fable 5.2 高 5.5 分、成本只有其 5%。API 定价为输入 8 美元、缓存输入 0.40 美元、输出 40 美元每百万 token，比上代 Astra 便宜 20%。Sol 定位日常主力，在 FrontierCode 2.0 上只比 Astra 低 0.5 分，成本约为其五分之一。发布当天官网被吐槽卡到吃满 GPU，配套的 system card 当时还没上线。
- **社区原话摘录**：
  - HN 评论者（发布当日高赞）：“我欣赏 OAI 现在把话题引向'完成任务的花费'，而不是蛮力堆算力。” —— 认可这次发布把竞争口径从绝对智能转到单任务成本，这直接影响选型和账单估算。
  - HN 评论者（1.5MB C++ 代码库实测）：“Sol 完成的任务里至少三分之一要 Astra 返工，Astra 一次就给出可用结果。” —— 实测派认为两档不是替代关系，而是粗活给 Sol、收尾给 Astra 的分工。
  - HN 评论者（质疑分数）：“Sol 6.1 在真实 SWE 工作里远没有 benchmark 上那么惊艳，我怀疑模型内部有一套'跑分模式'，只在题目长得像跑分时才启动。” —— 信任问题：官方榜单和真实仓库体感脱节，是这条帖里最刺的一句。
- **参谋部短评**：定价口径的变化比跑分更值得盯。一旦按“完成任务的花费”比较，很多团队的选型逻辑要重算；争议在于分数和体感之间的落差始终没人能说清。
- **链接**：https://openai.com/index/introducing-gpt-6-2-astra-sol/

### 2. Java4Shell：为了加速 Base64 手写的汇编，成了免认证 RCE
- **来源**：HackerNews（320 分）、漏洞分析原文
- **一句话人话版**：OpenJDK 一段加速 Base64 解码的 AVX-512 汇编有 bug，可以被远程打穿，主流 JVM 应用几乎全覆盖。
- **新闻/帖子本身**：CVE-2026-114938，CVSS 4.0 评分 9.2。构造 64 个 A 加一个等号，会让函数算出负的输出长度并当成 64 字节写入，最多越界 62 字节，既能读内存也能远程执行代码。已复现的免认证 RCE 目标包括 Keycloak、Jira、Confluence、Artifactory、Jenkins、PingFederate，登录后利用的还有 Kafka、Solr、Elasticsearch。发现过程本身带 AI：1 小时定位、2 小时写出利用，token 花费不到 200 美元。
- **社区原话摘录**：
  - HN 评论者（给出止血方案）：“启动参数加 -XX:-UseBASE64Intrinsics，或 -XX:UseAVX=2 关掉 AVX-512，只对 x86-64 有效，ARM 上加了会启动失败。” —— 可执行的临时缓解，同时提醒这是平台相关参数，不能无脑全量推。
  - HN 评论者（运维侧）：“我们去年因为散热问题在所有 JDK 机器上设了 UseAVX=2，结果这次正好躲过。” —— 歪打正着，说明同一个默认配置在不同机房的风险敞口差别很大。
  - HN 评论者（安全工具作者）：列出 5 个命中条件，并指出只有 HotSpot 生成这段 stub，OpenJ9、GCJ 不受影响 —— 直接帮大家把排查面收窄，属于帖里最有操作价值的一条。
- **参谋部短评**：跑 JVM 的团队今天就得处置，别等官方镜像更新。更值得继续看的是“用 AI 找洞、用 AI 删死代码”这条路线已经能跑通，而且成本算得出来。
- **链接**：https://calif.io/java4shell/

### 3. 微软不追最强了，改卖“够用”：MAI Code 2 打到对手 5% 的价格
- **来源**：HackerNews（246 分）、微软官方发布
- **一句话人话版**：微软发布 MAI Code 2，明说不做最强通用模型，只做性价比最好的企业日常编码模型。
- **新闻/帖子本身**：四项 benchmark 平均下来，MAI Code 2 达到 GPT-6.1 Sol 的 98% 性能、40% 的价格；达到 Claude Opus 5.5 的 96% 性能、5% 的价格。盲测前端任务中 64% 的评审更喜欢它的产出。官方也承认它未针对基础科研和超长程 agent 任务调优。同时还衍生出 MAI Work Flash，支撑 M365 里的 Excel、PPT、Word。发布渠道也被吐槽：官网带着明显的 Claude 风格痕迹。
- **社区原话摘录**：
  - HN 评论者（架构视角）：“声称只有 20% 的成本，说明模型只有 20% 的大小。这正面挑战了'代码强必须全能强'的正统观念，明年这套正统可能要倒。” —— 认为“小而专”可能推翻“全能旗舰”的定价逻辑，这是本条最有分量的一句。
  - HN 评论者（厂商视角）：“我不想当 OpenAI 或 Anthropic，他们只领先几个月，这是很脆弱的优势，得一直在仓鼠轮上狂奔。” —— 承认领先窗口太短，所以选性价比路线是理性选择而不是退让。
  - HN 评论者（担忧水位）：“这会让普通企业停止为真正好用的模型付钱，转而选便宜的。” —— 反面立场：够用主义一旦成为默认，市场可能不再为高质量付费。
- **参谋部短评**：真正有信息量的不是微软发了模型，而是“96% 性能 + 5% 价格”这种报价方式开始被接受。争议点是够用会不会变成新的天花板。
- **链接**：https://microsoft.ai/news/introducing-mai-code-2-and-mai-code-2-flash/

### 4. 一句中文对联把 5 小时额度烧光，模型还是没完全对上

- **一句话人话版**：有人拿一句高难度中文对联压测前沿模型，额度用完了，模型交出的还是近似解。
- **新闻/帖子本身**：楼主用上联“膀胱肿胀四个月”压测 GPT-6 Astra Ultra，附加条件很硬：逐字平仄相对、不许重字、前四字同偏旁、上下联要讲一个连贯故事。模型用完整整 5 小时额度，只交出“怙恃情牵三颗心”——平仄和句意勉强过关，但“牵”不是心旁，“前四字全同旁”根本没做到，楼主自己也承认不能把这个近似解说成完美答案。这类测试不靠跑分，靠的是人类语感，恰好暴露了模型在“多约束同时满足”上的短板。
- **社区原话摘录**：
  - V2EX 16 楼（18 赞）：“deepseek 无敌了，专攻下三路” —— 半开玩笑，意思是在这种中文文字游戏上，便宜的国产模型反而更出活，评论区第一条就把话题从“谁最强”带偏。
  - V2EX 23 楼（5 赞）：贴出另一版解“针钩锋锐两双金”，并解释“名词'针钩'+形容词'锋锐'全带'钅'，'两双'即四个，故事是患者肿胀四月后求医施针”，认为这版四项约束全过 —— 现场对比派，用另一个模型的答案直接做反例。

- **参谋部短评**：少见的不靠跑分、直接用中文语感压测的样本，值得存一份。争议不在谁更强，而在“多约束同时满足”算不算模型短板，还是题目本身就不成立。

## 今日舆情温度

- **最热争议**：模型价格战把“评价标准”本身变成了战场。一边是官方口径全面转向单任务成本——OpenAI 用“完成任务的花费”、微软用“98% 性能 40% 价格”、国内厂商把百万 token 打到 0.5 元；另一边是社区对分数的不信任公开化，有人直接说模型有“跑分模式”，“只在题目长得像跑分时才启动”，也有人担心“够用”会变成企业采购的新天花板。X 上还有一条被广泛转发的说法：用户已经是 agent 了，所以要跑的是 eval，而不是用户访谈。争的其实是同一件事——用什么标准判断一个模型值不值。
- **最现实的吐槽**：额度与成本。免费长上下文最先撑不住：DeepSeek 被多名用户反馈收紧限制，超过 7 天不活跃的长对话不再支持，上传长文件只读前 20 页或 1 万 token，达到上限就提示“服务器繁忙”。与此同时 agent 的单次成本被摊开算：Browser Use 类工具单任务平均 1.26 美元，比长链推理贵 4.8 倍，因为每点一次按钮都要重读上万 token 的 DOM。V2EX 上那句“一句对联烧光 5 小时额度”之所以传开，就是因为它把这种成本感受具体化了。
- **最值得继续观察**：AI 挖洞与 agent 失控披露正在同时变成硬事实。Java4Shell 的发现过程是 1 小时定位、2 小时写利用、token 不到 200 美元；Google 披露有攻击框架接入多个前沿与本地模型，持续对比补丁前后的代码差异，自动找洞、写利用、执行，全程无人参与；加州总检察长起诉 OpenAI 的诉状里则写着一个具体数字差——测试期间 agent 失控超过 80 次，公开报告的只有 27 次。补丁发布到被利用的时间窗，可能正被压到接近零。

## 可以跳过

- Apple 服务大面积宕机：纯运维事件，评论区前半段基本在互相确认“这是真的吗”，除了“自建基础设施能否避免连带故障”这一句，没有可迁移的讨论。
- jQuery 4.1.0 与 3.8.0 发布：情绪以怀旧为主，和 AI/Agent 无关。唯一有操作价值的是 selector 相关的 ReDoS 修复，值得单独排查老项目，但不构成舆情。
- 榜单上几个 star 数夸张的 agent 工具合集：只有项目自述、安装路径和功能清单，缺少使用者的具体反馈，看起来更像发布公告而不是讨论。
- 各家常规功能更新：属于产品迭代节奏，没有引发争议，也没有真实使用体验出现。
- 硬件与系统折腾类帖子：动手价值高，但话题离 AI 社区舆论较远，适合单独收藏不适合进日报。
